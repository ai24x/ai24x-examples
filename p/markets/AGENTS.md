# p\markets · 产品迭代授权章程（2026-08-16 雷总定：默认执行，例外审批）

> 本文件对在 p\markets 工作的 Codex 会话（行情官国际版 / 司令）自动生效。
> 核心模式：**该做的直接做，遇到红线才申请审批**。不要问「要我开始吗」，按下面边界直接开工。

## 一、默认授权（直接开发，不需要再问）
- P0 纯前端/体验/文案/合规收紧（如：新用户引导、onboarding、Watchlist 界面化[后端 API 已就绪]、移除中文 UI、AI 点评入口前置）
- 低风险后端小改（默认参数调整、既有能力界面化）
- P1 中不涉及「例外审批清单」的体验增强（如登录回跳增强、支付成功引导）

## 二、完成动作（默认闭环）
1. 本地自测（浏览器/接口走查，手机视口过一遍）
2. commit，message 注明「周复盘自主迭代」
3. 回执给司令/主脑：改动清单 + 自测结果 + 部署建议
4. 部署由司令统一执行（04 生产 + nginx sites 目录同步 + 验收 + 群回执），行情官不直接部署公网

## 三、例外审批（必须先标【需审批】，等雷总一句话）
- 涉及付费/支付流程改动（PayPal/订阅/计费）
- 对外承诺类：ToS/Privacy/服务条款/宣传文案/价格
- 新功能对外上线（新增对外入口/发布公告）
- 架构调整、生产配置/数据库改动、花钱/账号操作
- 审批格式：`【需审批】<事项> | 建议：<默认方案> | 影响：<一句话>`，转雷总/司令，批准后继续

## 四、负分项（禁止，越权=事故）
- 不直接改生产配置/数据库
- 不越权部署公网/不绕过司令部署流程
- 不对外发布承诺/不擅自改价格与对外文案
- 不刷屏打扰（回执一句话结论）
- 不重复做已提交的工作（先查 git log / 状态）

## 五、节奏
- 每周日 20:00 产品周复盘（cron 驱动），产出提案并默认开工 P0/P1
- 每周小版本 ≤1 次自主上线（由司令部署），大版本/新功能提案等拍板

# 参考渔悦资产清单（p/game/fisher）

> 渔悦=矩阵的「工程骨架 + 合规口径 + 小程序样板」参考库，不占 P0 名额。
> 中台 core 与 P0-1 开发时优先复用以下资产，避免重复造轮子。

## 一、后端（api/server/，FastAPI + SQLAlchemy + PG）— 中台 core 的工程起点

| 文件 | 内容 | 复用方式 |
|---|---|---|
| app/auth_jwt.py | JWT 签发/校验（HS256）+ Bearer 依赖 | 直接复制改表名（Player→User） |
| app/config.py | pydantic-settings 环境配置 | 复制改字段（FISHER_DATABASE_URL→GAME_CORE_DATABASE_URL） |
| app/db.py | SQLAlchemy Session 依赖 | 直接复用 |
| app/models.py | 表模型（Player/Fish/...） | 作为中台表模型风格参考 |
| app/schemas.py | Pydantic 出入参 | 风格参考 |
| app/security.py | 密码哈希等安全工具 | 复用（虽然小游戏主要走微信 code2session） |
| app/content_safety.py | 文本内容安全 | 保留（预置文案场景） |
| app/main.py (20KB) | 路由/启动/中间件 | 结构参考；中台独立写 |
| app/seed_data.py | 种子数据 | 中台配置种子参考 |
| requirements.txt | 依赖清单 | 直接参考 |

## 二、微信小程序（miniprogram/，原生）— 工具类小程序模板

- app.js/app.json/app.wxss + project.config.json + sitemap.json：最小可用骨架，直接复制改名。
- pages/index/：单页玩法页结构参考。
- 注意：P0-1 游戏走 Cocos 构建产物进小游戏类目，原生骨架主要用于「轨道 B 工具类小程序」。

## 四、数据库（db/）

- fisher_dump_20260812.sql / .dump：PG 快照（8 钓场/50 鱼种/36 玩家样本）。
- 拆分独立库脚本：scripts/init_fisher_db.ps1 + bootstrap_fisher_pg.sql。
- 中台 game_core 库可仿此模式建库（本机 PG15，bin: C:\Program Files\PostgreSQL\15\bin）。

## 五、Web/H5（web/）

- index.html + bag.html：H5 前端参考（P0-1 原型可先做 H5 验证玩法，再构建微信）。
- agreement.html：用户协议页现成模板，可改产品名复用。
- 9am-checklist.md：每日运营检查清单参考。

## 六、运行方式（scripts/）

- start_api.cmd：FastAPI 启动（PM2: fisher-api-18041）。
- serve_web.cmd：H5 静态服务（PM2: fisher-web-18002）。
- 中台 core 沿用同一套 PM2 模式（core-api-18xxx）。

## 结论

中台 core 第一版代码 = 渔悦 api/server 的「结构 + 鉴权 + 配置 + db」直接迁移改造，替换业务模型为 用户/星币/榜单/挑战/事件/广告台账，一周内可出可运行骨架。

# 开发会话协作 SOP（游戏官 定稿 2026-08-13）

## 一、为什么分
本会话（游戏官）= 项目总负责：规划/PRD 定稿、验收、派发、对外通信（收发×2）。
开发按「任务制」开独立会话：一个任务一个会话，任务书进、回执出，做完即归档、不保留长期记忆。
目的：避免决策上下文被长开发稀释、开发上下文无限膨胀，两者互相污染。

## 二、分工边界
| 场景 | 由谁做 |
|---|---|
| 规划/PRD/验收/拍板/回复司令来信/对外派发 | 游戏官（本会话） |
| 短任务（2小时内，单文件/小模块） | 游戏官直接干，或 spawn_agent 内嵌开发 |
| 本机长开发（半天以上，Cocos 工程/中台完整模块） | 独立开发会话（任务制，做完即归档） |
| 远程构建/冒烟/微信构建流水线 | 副脑01（42.192.1.93） |
| 竞品监控/运营统计/矩阵管理自动化 | 副脑02（118.89.111.23） |
| 生产部署 | 副脑03/04（走 deploy 脚本） |

铁律：开发会话不决策、不对外通信（不发主脑/司令/副脑），只产出代码 + 回执。

## 三、目录协议
- 任务书池：p\game\开发任务\inbox\DEV-YYYYMMDD-NN-任务名.md
- 回执落点：p\game\开发任务\done\DEV-YYYYMMDD-NN-回执.md
- 模板：p\game\开发任务\TEMPLATE-开发任务书.md

## 四、任务书必填字段
任务编号 / 优先级(P0/P1/P2) / 目标产出 / 背景与约束(含写范围、禁改文件) / 验收标准 / 预计工时 / 派发人 / 派发时间。

## 五、回执格式（统一）
✅ 已完成项：…
⚠️ 问题项：…（无则写「无」）
产出清单：<文件路径列表>
未决事项：…

## 八、并行与纪律
- 写同一目录树的任务不得并行（防冲突）；写范围不重叠可并行
- 产出先经游戏官验收；验收不过打回迭代（2轮内），仍不过拆小重派
- 涉及数据库变更/微信平台/广告后台操作：只出「变更说明」，操作交给游戏官/副脑

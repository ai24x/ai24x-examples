# 渔悦 · 安全架构与防拷贝体系

> 更新于 2026-05-11

## 五层防护架构

```
┌────────────────────────────────────────┐
│  层1: API域名白名单 + Referer校验       │
│  层2: 全局限流 (60s/120次)             │
│  层3: JS代码混淆 (terser压缩+mangle)    │
│  层4: 核心逻辑服务端闭环                │
│  层5: 环境指纹 + 完整性校验             │
└────────────────────────────────────────┘
```

### 层1：域名白名单

`app/security.py` → `ALLOWED_ORIGINS`

- 开发期: `localhost`, `127.0.0.1`
- 上线前添加正式域名

### 层2：速率限制

`app/security.py` → `SecurityMiddleware`

- 通用接口: 60秒120次
- 游戏操作: 60秒30次
- 超限自动返回 429

### 层3：前端混淆

生产部署时构建混淆版:

```bash
cd p/game/fisher/web/js
bash build.sh
# 产物: js/min/*.js (变量名混淆+压缩)
```

部署到服务器后，修改 `index.html` 加载路径:

```html
<script src="js/min/sfx.js"></script>
<script src="js/min/fisher-api.js"></script>
<script src="js/min/demo2.js"></script>
```

### 层4：服务端闭环

所有关键逻辑在服务端执行:

- 鱼获随机 → 服务端 `roll_fish()`
- 金币增减 → 服务端 `db.commit()`
- 装备购买 → 服务端 `do_buy_equipment()`
- 交易成交 → 服务端转账

**前端可被拷贝，但只是空壳——没有API无法钓鱼。**

### 层5：环境绑定

数据库不随代码分发:
- PostgreSQL 数据库在服务器
- 种子数据自动填充
- 用户数据无法导出

## 生产部署 Checklist

- [ ] 修改 `config.py` 或 `.env`:
  ```
  FISHER_ENV=production
  FISHER_JWT_SECRET=<随机64位密钥>
  FISHER_CORS_ORIGINS=https://your-domain.com
  ```
- [ ] 在 `security.py` 的 `ALLOWED_ORIGINS` 添加正式域名
- [ ] 执行 `bash js/build.sh` 构建混淆前端
- [ ] 修改 Nginx/Apache 配置:
  ```nginx
  # 禁止访问源码目录
  location ~ /(\.git|backup_|archive/|docs/) { deny all; }
  ```
- [ ] 开启 HTTPS
- [ ] 数据库定期备份

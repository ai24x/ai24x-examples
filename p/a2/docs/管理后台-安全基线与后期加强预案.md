# 管理后台 · 安全基线（首推）与后期加强预案

面向 **小项目 / MVP / 个人或小团队**：先做到「省事 + 够用」，再按需启用下文「后期预案」。

---

## 一、现阶段首推基线（已实现或靠配置即可完成）

| 项 | 说明 |
|----|------|
| **强管理密钥** | `AI24X_ADMIN_KEY`：用密码管理器生成 **≥24 位随机串**（建议 32+），勿用 `change-me-admin` 等示例值。 |
| **浏览器入口弱隐蔽** | 默认挂载 `AI24X_ADMIN_MOUNT_PATH`（如 `/admin20260501`），**勿在对外宣发、截图、录屏中暴露**；轮换时改 env + Nginx。 |
| **登录限流** | `POST /api/admin/login` 按 IP 限次（默认每 15 分钟 `AI24X_ADMIN_LOGIN_MAX_PER_15M` 次，可调）。 |
| **会话 Cookie** | 登录成功后 **HttpOnly** 会话；生产 `AI24X_ENV=prod` 时 Cookie **Secure**（须 **HTTPS**）。 |
| **常量时间比密钥** | 校验管理密钥使用 `hmac.compare_digest`，降低简单时序侧信道风险。 |
| **HTTPS（有域名即上）** | 公网访问域名时务必 TLS（如 Let’s Encrypt），避免明文传输密钥与 Cookie。 |
| **启动自检日志** | 进程启动时若密钥过短/疑似示例值，会打 `[admin-security]` **告警日志**（不阻断，便于本地开发）。 |
| **总管手机 OTP（可选）** | `AI24X_ADMIN_OTP_PHONES`（逗号分隔）与表 **`admin_operators`** 中 `enabled=1` 的手机号**并集**非空时：浏览器登录须 **短信 OTP + 管理密钥**；接口 `POST /api/admin/otp/send` → `POST /api/admin/login`（body 含 `key, phone, otp`）。**`X-Admin-Key` 调用 API 不受 OTP 影响**。库表字段含 `role` / `perm_flags` / `perm_json`，供以后分管与细粒度权限。 |

**本地开发**：`uvicorn` 绑定 `127.0.0.1` 时，公网本就无法直连，天然多一层保护。未配主站短信时，非 prod 下发码接口会在 JSON 中带 **`dev_code`**（可另设 `AI24X_ADMIN_OTP_DEV_CODE` 固定联调码）。

## 二、上线前简检查清单（可复制自用）

- [ ] `AI24X_ADMIN_KEY` 已换成长随机串（≥24 字符）。
- [ ] `AI24X_JWT_SECRET` 在生产已换成长随机串。
- [ ] 公网域名已 **HTTPS**；`AI24X_ENV=prod`（或你们约定的生产值）。
- [ ] Nginx（若有）已反代 **`{ADMIN_MOUNT}/login`** 与 **`{ADMIN_MOUNT}`**，与 `.env` 中 `AI24X_ADMIN_MOUNT_PATH` 一致。
- [ ] `.env` 未提交进 Git；服务器权限仅本人/运维可读。
- [ ] （建议生产）已配置 `AI24X_ADMIN_OTP_PHONES` 与主站短信转发，浏览器管理登录走 OTP。

## 三、后期加强预案（按需启用，由易到难）

### 1. Nginx 按 IP 放行管理路径（适合固定出口 IP）

- 对 `location` 匹配管理前缀使用 `allow 你的公网IP; deny all;`。
- **注意**：家庭宽带 IP 常变，变更后需同步改配置，否则易把自己锁在外面。

### 2. SSH 本地端口转发（适合「管理口不对公网开放」）

- 服务器上 API 仅监听 `127.0.0.1`；笔记本执行：  
  `ssh -L 18031:127.0.0.1:18031 user@server`  
- 浏览器访问 `http://127.0.0.1:18031/...`，管理流量走 SSH，**公网扫不到管理页**。

### 3. 内网 / 云厂商 VPN / 专线

- 仅内网 IP 或 VPN 网段可访问管理或整站 API；适合团队与合规要求升高阶段。

### 4. 管理操作审计外置

- 将 `[admin-security]` 与业务日志接入集中日志或告警（异常时段大量 401/429）。

### 5. 二次验证（2FA）与独立管理员账号体系

- 当前 MVP 为「单密钥 + Cookie」；若金额与权限复杂度上升，可规划：独立管理员用户、TOTP/WebAuthn、分角色 RBAC（属产品级改造）。

### 6. WAF / 风控 / 地域限制

- 云 WAF、速率限制、Bot 管理；按预算与攻击面逐步加。

## 四、相关环境变量（行情官 `p/a/api/server`）

| 变量 | 作用 |
|------|------|
| `AI24X_ADMIN_KEY` | 管理密钥；请求头 `X-Admin-Key` 或登录页提交。 |
| `AI24X_ADMIN_MOUNT_PATH` | 浏览器工作台路径前缀；登录为 `{路径}/login`。 |
| `AI24X_ADMIN_LOGIN_MAX_PER_15M` | 每 IP 每 15 分钟登录 POST 次数上限。 |
| `AI24X_ADMIN_OTP_PHONES` | 总管手机 CSV；与 `admin_operators` 启用行并集控制 OTP 白名单。 |
| `AI24X_ADMIN_OTP_TTL_S` / `AI24X_ADMIN_OTP_SEND_PER_15M` / `AI24X_ADMIN_OTP_DEV_CODE` | 验证码有效期、发码限流、非 prod 可选固定联调码。 |
| `AI24X_ENV` | `prod` 时 Cookie `Secure`、部分支付调试开关关闭等。 |
| `AI24X_JWT_SECRET` | 用户 JWT 签名密钥；生产须足够强。 |

---

## 五、说明

- **路径保密不是加密**：降低被自动化扫到的概率；**真正防爆破**仍靠 **长随机密钥 + 限流 + HTTPS + 网络策略**。
- 文档随项目迭代可继续增补「你们实际用的 Nginx 片段、PM2 进程名」等，与 `docs/PORTS.md`、部署卡片交叉引用即可。

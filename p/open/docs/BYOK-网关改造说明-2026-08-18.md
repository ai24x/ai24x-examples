# open.ai24x.com BYOK 智能网关改造说明（Phase 1）

> 日期：2026-08-18 ｜ 范围：`p/open` ｜ 状态：Phase 1 已完成本地验证

## 一、改造目标

把 open.ai24x.com 从「Token 聚合转售平台」升级为「BYOK（Bring Your Own Key）
多模型智能网关」：开发者自带上游 API Key，平台提供**智能路由 + 故障转移 +
请求缓存 + 用量统计/成本看板**，收取**平台服务费**，不再囤 token、不再转售，
上游 TOS 封号风险归零。

定位（改造后不做前台主打）：
1. 内部支撑（首要）：AI24X 各智能体自己的 key 统一走网关，吃路由 + 容灾 + 成本看板。
2. 特殊合作伙伴：少量信任伙伴。
3. 开发者利基：海外开发者自备 key，收服务费，社群冷启动。

## 四、数据模型（新表）

- `byok_keys`：用户自有 key（`key_cipher` 存 AES-256-GCM 密文，`key_prefix`
  只存明文前 8 位；`provider / name / models / base_url / status / priority /
  last_latency_ms / success_count / fail_count` 供选路与展示）。
- `byok_usage`：每请求一行（`prompt_tokens / completion_tokens / total_tokens /
  cost_usd_micro / latency_ms / success / error_code / cached / project`），
  `byok_key_id` 无外键：删 key 保留历史看板数据。

建表：服务启动 `init_db()` 自动 `create_all`（已在本机 `ai24x_open_pre` 验证）。

## 五、加密与合规红线

1. **AES-256-GCM**：`encrypt_key()` 随机 12 字节 nonce，密钥由
   `SHA256("byok:" + SECRET_KEY)` 派生；密文格式 `aesgcm:v1:<nonce_b64>:<ct_b64>`。
2. **明文不落盘**：日志 / 响应 / 前端只暴露 `key_prefix`；`decrypt_key()` 仅在
   请求生命周期内内存解密用于调用上游。
3. **不转售**：BYOK 请求路由目标 = 用户自有 key，任何路径都不发平台聚合 key。
4. **缓存隔离**：缓存键含 `auth_user_id`，跨用户隔离，不落 prompt 原文。
5. **服务费口径透明**：`/v1/byok/status` 与响应 attribution 明示
   「平台只收网关服务费，不赚 token 差价」。
6. **保留既有风控**：`captcha_guard / email_abuse_guard / referral_abuse` 未动，
   BYOK 路由仍走 `get_current_user` 鉴权 + `UserService.check_rate_limit`。

## 六、路由与故障转移

- 非流式：`route_byok_chat()` 按评分（成功率 > 最近延迟 > priority）排序候选 key，
  逐个尝试；`401/403/429/5xx/超时` 自动切下一把；`400`（载荷格式）停止本链。
- 流式：`stream_byok_chat()` 首包前失败切下一把 key；已输出部分内容时按既有
  语义以 `degraded_error` 收尾，客户端不悬空。
- 全部失败：`BYOK_FALLBACK_TO_PLATFORM=1`（默认）回退平台路由；`=0` 返回
  `502 byok_all_failed`，提示用户检查 Key。
- Anthropic：原生 Messages API 适配器（非流式 + 流式），OpenAI SDK 载荷自动转换。
- 请求缓存：仅非流式、无 tools、同用户同载荷；默认 TTL 300s（`BYOK_CACHE_TTL_S`）。

## 七、控制台 API（`/v1/byok/*`，需登录）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/byok/status` | 网关状态 + 服务费口径 + 免费档 |
| GET/POST | `/v1/byok/keys` | 列表（只含前缀）/ 新增（AES 加密） |
| PATCH/DELETE | `/v1/byok/keys/{id}` | 改名 / 启停 / 模型 / 优先级 / 换 key；删除 |
| POST | `/v1/byok/keys/test` | 校验 key（不落库，最小请求） |
| GET | `/v1/byok/models` | Provider 清单 + 平台目录推荐模型 |
| GET | `/v1/byok/usage?days=&group_by=key\|model\|project\|provider` | 用量/成本看板 |
| GET | `/v1/byok/cache/stats` | 缓存条目 / TTL |

请求归因：请求头 `x-byok-project: <project>` 会记入 `byok_usage.project`，
看板可「按项目」聚合。

## 九C、套餐页「--」状态条修复（2026-08-18）

老板反馈：console.html#billing 套餐区顶部状态条显示「--」，像没介绍。

### 根因

`.byok-sub-banner { display:flex }` 覆盖了 HTML 原生 `hidden` 属性；未订阅用户的
占位条（`<div hidden>` 内 `--`）被强行显示出来，而 JS 尚未把订阅状态写进去，
于是出现裸「--」。

### 修复

- `web/console.html`：CSS 补 `.byok-sub-banner[hidden] { display:none !important; }`，
  保证隐藏态不被 flex 覆盖。
- `web/js/console.js` `renderByokSubBanner` 未订阅分支：改为显式渲染引导条——
  「未订阅 · 免费档」+ 描述（含基础路由；升级 BYOK Pro $9.9/月 解锁智能路由 /
  故障转移 / 请求缓存 / 成本看板）+「选购 BYOK Pro」按钮（点击滚动到套餐卡区）。
- 已订阅分支不变：当前订阅 + 到期时间 + ✓ Pro 已开通。
- 版本号：console.html / console.js / locales.js / api.js → 全站 `v=20260818d`。

## 〇、MVP 最终决定（不可再摇摆）

### 一期先上（3 条）

| 顺序 | 垂直 | 角色 | 清算数据 |
|------|------|------|----------|
| 1 | **宏观经济指标**（CPI / PMI / 社零等） | 清算样板 | 国家统计局公开口径 |
| 2 | **70 城二手房**（房价指数 / 成交套数） | 话题流量 | 统计局、住建公开口径；**不做个案小区、不写该不该买** |
| 3 | **院线票房** | 传播与结算故事 | 猫眼 / 灯塔等公开口径（手录或授权） |

### 后期再上（商业价值更高，但不阻塞开站）

| 顺序 | 垂直 | 准备动作（一期并行，不上线命题） |
|------|------|----------------------------------|
| 4 | **A 股财报硬指标**（优先于大宗） | 核查 AI 行情官已有 **TuShare** 套餐是否含 `income` / `fina_indicator`；草拟「只做营收/净利等硬指标、严禁股价」命题模板；结算以交易所公告为准 |
| 5 | **大宗商品现货月均价** | 商务询价钢联 / 卓创等**商用授权 API**；禁止用行情官 K 线公共源或期货行情冒充现货清算 |

**一句话：** 先上 **宏观 + 二手房 + 票房**；后上 **财报 → 大宗**。

---

## 一、与 AI 行情官（p/a1）数据关系（给研发）

| a1 已有 | 用途 | 能否做人机清算主源 |
|---------|------|-------------------|
| 腾讯 / 东财 / 新浪 K 线（公共） | A 股行情展示 | **否**（非契约 API，且不是月度指标/财报硬指标） |
| TuShare Pro（付费） | 日 K、指数、部分板块 | **行情复用有限**；**财报接口未在 a1 接线**，后期可同 token 扩接口，须核权限与商用条款 |
| 钢联 / 卓创 / 统计局 / 票房 | — | **a1 未接入**；研判站独立建设 |

MVP 三垂直：**手录 + 官方公开页低频核对** 即可上线，不依赖 a1 行情栈。

## 二、用户端文案硬约束（v2.2 新增，验收必查）

> 面向 `web/**`、演示页、Alert、API 返回给浏览器的 `message`。  
> **禁止把架构 briefing 写进用户第一屏。**

### 用户页禁止出现（示例）

- 前台 / 后台 / 两套隔离 / 物理隔离 / B 端 API / 商用概率  
- 盘口 / 赔率 / 下注 / 猜涨跌 / 兑付（免责区可写「无博彩兑付」，hero 不要）  
- MVP / 联调 / 非生产 / 需求 v2.x / 副脑 / env（页脚 demo 元信息可极简保留「演示」）  
- 「中国版 Kalshi」  

### 推荐用户腔

| 场景 | 写法 |
|------|------|
| Hero | 同一道公开数据题，人和 AI 各自作答。写清依据，结算后看谁更准。 |
| 冷启动 | 参与的人还不多，先看看各家 AI 怎么判断。 |
| 会员 | 解锁更完整解读与工具，不改变任何人的票权。 |
| 页脚免责 | 调研与知识互动参考；不构成投资/购房/采购建议；无金融交易与博彩兑付。 |

架构说明、隔离、熔断、KYC：**只写文档与代码注释。**

## 四、开发阶段（相对 v2.1 的修正）

### 一期（约 8～12 周）：三垂直 + C 端 + 熔断

1. 账号风控分层 + 双账本  
2. **宏观 + 二手房 + 票房** 框架 + 手录/核对入口  
3. 3 家备案 AI + 日批调度 + **算力熔断**  
4. 自动清算 + 延期 + 争议工单最小集  
5. 会员四档；日票免费额度  
6. 冷启动（人票 &lt; N 先亮 AI）  
7. 结算分享卡  
8. **用户文案过「去开发腔 / 去赌感」清单**  

### 二期：商业垂直切入 + B 端

1. **财报硬指标**上线（TuShare 辅助拉取 + 公告清算）  
2. B 端 API + KYC / 禁售 + 方法论  
3. Brier / 校准；扩模型按收入  
4. 大宗：**仅当授权 API 就绪** 再开命题  

### 三期

虚拟权益商城（无现金补差实物）；运营看板；可选数据交易所。

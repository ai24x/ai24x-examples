## 固定规则（远端/分支/发布铁律 · 贴给新会话用）

### 远端与分支铁律

- **唯一发布分支**：只允许推送到 `master`
- **唯一拉取口径（副脑03）**：只允许 `git pull origin master`（避免拉到 `gitee`/别的分支）
- **推送前必须确认**：

```bash
git status
git branch --show-current
git log -1 --oneline --decorate
git remote -v
```

- **通过标准**：
  - branch 必须是 `master`
  - status 必须干净或改动明确
  - `git log -1` 必须是你期望的那条提交
  - `git remote -v` 必须同时存在：
    - `origin = https://gitee.com/ai24x/ai24x-website.git`
    - `gitee = https://gitee.com/ai24x/ai24x01.git`

### 本机推送到 Gitee（标准流程）

```bash
cd E:\AI24X\ai24x-website\ai24x01

git checkout master
git pull origin master

git status
git diff --stat

git add -A
git commit -m "fix: xxx" -m "why: xxx"

git push gitee master
git push origin master

git log -1 --oneline --decorate
```

- **禁止**：在 PowerShell 用 `&&` 串命令；一行一个命令或用 `;`

### 给副脑03的更新指令（极简、稳定、不出错）

```bash
cd C:\ai24x01

git status
git checkout master
git pull origin master
git log -1 --oneline

pm2 restart a-api-8001
pm2 restart core-api-8002
pm2 save
```

**验收口径**：
- `git log -1` 必须出现本次发布的 commit id
- 页面仍旧不对时：访问一次 `/index.html?x=1` 触发拉新静态资源（避免缓存/旧 SW）

### 常见错误兜底

- **fatal: not a git repository**：说明没进目录，先 `cd C:\ai24x01`
- **detached HEAD**：执行 `git checkout master` 再 `git pull origin master`
- **更新无效**：先看副脑03 `git remote -v`，必须存在 `origin` 且指向 `ai24x-website.git`

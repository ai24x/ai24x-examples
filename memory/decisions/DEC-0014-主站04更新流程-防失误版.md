# DEC-0014 · AI24X 主站更新流程（防失误版 · 给 Cursor）

> 背景：2026-08-28 教训——token-admin.html 更新后用户看不到新功能，根因是 EdgeOne CDN 缓存旧版（8/26）+ 04 上直接改文件未入库。以下流程照做可完全避免。

## 〇、更新铁律（顺序不可乱）

1. **本地改代码 → 本地起服务验证**（8000/18012/18080）
2. **跑对应 QA**（`p/markets/scripts/_qa_*.js`、`_qa_*.py`，本地全绿才算过）
3. **提交 → 双推两个远端**：`git push gitee master` + `git push origin master`（**只显式 add 本次文件，严禁 `git add -A`**）
4. **写部署脚本**（.ps1，UTF-8 带 BOM）放 `docs\营销\收发\指令\`
5. **派发**：`powershell -File scripts\deploy04.ps1 <脚本>`
6. 04 跑完自动发指挥部群回执 → `scp` 拉回执 → 更新 `memory/daily/` → 提交双推
7. **涉及 HTML 管理页/用户中心 → 处理 CDN 缓存**（见第四节）

## 一、红线（禁止）

- ❌ **禁止直接在 04 生产仓库改文件不提交**（ops_alert.py 教训：改完未入库差点丢失；competitor-ranking.html 曾只在 04 存在）
- ❌ **禁止只推一个远端**（必须 gitee + origin 都推，缺一不可）
- ❌ **禁止 `git add -A` / `git add .`**（工作树常年有无关改动，会误提交）
- ❌ **禁止改共享资源不升版本号**（`locales.js / api.js / console.js / shell.js` 必须全站统一升 `?v=`，禁止各页各版本）
- ❌ **禁止重大项（价格/支付/首页/导航/登录/账户/视觉/多页批量）不经老板确认直接上线**

## 二、04 环境事实

- 主机：`Administrator@43.160.246.30`（新加坡），生产仓库 `C:\ai24x01`（**只有 origin remote，无 gitee**）
- 服务（nssm）：

## 三、部署脚本要点

1. **必须 UTF-8 带 BOM**（脚本含中文时 04 PS5.1 按 GBK 误读）→ node 写 `'\uFEFF'+src` 或 `UTF8Encoding($true)`
2. **HEAD 校验用 `git merge-base --is-ancestor $EXP HEAD`**（health 返回完整 hash，前缀匹配必误报）
3. 结构：pull → marker 检查 → 备份改配置 → `Restart-Service AI24X-*` → 业务同步（Dodo sync 用 `python -c "asyncio.run(sync_dodo_products())"`，HTTP 触发 403）→ 公网验证 → 输出 `DONE EXP=... HEAD=...`
4. override JSON（`token_plans_override.json` 等）是 **utf-8 无 BOM**，写回用 `UTF8Encoding($false)`

## 四、CDN 缓存处理（重点 ⚠️）

- EdgeOne 加速区域**不含中国大陆**，国内用户命中的边缘节点可能缓存旧版 HTML（本次就是：`EO-Cache-Status: HIT` + Last-Modified 8/26）
- **HTML 页面默认会被 EdgeOne 缓存**。凡是更新管理页/用户中心（`token-admin.html`、`console.html` 等）：
  1. 确保 nginx 已加 `Cache-Control: no-cache, no-store`（04 已配置好，勿删）
  2. **更新后刷新 EdgeOne 缓存**：腾讯云控制台 → EdgeOne → 缓存配置 → 刷新缓存 → URL 刷新，粘贴对应 URL，等 1-5 分钟
  3. 验证：请求带 `?v=时间戳` 参数看新内容；响应头 `EO-Cache-Status` 应为 `MISS` 而非旧 `HIT`
- 纯静态资源（css/js）带版本号 + `immutable` 不受影响

## 待排查问题（按严重度排序）

### P1 · codex CLI 模型名不被自家网关接受
- 现象：`codex exec -c model="flash"` 报错
  `The supported API model names are deepseek-v4-pro or deepseek-v4-flash, but you passed flash`
- 影响：Codex 配置里默认 model 名是 `flash`，但 AI24X 网关（api.ai24x.com）只认 `deepseek-v4-flash` / `deepseek-v4-pro`
- 临时绕过：手动改传 `-c model="deepseek-v4-flash"` 才能跑通
- 待排查：Codex 侧 config.toml 的模型映射 / 网关别名（flash→deepseek-v4-flash）哪个环节丢了映射

### P2 · Codex exec 沙箱只读，无法写收发目录回复文件
- 现象：Codex 收到「写入回复文件」指令时报
  `PermissionDenied / UnauthorizedAccessException（沙箱限制，非目标目录权限问题）`
- 影响：收发目录 `E:\AI24X\ai24x-website\ai24x01\docs\营销\收发\回复\` 的落盘环节走不通，Codex 只能靠直连通道文字回执，文件交换链路不完整
- 待排查：Codex 默认 sandbox 模式（read-only?）是否应放开对收发目录的写权限，或是否应加白名单

### P3 · codex exec 偶发 SIGKILL（无输出被杀）
- 现象：多次 `codex exec` 运行中进程被 SIGKILL（signal），部分无输出
- 影响：长任务/等待回执时不可靠，驱动链路不稳定
- 待排查：超时配置 / 资源限制 / 与 OpenClaw gateway 的进程管理冲突

### P4 · 04 副脑 plugins.allow 未显式信任（非阻塞提示）
- 现象：04 回执附带提示
  `plugins.allow is empty; discovered non-bundled plugins may auto-load: deepseek, feishu`
- 影响：无功能影响，仅提示可在 openclaw.json 配 `plugins.allow: ["deepseek","feishu"]` 显式信任
- 建议：顺手配置，消除提示

# AI 行情官｜灯塔版（1.01）方案卡片：最精简、最快、且“不出错”的发布总流程

目的：把发布收敛成“**固定顺序 + 固定动作 + 固定验收 + 固定回滚**”，避免小白手滑。

---

## 0) 铁律（必须遵守）

- **单一真相：Git**（服务器只 `git pull`，不在服务器改代码）
- **先预演再生产**（副脑01通过才进副脑03/04）
- **生产先备份再发布**（副脑03/04 强制 `pg_dump`）
- **数据库变更先兼容后启用**（避免瞬断）

---

## 1) 发布顺序（固定）

本地（主脑）→ 副脑01（预演）→ 副脑03（国内生产）→ 副脑04（国际生产）

---

## 2) 每次发布动作（无 DB 变更）

### 副脑01（预演）

- `git fetch --tags`
- `git checkout <rc tag 或指定 commit>`
-（如依赖变更）`pip install -r p/a/api/server/requirements.txt`
- PM2：重启/热更新 AI 行情官 API
- 验收（见第 4 节）

### 副脑03 / 副脑04（生产）

- **先 `pg_dump` 备份**
- `git fetch --tags`
- `git checkout <prod tag>`
-（如依赖变更）安装依赖
- PM2：重启/热更新
- 验收（见第 4 节）

---

## 3) 有 DB 变更时（字段/表）

最稳 4 步：

1) 先发布“兼容新旧结构”的代码  
2) 副脑01 执行迁移并验收  
3) 副脑03/04（生产先备份）执行迁移并验收  
4) 需要时再发布“启用新字段”的代码

> 强烈建议迁移脚本化（`migrations/*.sql` + `schema_migrations`），禁止手工改库。

---

## 4) 最小验收清单（5 分钟内）

- `/health` 200
- `/docs` 200
- 登录成功（拿 token）
- `/api/me` quota 正常
- `/api/kline` 查询一个常用标的成功
- 扣次抽测：成功扣、失败不扣、去重不重复扣

---

## 5) 回滚卡片（优先级固定）

1) **先回滚代码**：切回上一个稳定 tag/commit → PM2 reload/restart  
2) 若迁移不可兼容（不推荐发生）：用发布前 `pg_dump` 恢复  
3) PG 连接异常可止血：切回 SQLite（`AI24X_DB_KIND=sqlite`）→ 重启

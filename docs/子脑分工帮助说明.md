# 子脑分工帮助说明（AI 行情官｜灯塔版）

本文档解释：这里说的“子脑”是什么、怎么用、怎么查看记录，以及针对 **AI 行情官尽快开发与上线** 的最推荐分工模板（可直接照抄）。

---

## 1) “子脑”到底是什么？

- **子脑 = Cursor 里的会话代理/子智能体**（我在同一对话里并行派出去做不同任务的“协作机器人”）。
- **不是**某一台 Windows 主机。

你们的三台机器（副脑01/03/04）属于“执行环境”；Cursor 子脑属于“分工协作方式”。

---

## 2) 子脑能做什么（适合并行的工作）

- **代码盘点**：入口/页面/脚本/断链、白名单与会员提示、PWA/SW 风险点
- **后端就绪**：PG 兼容、表结构/索引、冒烟用例、配置开关与稳定性策略
- **上线与回滚**：PM2/Nginx/PG 的 runbook、三环境差异口径、备份与回滚 SOP

不适合交给子脑的：需要你本人拍板的“对外口径/商业策略/域名最终归属”。

---

## 3) 怎么查看子脑的工作记录？

### A. 在当前对话里看

子脑完成后，我会把结果汇总回主对话（含 P0/P1、文件路径、runbook）。

### B. 在项目里看（自动留痕）

仓库已启用项目 hooks，会把协作过程记录到当天日志：

- `memory/daily/YYYY-MM-DD.md`

---

## 4) 怎么“分别和子脑沟通”？

子脑不是独立聊天窗口；你只需要在主对话里说清楚分工即可，例如：

- “开 3 个子脑：A 前端体验、B 后端 PG、C 部署回滚”
- “子脑 A 只读盘点 demo/account/index 的 P0；子脑 C 输出可照抄 runbook”

我会把任务分别发给不同子脑，并把结果分段回传。

---

## 5) AI 行情官最推荐的子脑个数与分工（默认 3 个）

### 子脑 A：前端/用户路径/体验（P0 优先）

输出要求：
- 入口一致性：`index.html`、`demo.html`、`account.html` 的跳转与锚点是否一致
- 白名单策略：未登录可查清单维护点（前端/后端）是否一致，是否容易漂移
- 会员提示：未登录查询非白名单时提示是否明确（top-alert / 按钮跳转）
- PWA/SW：上线后缓存更新是否稳定（是否重复注册、是否强制 reload）
- **P0/P1 清单**：每条附文件路径与定位关键词

### 子脑 B：后端 + PostgreSQL 就绪（上线稳定性）

输出要求：
- PG 模式下是否还有 SQLite 专用 SQL 误用风险（配置错会怎样）
- `init_db()` 建表清单、是否需要最小索引、未来迁移策略风险
- 冒烟测试（≤10 条）：health/login/me/kline/quota/invite
- 数据源稳定性开关：cache/admin_config/paid provider
- **P0/P1 清单**

### 子脑 C：Windows 裸机 PG + PM2 + Nginx（上线/回滚 runbook）

输出要求：
- 需要落地的配置文件清单（.env/PM2/Nginx/端口表）
- 三环境差异（预演/国内/国际）：域名、端口、库名的最小口径
- **最短上线 runbook（10–15 条）**：可照抄执行
- **回滚 runbook（5–8 条）**：含“切回 SQLite 止血”
- 生产前检查清单：备份、日志、健康检查、冒烟

## 6) 一键“任务包模板”（复制即用）

把下列内容复制到主对话，我会按模板自动派发子脑。

### 模板：AI 行情官上线并行任务包

- **目标环境**：副脑01（预演）/ 副脑03（国内生产）/ 副脑04（国际生产）
- **域名与端口口径**：
  - a-pre：<域名> → <端口>
  - a-cn：<域名> → <端口>
  - a-intl：<域名> → <端口>
- **白名单口径**：只指数 / 指数 + 少量个股（列出清单）
- **成功标准（3 条）**：
  - [ ] `/health` 200
  - [ ] 登录→`/api/me` OK
  - [ ] `demo.html` 查询→扣次规则正确

请开 3 个子脑并行：
- 子脑 A：前端体验 P0/P1 + 需要修改的文件清单
- 子脑 B：后端 PG readiness + 最小索引建议 + 冒烟
- 子脑 C：三环境 runbook + 回滚卡片

## 7) 你们团队的“铁律”（建议贴墙）

- **预演先跑**：副脑01 不通过，禁止进生产
- **生产先备份**：副脑03/04 发布前必须 `pg_dump`
- **回滚优先回代码**：必要时才恢复 DB

## 一、数据分级（🟢🟡🟠🔴）

| 级别 | 含义 | 存放位置 | 示例 |
|---|---|---|---|
| 🟢 公开 | 可公网/群内传播 | web 静态、帮助指南 | 角色职责、文档、机型 |
| 🟡 内部 | 仅内部成员可看 | docs、收发 | IP、oid、业务规划 |
| 🟠 敏感 | 泄露有风险 | 本机 .env / 安全凭据 | API Key、appSecret、支付密钥 |
| 🔴 机密 | 最高等级 | 本机离线存储，禁止出机 | 私钥、数据库口令、客户资金 |

## 二、ops 目录安全纪律（2026-08-13 定）

- `web\ops\` 是内部机读管理目录，挂在 web 静态根 → 公网可达，但 `/ops/` 已配 **Basic Auth 兜底保护**（2026-08-12 雷总指令，凭据 `.eval-htpasswd` 内部保存、不入 git），无凭据访问返回 401。属 🟡 内部级：只放角色/职责/昵称/路径等元数据，仍禁止放密钥。
- **禁止**在 ops 及任何 web 静态目录放：API Key、appSecret、token、密码、oid、私钥、连接串。
- 机读 JSON 更新后、发布前必须自查：`rg -n -i "secret|password|api[_-]?key|bearer|BEGIN.*KEY" web/ops`，无命中才发布。
- 密钥类一律进：本机 `.env`、`安全凭据` 目录（🟠🔴），不进 git、不进 ops、不进公网、不进群私信明文。

## 三、凭据管理纪律

- 🟠🔴 凭据不提交 git（`.env` 已 gitignore）；确有需要走本机文件 + 权限控制。
- 发给副脑的部署指令中，密钥用占位符 + 各机 `.env` 实际值，不写明文。
- 定期核 04 生产 `web\ops\`、`www` 静态根是否有夹带敏感文件，发现即挪走。

## 四、归档与删除纪律

- 删除/迁移一律 Move 到 `E:\AI24X\archive\<日期>-<主题>\`，不直接删除（可回滚）；每个归档目录附 README（原路径→现路径）。
- 唯一备份目录 = `ai24x01\_backups`。
- 清理前先核对目标路径在明确目录内，禁止跨 shell 拼接路径删除。

## 五、git 纪律

- 双远端推送（gitee + origin）；提交前 `git status` 核对文件边界，不混入他人改动。
- 提交消息规范：`type(scope): 摘要`。
- 敏感文件（.env、凭据、dump）一旦发现被跟踪，立即移出 + 清理历史。

## 六、巡检节奏

- 每次部署前：web/ops 敏感词自查 + git 边界核对。
- 每周：04 公网 ops 目录巡检（供应商调研产物是否夹带 key）。
- 每月：安全事件复盘（对接 2026-08-08 复盘方案）。

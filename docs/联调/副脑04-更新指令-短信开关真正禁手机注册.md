| 你以为 | 实际旧逻辑 |

## 本包改了什么（拉码后生效）

- `api/main.py`：`effective_sms_106_enabled()` 关 → **禁止一切手机号注册**（含内部密钥）；发码/绑手机同判  
- 内部密钥仅在短信 **开** 时跳过 OTP，不再跳过开关  
- `api/system_flags.py` / `web/token-admin.html`：文案标明「关=禁手机注册/发码」  
- 历史脏手机号：本包 **不删**；继续在 token-admin **冻结**

## 验收（必须）

在 **04** 本机或可打到源站的机器执行（把 `KEY` 换成现网 `SMS_INTERNAL_KEY`，测完可不管返回体）：

```powershell
# 1) 公开手机注册 → 应 503，文案含「手机号注册暂未开放」
try {
  Invoke-RestMethod -Uri "https://api.ai24x.com/v1/auth/register" -Method POST `
    -ContentType "application/json" `
    -Body '{"phone":"13900000001","password":"Test1234!","sms_code":"000000"}' -TimeoutSec 15
} catch { $_.ErrorDetails.Message }

# 2) 带内部密钥的手机注册（旧旁路）→ 同样应 503，不再落库
$key = "<SMS_INTERNAL_KEY>"
try {
  Invoke-RestMethod -Uri "https://api.ai24x.com/v1/auth/register" -Method POST `
    -ContentType "application/json" `
    -Headers @{ "X-SMS-Internal-Key" = $key } `
    -Body '{"phone":"13900000002","password":"Test1234!"}' -TimeoutSec 15
} catch { $_.ErrorDetails.Message }

# 3) 邮箱注册路径不受影响（用真实流程或跳过）；发码关：
try {
  Invoke-RestMethod -Uri "https://api.ai24x.com/v1/auth/sms/send" -Method POST `
    -ContentType "application/json" `
    -Headers @{ "X-SMS-Internal-Key" = $key } `
    -Body '{"mobile":"13900000003","purpose":"register"}' -TimeoutSec 15
} catch { $_.ErrorDetails.Message }
```

期望：1/2/3 均为不可用类错误；token-admin **不再新增**仅手机号新用户。

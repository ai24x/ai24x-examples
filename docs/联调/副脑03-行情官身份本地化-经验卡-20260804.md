## 一、开关（admin_config / 管理台「账号模式」）

| key | 值 | 说明 |
|---|---|---|
| `auth_local_enabled` | `1` | 本地身份开关（0=转发主站旧逻辑） |
| `sms_active_provider` | `local` | 106 本地直发（正式）；`tencent` 仅临时（移动签名未过审）；`juhe` 备案中勿切；`identity_proxy`=经主站（主站关短信会挂） |
| `identity_api_base` | `https://api.ai24x.com` | 红线，勿指本机/127.0.0.1/f.ai24x.com |

## 二、必有列：`users.password_hash`

- 哈希算法：`passlib pbkdf2_sha256`（与主站 api/auth_user_service 同构 → 按 id 迁入后老用户同密码可登录）
- 检查：
  ```sql
  SELECT column_name FROM information_schema.columns
  WHERE table_name='users' AND column_name='password_hash';
  ```
- 无列：代码 auth_local 软迁（注册/改密时自动补）或 `ALTER TABLE users ADD COLUMN password_hash text;`

## 三、导入顺序（铁律，颠倒即老用户全挂）

```
1. 先按 id 导入 password_hash（POST /api/admin/auth_import）
2. 导入后必须 setval 对齐序列
3. 最后才开 auth_local_enabled=1
```
- ❌ 禁止：先开开关再导入
- ❌ 禁止：把冲突行（如 id=27 与本地 id=1 email 相同）的 hash 合并/覆盖到本地 id=1

## 四、setval（导入后必做，否则注册 500）

```sql
SELECT setval(pg_get_serial_sequence('users','id'),
              (SELECT COALESCE(MAX(id),1) FROM users));
-- 验证
SELECT last_value, is_called FROM users_id_seq;  -- last_value 应 >= MAX(id)
SELECT COALESCE(MAX(id),1) FROM users;
```
- 症状：导入固定 id 后自增序列落后 → 新注册 INSERT 撞主键 → **500 Internal Server Error**
- 代码侧已修：`2083f73`（db.py 注册时自动同步序列），但导入后手动 setval 仍建议

## 五、导入接口

```
POST /api/admin/auth_import   （需 admin session：dev code 或真实 OTP 登录）
body: {"rows":[{"id":1,"phone":"...","email":"...","password_hash":"..."}, ...]}
返回: {"ok":N,"skip":N,"error":N}
```
- error 常见：`email` 唯一约束冲突（本地已有同 email 用户）→ 属合理跳过，主脑拍板接受即可
- admin 登录（本机 dev）：`AI24X_ENV=dev` 时 POST /api/admin/login `{key, phone, otp}`，otp 用 `AI24X_ADMIN_OTP_DEV_CODE`，phone 用 `AI24X_ADMIN_OTP_PHONES` 白名单号

## 六、验收（每项都测）

1. **老用户**：原密码登录成功，`id` 不变（实测 137****8297 / id=43）
2. **新用户**：发码→注册→登录，本地分配新 id（序列修复后正常递增，实测 id=45）
3. **主站 auth_users 不增**（本地化核心指标）：
   ```
   GET https://api.ai24x.com/v1/admin/users/lookup?phone=<新号>
   带 X-SMS-Internal-Key → 期望 404「用户不存在」
   ```
4. **错密登录**：400 本地拦截（非 500）
5. 短信：106 试发网关返回 `100`（101=账号密码错，查 admin_config 的 sms_106_* 历史有效值）

## 七、本机开发对齐（雷总本机 PG 跑 a1）

- 对齐目标：**a1 的 users 表结构 / 开关习惯**，不是 04 的 Token auth_users，也不是整库拷生产数据（除非明确做脱敏副本）
- 本机起 a1：`AI24X_ENV=dev` + `AI24X_DATABASE_URL` 指本机 PG → `uvicorn app.main:app --port 8003`
- 自检 SQL（一条命令跑完）：
  ```sql
  SELECT column_name FROM information_schema.columns WHERE table_name='users' AND column_name='password_hash';
  SELECT last_value, is_called FROM users_id_seq;

  ```
- 本机测身份：`auth_local_enabled=1` + 本地注册；dev 模式短信可用 dev code / 固定验证码
- 只看静态 / 不测身份 → **不必动库**

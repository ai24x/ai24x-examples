# 账号注册登录 · 首期设计（主站）

口径对齐：`memory/decisions/DEC-0006-账号体系-手机与邮箱为主-微信后期.md`。  
**首期不含微信扫码**；**主站 `api/` 手机验证码当前走 106 网关**（腾讯云可作备用双通道）。

---

## 1. 现状与范围

| 项 | 说明 |
|----|------|
| 主站前端 | `web/login.html`、`web/register.html`：**手机 \| 邮箱** 分段；手机注册含 **短信验证码**；`?v=` 静态缓存破坏见 `web/scripts/bump_asset_version.py` |
| 主站后端 | `api/main.py`：`/v1/auth/sms/send`（106）、`/v1/auth/register`（手机 OTP 内存校验联调）；登录与落库仍待接 |
| **a.ai24x.com（`p/a`）** | **认票不存真源**：前端 **手机/邮箱 + 密码 + 注册验证码**；后端将 `/api/auth/*` **代理**到 `api` `/v1/auth/*`，JWT 与 `api` **同 SECRET**；本地仅 **影子用户**（`users.id` = `auth_users.id`）承载配额/邀请。详见 `memory/decisions/DEC-0007-身份真源-api与行情官认票.md`。 |

**非目标（首期不做）**：微信扫码登录、OAuth 第三方、无密码纯邮箱 magic link 登录（注册验证邮件仍可用链接）。

## 2. 信息架构（页面清单）

| 路由（建议） | 用途 |
|--------------|------|
| `login.html` | 登录：主切换「手机号 \| 邮箱」；手机下再切换「验证码 \| 密码」 |
| `register.html` | 注册：同上主切换；手机/邮箱各自完成验证 + 设密 + 协议 |
| `forgot-password.html` | 忘记密码：先选「手机 \| 邮箱」→ 对应验证流 → 设新密码 |
| `reset-password.html?token=…` | 邮箱重置链接落地页（仅邮箱路径；token 一次性） |
| `account.html` 或控制台内 | 登录后：**绑定手机 / 绑定邮箱**（首期可 P1） |

首页/全站导航：**登录**、**注册** 入口；**不出现微信**。页脚可灰字「更多登录方式敬请期待」。

## 3. 交互流程（文字线框）

### 3.1 登录页（默认「手机号」）

**静态页现状（已实现）**：`web/login.html` 为 **手机号 + 密码** 与 **邮箱 + 密码** 二选一，**默认手机**；提交 JSON 为 `{ "phone","password" }` 或 `{ "email","password" }`。后端 `/v1/auth/login` 仍为占位时需自行联调。下列「验证码登录」为下一迭代（与腾讯云短信）。

1. 分段：**手机号**（默认）| **邮箱**
2. **手机号**  
   - 子切换：**验证码登录** | **密码登录**  
   - 验证码：输入手机号 → 获取验证码（60s 倒计时）→ 输入验证码 → 登录  
   - 密码：输入手机号 + 密码 → 登录；链到「忘记密码」  
3. **邮箱**  
   - 邮箱 + 密码 → 登录；「忘记密码」  
4. 底部：「没有账号？去注册」

### 3.2 注册页（默认「手机号」）

**静态页现状（已实现）**：`web/register.html` 同上，默认 **手机 + 密码**；提交 `{ "phone","password" }` 或 `{ "email","password" }`。下列「短信验证码注册」为下一迭代。

1. 分段：**手机号** | **邮箱**
2. **手机号**：手机 → 验证码 → 密码（强度提示）→ 勾选协议 → 提交  
3. **邮箱**：邮箱 → 发送验证邮件 → 用户点击邮件链接打开 `reset-password` 同类页或专用 `verify-email` → 设密码 → 勾选协议 → 完成注册（或「验证通过即创建账号、密码在下一步」二选一，实现时取 **验证通过后一步设密** 更简单）

### 3.3 忘记密码

1. 选 **手机 \| 邮箱**  
2. 手机：验证码校验通过后 → **仅允许设新密码**（不自动登录，或设完可选自动登录，建议 **设完跳转登录** 降低逻辑分支）  
3. 邮箱：输入邮箱 → 发送重置链接 → `reset-password.html?token=…` → 设新密码  
4. 全局文案：**不透露该邮箱/手机是否已注册**（防枚举）；「若账号存在，您将收到短信/邮件」

## 4. API 草案（REST，供前后端对齐）

前缀示例：`/v1/auth/`（与现有占位路径一致可渐进替换）。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/v1/auth/sms/send` | **已实现（106）**：body `{ "mobile": "13800138000", "purpose": "test" \| "login" \| "register" \| "reset" }`；环境变量 `SMS_106_*`；可选头 `X-SMS-Internal-Key`（与 `SMS_INTERNAL_KEY` 一致）。同号默认 60s 冷却。 |
| POST | `/v1/auth/register/phone` | `{ phone, code, password, accept_tos_version }` |
| POST | `/v1/auth/register/email` | 发起：`{ email }` 发信；或一步 `{ email, password }` 后发验证链接（推荐异步发信） |
| POST | `/v1/auth/verify-email` | `{ token }` 换「可设密」短期 session 或直接完成注册（实现二选一） |
| POST | `/v1/auth/login/phone-code` | `{ phone, code }` |
| POST | `/v1/auth/login/phone-password` | `{ phone, password }` |
| POST | `/v1/auth/login/email-password` | `{ email, password }` |
| POST | `/v1/auth/password/reset-request` | 手机或邮箱分支：`{ channel:"phone", phone }` / `{ channel:"email", email }` |
| POST | `/v1/auth/password/reset-confirm` | `{ channel, token_or_code, new_password }` |
| POST | `/v1/auth/logout` | 作废 refresh token（若采用双 token） |

**响应**：统一 `access_token`（短）+ `refresh_token`（长，httpOnly cookie 或安全存储）或仅 access + 服务端 session（MVP 可简化，但需写明）。

## 5. 数据与风控（实现要点）

- **用户表**：至少 `id`、`email`（可空）、`phone`（可空 E.164）、`password_hash`（可空若仅验证码用户）、`email_verified_at`、`phone_verified_at`、`created_at`  
- **验证码**：Redis 或 DB 表，字段含 `purpose`、`expires_at`、`attempts`；同手机号多 purpose 隔离  
- **邮箱重置 token**：随机高熵、单次使用、短 TTL（如 30～60 分钟）  
- **限频**：同 IP / 同手机 / 同邮箱 发送间隔与每日上限；腾讯云侧模板与审核一致  
- **审计**：短信发送失败原因、邮件退信（若可）打日志，不落敏感正文

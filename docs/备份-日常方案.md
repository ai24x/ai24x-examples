## 日常备份说明（先记录，后续落脚本）

目标：在不打扰日常开发/联调的前提下，实现**可恢复、可追溯、可异地**的备份。

### 1) 备份范围（按优先级）

- **代码与文档（最高优先级）**：通过 Git 推送到远端（Gitee/GitHub）即为异地备份。
- **配置与密钥（禁止入库，但必须备份）**：
  - 各服务 `.env`（真实值）
  - Nginx 站点配置、证书与私钥（若有）
  - PM2 配置（如 `ecosystem*.js/cjs`）与自启动相关配置
- **数据（按实际服务）**：
  - **SQLite**（子项目/轻量服务）：每日备份（推荐用 sqlite 的一致性备份）
  - **PostgreSQL**（主站/核心 API）：每日 `pg_dump`（若当前已启用）
- **可选运行态**：
  - 用户上传目录/静态资源目录（若存在）
  - 重要日志（仅保留最近若干天，用于回溯；不建议长期囤积）

### 2) 推荐策略（分层 + 保留 + 异地）

- **频率**：
  - 每日一次（建议凌晨 03:30）
  - 重要升级/数据库迁移前：手动补一次“升级前快照”
- **保留**：
  - 本地保留 14 天
  - 异地保留 90 天（或按成本调整）
- **异地**：
  - NAS/另一块盘/云盘挂载目录（保证与部署机物理隔离）

### 3) Windows（副脑03）最小可执行流程（后续写脚本）

建议落地目录（示例）：

- 本地：`E:\\BACKUP\\ai24x01\\`
- 异地：`X:\\ai24x01\\`（NAS/云盘挂载盘符）
- 日志：`E:\\BACKUP\\ai24x01\\logs\\`

每日任务执行步骤（示例）：

1. **打包配置**：收集 `.env`、Nginx 配置、PM2 配置、关键运维脚本
2. **备份数据库**：
   - SQLite：使用 `sqlite3` 的 `.backup` 生成一致性备份，再 zip
   - PostgreSQL：`pg_dump` 输出为 `.sql` 或 `.dump`，再 zip
3. **生成校验**：对 zip 生成 `sha256`（可选）
4. **同步到异地**：`robocopy` 或等价方式
5. **清理旧备份**：按保留策略删除过期目录

### 4) 备份是否靠谱的唯一标准：可恢复

每周抽检（可选自动化）：

- 从最近备份解压到临时目录
- 用备份 DB 启动一次 API（或至少执行一次只读查询）
- 通过才算合格（否则视为“备份失败”）

## 6) PostgreSQL（Windows 裸机）最小命令卡（可直接手动跑）

以下示例以 **AI 行情官** 的库为例（副脑03：`ai24x_a_cn`）。请按环境替换库名：

- 预演（副脑01）：`ai24x_a_pre`
- 国内生产（副脑03）：`ai24x_a_cn`
- 国际生产（副脑04）：`ai24x_a_intl`

### 6.1 备份（推荐 custom 格式，恢复更稳）

PowerShell：

```powershell
$ts = Get-Date -Format "yyyyMMdd-HHmmss"
$outDir = "E:\BACKUP\ai24x01\pg"
New-Item -ItemType Directory -Force -Path $outDir | Out-Null

# 方式 A：使用环境变量（推荐：从 .env / 系统环境变量读取）
pg_dump -Fc -Z 6 -f "$outDir\ai24x_a_cn-$ts.dump" "postgresql://ai24x_a:<PASSWORD>@127.0.0.1:5432/ai24x_a_cn"

# 方式 B：使用本机已配置的 PG 账号（如已在 pgpass / 登录态中）
# pg_dump -Fc -Z 6 -f "$outDir\ai24x_a_cn-$ts.dump" -h 127.0.0.1 -p 5432 -U ai24x_a ai24x_a_cn
```

### 6.2 恢复（兜底用，先停写/维护模式）

```powershell
# 先确保目标库存在（必要时先 drop/recreate）
pg_restore --clean --if-exists -d "postgresql://ai24x_a:<PASSWORD>@127.0.0.1:5432/ai24x_a_cn" "E:\BACKUP\ai24x01\pg\ai24x_a_cn-YYYYMMDD-HHMMSS.dump"
```

> 原则：**生产恢复前先停写**，并保留“恢复前快照”（再备份一次）。

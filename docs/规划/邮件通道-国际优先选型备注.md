## 2. QQ SMTP 是否够用？

**结论：只适合短期联调 / 极低日活，不适合国际站正式增长。**

经验量级（腾讯侧动态风控，非合同保证，以实际为准）：

| 口径 | 量级（约） |
|------|------------|
| 普通个人邮 | 100–200 封/天 |
| VIP / 老号 | 200–500 封/天 |
| 频率 | 每分钟十几封即易触发风控（如 535 / system busy） |
| 其它风险 | 云主机新 IP 易拦；国外邮箱进信箱率差；发信显示为个人 QQ |

日注册验证码若仅几十～一两百封，可能暂时扛住；真正卡脖子的是**风控、送达率、品牌**，不是「日上限数字」本身。

---

## 3. 国际优先：供应商怎么选？

产品战略为**国际优先**时，**不要优先腾讯/网易企业邮作主通道**（国内送达尚可，对 Gmail / Outlook.com / 海外企业邮一般）。

应使用 **Transactional（事务邮件）** 服务，发信身份为自有域名（如 `noreply@ai24x.com` 或子域）。

| 供应商 | 定位 | 建议 |
|--------|------|------|
| **Resend** | 现代 SaaS、接入快、免费档约 3k 封/月 | **首选起步** |
| **Postmark** | 验证码/账单送达口碑最好 | 验证码进垃圾箱多时升级或并行 |
| **Amazon SES** | 单价低、量大省钱 | 量起来且有运维精力后再上 |
| 腾讯企业邮等 | 国内友好 | 仅作国内备用，不作国际主通道 |

### 推荐路径

1. **现在**：QQ SMTP 顶着用（联调 / 种子）  
2. **正式对外**：域名接入 **Resend**（SPF / DKIM / DMARC）  
3. **体验不稳时**：关键事务邮件切或并行 **Postmark**  
4. **超高量**：再评估 SES  

---

## 4. 域名与合规注意

- 发信用**独立子域**更稳，例如 `mail.ai24x.com`，避免主域信誉被营销/异常流量拖垮  
- 事务邮件（验证码）与营销邮件**分通道**，勿混在同一事务 IP/域名上狂发推广  
- 密钥只写各机 `api/.env`，勿进 git / 指挥中心 JSON / 公开文档  

DNS 配齐后再切生产 `SMTP_*`（或后续专用 API Key 通道），`pm2 restart core-api-8002 --update-env`。

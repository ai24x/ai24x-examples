# Gitee 仓库可见性与凭据习惯 · 规划备注

> 日期：2026-07-27  
> 状态：临时便利 / **主站对外开放推广前必改**  
> 核对：当日 API 确认 `ai24x/ai24x01`、`ai24x/ai24x-website` 均为 **private**

---

## 1. 当前约定（先用着）

| 项 | 现状 | 说明 |
|----|------|------|
| 仓库可见性 | **私有** | 未登录外人不可拉代码；API 未鉴权探测为 404 |
| 双 remote | `gitee` → `ai24x01`；`origin` → `ai24x-website` | 发版须双推 |
| HTTPS 凭据 | 本机 remote URL 内嵌私人令牌（方便推送） | **仅本机便利，不入仓库文件** |

现阶段种子期 / 内测：以「推送省事」为先，**不立刻**改成 SSH / 凭据管理器，避免打断日常发版。

---

## 2. 风险（心里有数）

- 仓库私有 ≠ 令牌安全：令牌写在 `git remote` URL 里，会出现在本机配置、部分脚本输出、协作日志中  
- 令牌泄露 ≈ 有人能以该账号读写私有库（视令牌权限）  
- 公开文档 / 指挥中心 JSON / 聊天记录 **禁止**再贴完整 remote（含令牌的 URL）

---

## 3. 主站对外开放推广前 · 必做提醒（闸门）

**触发条件（任一即执行本节）：**

- 主站 / Token 正式对外获客、投放、SEO、公开注册推广  
- 仓库协作者增多、副脑机增多、或准备开源部分模块  
- 怀疑令牌曾出现在日志 / 截图 / 聊天

**改进清单（P0）：**

1. Gitee 网页再确认两仓仍为 **私有**（未误开公开）  
2. **作废**当前私人令牌并重新生成；旧令牌立即失效  
3. remote 改为**不含密钥**的地址，例如：  
   - `https://gitee.com/ai24x/ai24x01.git`  
   - `https://gitee.com/ai24x/ai24x-website.git`  
4. 本机改用 **Windows 凭据管理器** 或 **SSH 密钥** 推送；副脑机同样不在 URL 内嵌令牌  
5. 抽查：`git remote -v` 输出中不得再出现明文 token  
6. 确认 `.env`、证书、SMTP/支付密钥从未进过 git 历史（若进过：轮换密钥 + 历史清理另案）

**可选（P1）：**

- 副脑只读部署令牌与主脑推送令牌分离  
- 打开 Gitee 操作日志 / 异常登录关注  
- 发版脚本统一走凭据助手，禁止打印 `remote -v` 全量到群聊

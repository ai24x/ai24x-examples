# 免费共享通道 · 独立运营域（2026-07-30）

## 产品结论

**应该独立管理，而且要做好——但是「优秀」的定义是引流转化，不是无限白嫖。**

| 原则 | 口径 |
|------|------|
| 漏斗顺序 | 试用礼包 → **主推付费** → 可选「继续免费共享」 |
| 与付费隔离 | 共享只走 **L0**，绝不进 flash/pro/ultra 付费池 |
| 运营独立 | 后台单独菜单「免费共享」：开关 / 日帽 / 主力池 / 今日用量 |
| 引流体验 | 稳、快、有日帽提示、升级按钮醒目；文案不暴露硅基/OR |
| 防刷 | 日请求帽 + 日 token 帽；OTP 注册；有量再上验证码墙 |

## 共享池要不要做成仓库？

**要。** 已按「小仓库」管理：目录启停、定主力、看连通/成本/扩容说明。用户对外仍只见 `shared`。

### 当前连通（本机实测口径）

| 条目 | 角色 | 连通 |
|------|------|------|
| 硅基 Qwen2.5-7B | 主力 | Key 已配 → L0 实际走 siliconflow |
| OpenRouter Auto | 备 | OR 模式已开 → 可作备 |
| OR Free / GLM / BYOK | 目录 | 规划或待启 |

只有 2 条在「启用链」里是刻意的：先把 **免费+稳** 跑通，再往池里加。

### 启用 / 主力 / 调度（已落地）

| 控件 | 规则 |
|------|------|
| **启用** | 多选：进容灾/轮询池 |
| **主力** | **单选**：failover 先打谁；rotate 轮询起点 |
| **挂了自动顶上** (`failover`) | 主力失败 → 其余启用项依次试 |
| **多条轮询** (`rotate`) | 每次请求换起点，降低单接口限流/封禁 |

### 付费仓库要不要同样改？

付费侧**已有层内容灾**（FREE `L1→L0`，VIP `L1→L2→L3`），不必再抄一套「主力单选」。继续优化重点：层 model 可改、目录状态、毛利——与共享池职责分开即可。

## 一、两个场景（兜底路径不同）

- **场景 A：总司令 gateway 卡死**（本机还活着，Codex 项目官还活着）
- **场景 B：总司令整机关机**（Codex 也失联，只剩远程副脑）

## 二、兜底四步（检测 → 上报 → 降级 → 恢复）

### ① 检测（谁发现失联）
- 副脑 01/02/03/04：各自「主脑心跳检测」——查指挥部群心跳，**>120 分钟无心跳 = 判定失联**（02 已有 main-brain-check.mjs，01/03/04 需补齐）
- Codex 项目官（场景A）：本机检测 gateway 端口 18789 无响应，判失联

### ② 上报（谁通知雷总）
- 副脑：飞书**私信雷总**，前缀「⚠️主脑失联降级」，每 6h 合并一条（P0 事故立即发）
- Codex（场景A）：用 `scripts\feishu_send.ps1` 兜底直发飞书，注明「兜底直发」

### ③ 降级（失联期间各角色怎么办）

| 级别 | 动作 |
|---|---|
| 🟢 岗位日常 | 副脑照常干活；Codex 各项目**照常编码**（不依赖总司令） |
| 🟡 需总司令路由/跨项目协同 | 暂停，等恢复 |
| 🔴 生产/密钥/支付/审批 | **一律暂停等雷总** |

### ④ 恢复（总司令回来后）
发「✅恢复公告」→ 补跑巡检 → 各副脑/项目官补报失联期间产出 → 总司令归档。

## 四、敏感信息分级通道（配套规则）

| 级别 | 内容 | 通道 |
|---|---|---|
| 🟢 普通 | 协同/汇报/进度 | 飞书群（group_msg 可读，没关系） |
| 🟡 普通敏感 | 账号密码/注册信息 | 飞书私信雷总（不进群不留痕） |
| 🟠 高危 | 支付凭证/生产密钥/Gitee密码 | SSH 直连 + 加密文件（不过飞书） |
| 🔴 顶级 | PayPal Live/生产 .env/appSecret | 本地加密文件/密码管理器 |

**铁律**：🟠🔴 永不进群、永不私信明文，只走 SSH/加密文件。飞书只承载 🟢🟡。
**权限最小化**：不需读全群消息的副脑，降级用 `im:message.group_at_msg`（只读@自己）。

## 五、SSH 专属通道（安全背板）

- 主脑 ↔ 副脑 SSH 直连（公钥 id_ed25519 已装 4 台，BatchMode 免密）
- 敏感配置：scp 拉本地改 → 加密回传；高危凭证：SSH 登录远程直接操作，不过飞书
- **飞书 = 协同脑（看得见），SSH = 安全背板（敏感管道）**

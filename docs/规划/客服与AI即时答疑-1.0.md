# 国际 Token · 客服与 AI 即时答疑（拍板草稿）

> **版本**：1.0 · 2026-07-31  
> **现状**：行情官 `a.ai24x.com` 已有登录工单；**主站 Token / 国际控制台尚无闭环反馈**（partner 文案写「工单上线后启用」）。

---

## 1. 目标

一人公司要扛国际开发者：**80%+ 开发/调模问题由 AI 即时解决**；人工只接支付异常、账号冻结、账单争议、AI 解决不了的投诉。

---

## 2. 三层机制（推荐）

```
用户遇阻
  ├─ ① AI 助手（控制台内嵌 / docs 侧栏）← 即时，默认入口
  ├─ ② 结构化自助（状态页、错误码释义、余额/限流说明）← 零人工
  └─ ③ 人工工单（建议 / 投诉 / 支付）← 异步；飞书通知 01/04
```

| 层 | 解决什么 | 不做 |
|----|----------|------|
| **AI 即时** | API 怎么调、model/档位含义、401/402/429、PayPal 到账多久、VIP 点名怎么开 | 不直接改库、不承诺退款、不泄露他人数据 |
| **自助** | 平台状态、已知故障、定价 FAQ | 不替代工单 |
| **人工工单** | 投诉、未到账、封禁申诉、商务合作 | 不当即时聊天室（一人扛不住） |

---

## 3. AI 即时反馈 · 怎么做到「绝大多数问题」

### 3.1 知识源（比「裸聊大模型」重要）

| 源 | 用途 |
|----|------|
| 英文 Quickstart + 错误码表 | 调用问题 |
| 公开 `/v1/models`、档位说明、VIP 点名规则 | 选模问题 |
| 定价 / PayPal 流程 FAQ | 账单问题 |
| **只读**用户上下文（登录后）：余额、最近 3 条 ledger、最近错误码 | 「为什么扣费/失败」 |

系统提示固定：基于文档与上下文回答；不确定则引导「提交工单」并预填分类。

### 3.2 路由与成本

- 走平台 **L1 flash**（或 shared 以外的内部助手额度），单独 `entry_type=support_bot`，**不扣用户余额**（平台成本）。
- 日帽：每用户 N 次/日，防刷。
- 回答后展示：「有用 / 仍需人工」→ 点后者一键开正式工单（带对话摘要）。

### 3.3 与「留言反馈」的关系

- **聊天式 AI** = 即时排障  
- **工单表单** = 正式建议/投诉（可附件、可追踪状态）  
- 禁止只有邮箱留言、无状态回执（国际用户最恨「石沉大海」）

## 4. 人工侧 · 提效（不为 7×24 真人）

| 项 | 口径 |
|----|------|
| 入口 | 控制台「Help」：AI 优先，工单其次；页脚 Help |
| 分类 | `billing` / `api` / `account` / `suggestion` / `complaint` |
| 通知 | 新工单 → 飞书 副脑01（国际）或 04；P0 投诉 @主脑 |
| SLA 话术 | 英文写清：支付类 1 个工作日；普通 2–3；不承诺秒回真人 |
| 后台 | token-admin 增「工单」列表：状态、备注、关闭；复用 a1 feedback 思路，**主站独立表，不混行情官库** |

---

## 5. 分期

| 期 | 交付 | 优先级 |
|----|------|--------|
| **P0** | 控制台内嵌 AI Help（文档 RAG 或精简 system+FAQ）+ 「转人工」开单 API/页 | 国际转化关键 |
| **P0** | 错误码用户文案 + docs 英文 FAQ（401/余额不足/429） | 减 50% 重复问 |
| **P1** | 工单后台 + 飞书推送 + 我的工单状态 | 投诉闭环 |
| **P2** | 登录后注入余额/最近错误给 AI；状态页 | 深度排障 |
| **不做（现阶段）** | Intercom/Zendesk 全套；7×24 真人在线；电话客服 | 成本与编制 |

# 12 · 老板 → 司令/指挥 → 副脑 顶级模式

> 版本：V1.0 · 2026-08-08 · AI24X 营销体系实战沉淀（2026-08-07 首建，08-08 定稿）
> 解决的问题：在「老板 + 司令(Codex) + 指挥(主脑) + 多台副脑」的顶级指挥结构下，如何单向派发、双向秒级通信、可审计、防重复、防递归、防封号。

---

## 一、顶级模式结构（谁是谁）

```
雷总（老板·拍板）
 ├─ 司令（Codex·本机）     战略层：策略/拍板前会诊/审批矫正/疑难兜底
 │   对外代号：司令 / 总司令
 └─ 指挥（主脑 OpenClaw）  调度层：派发/监督/验收/汇总/飞书单一出口
     对外代号：指挥 / 指挥官
      └─ 副脑 01/02/03/04  执行层：国际获客 / 中国运营 / 运维CN / 运维SG
```

- **老板消息前缀**：`司令:` / `总司令:` = 给司令（兼容旧 `cx:`）；无前缀 = 给指挥
- **飞书出口唯一 = 指挥**：司令回复经指挥转达（带 `[司令]` 标记）；司令不直发飞书，仅指挥失联兜底并注明
- **层级铁律**：司令是战略层，不陷入操作层；指挥是调度中枢；副脑是执行层。派发一律 司令→指挥→副脑

---

## 二、双向通信协议（类 SSH，秒级往返）

| 方向 | 通道 | 说明 |
|------|------|------|
| 司令→指挥 | `openclaw agent --agent main --message-file <指令>` | 同步，秒级~分钟级；长任务先 ACK 后异步 |
| 指挥→司令 | `cx_bridge.ps1` 驱动本机 `codex exec` | 默认写持久值守线程 `019fdcdd-e3e7-7122-90a0-8ac181c9b141`，任务/回复追加成连续记录 |
| 司令↔指挥 共享 | 收发目录 `收发\指令\` + `收发\回复\` | 指令、回复、回执全落盘，文件即审计 |
| 指挥→副脑 | SSH 派发任务文件 + 驱动执行 | 副脑执行完写回执 / 发飞书群 |

- **桥接模式 = 派发+确认**：长链条任务（司令→指挥→四副脑→汇总）只派发不同步等待；结果由指挥异步执行后飞书汇报
- **验收链（实测通过 00:16-00:25）**：司令→指挥→副脑→发飞书群→指挥读群验收→飞书私信老板

## 三、本次沉淀的关键踩坑（2026-08-07/08）

1. **P3 SIGKILL 根因**：指挥 exec 工具约 120s 超时杀进程树 → 长链条任务同步等待必然被杀。根治：桥接改"派发+确认"、任务预算≤100s、长任务指挥直执行、失败 2 次停止重试。
2. **codex exec 写完回复不退出**：config.toml `notify` 钩子（turn-ended 跑 computer-use exe）挂起 → 必须加 `-c "notify=[]"`。
3. **模型短名不被网关接受**：`-m flash` 报错，必须用 config 默认 `deepseek-v4-flash`（不传 -m/-c）。
4. **codex exec 沙箱只读**：默认沙箱写不了收发目录 → `--sandbox danger-full-access`。
5. **双飞书出口 = 重复消息**：司令直发 + 指挥转达各发一遍 → 定"飞书单一出口"：指挥统一转达，转达前查 `_sent\` 防重复。
6. **副脑只写回执不发言**：派发任务必须显式写"发飞书群"，否则副脑只落盘文件 → 验收必须读群核对消息 ID 与内容。
7. **PowerShell here-string `$` 插值**：双引号 here-string 写指令文件会把 `$0.35` 变成 `.35`（`$0` 被当变量）→ 含 `$` 的指令/文档一律用单引号 here-string。
8. **主脑上下文膨胀**：会话 947 行 / 53 万 token → 每轮变慢 → 上下文卫生（超 30 万归档压缩）+ 先ACK后干活 + 回复≤3 行。
9. **cron 递归**：指挥 cron 若驱动所有指令文件，司令派发的 `codex-*` 文件会被再驱动 → cron 只驱动 `老板-*` 指令；`codex-*` 派发文件由指挥自读自执行。
10. **feishu_send.ps1 反斜杠 bug**：消息含路径 `收发\指令\` 破坏 JSON → 改用 ConvertTo-Json 双层转义。

## 四、指挥失联降级预案（2026-08-08 定）

- **判定**：司令连续 2 次 `openclaw agent --agent main` 调用失败/超时 = 指挥失联
- **降级动作**：
  1. 老板回本对话（司令）直接接管调度
  2. 司令本机直连 01（本机 OpenClaw）发紧急操作，结果落盘 `收发\回复\` 保审计
  3. 需远程机（02/03/04）的操作暂缓，待指挥恢复
  4. 指挥恢复后补同步审计（直连操作补录给指挥）
- **不设常规直连**：保持 司令→指挥→副脑 单线派发，指挥统一调度/验收/审计；直连仅限失联降级

## 五、纪律红线

- **宁慢勿封**：外网账号操作频率一点点来，账号是稀缺资产
- **能落盘就不靠记忆**：规则/决策/踩坑全部写文档，重启不失忆
- **单向派发 · 单一出口 · 先ACK后干活 · 上下文卫生 · 转达前查重**
- **战略不陷入操作层**：司令只做战略与拍板前会诊，操作交给指挥与副脑

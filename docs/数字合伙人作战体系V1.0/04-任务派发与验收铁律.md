# 04 · 任务派发与验收铁律

> 版本：V1.0 · 2026-08-03 · AI24X 实战沉淀
> 解决的问题：派活怎么派才不白派（曾经：副脑收到指令但零产出，老板问责）

---

## 一、事故背景（为什么要立这条铁律）

2026-08-01 凌晨派发 03→04 迁移任务，副脑收到指令但**未执行**（03 交接物零产出），雷总 08:54 问责。根因：
- 指令措辞软（「准备一下」非「交付」）
- 飞书群 @ 对副脑 agent 失效未验证
- 无夜间盯梢

**从此确立四条硬规矩：**

---

## 二、铁律一：任务必须带「三要素」

```markdown
任务 = 目标 + 验收标准 + 硬性截止时间 + 完成即报
```

- ❌ 禁止：「准备一下」/「有空看看」/「明天再说」
- ✅ 必须：「X 前交付 Y，验收标准 Z，完成后立即报」

派发即目标驱动，禁说「准备一下」。

---

## 三、铁律二：指令送达必须验证（10 分钟内）

**飞书群 @ 对副脑 agent 可能失效！群消息不算数。**

```powershell
# 派发后 10 分钟内 SSH 确认副脑 agent 已启动
# （新 jsonl 出现 = 已开始跑）
ssh <SSH用户名>@<副脑IP> "dir /o-d <副脑用户目录>\.openclaw\agents\main\sessions\ | findstr /i jsonl"
```

- 未启动 → 立即改 SSH 直驱（可靠驱动命令见下）

**可靠驱动命令（首选）：**
```powershell
ssh <SSH用户名>@<副脑IP> "openclaw agent --agent main --message-file <副脑用户目录>\ops\<任务文件>.txt"
```

流程：任务文件写好 → scp 上传到副脑 ops/ → SSH 驱动执行。

---

## 四、铁律三：夜间自动盯梢（cron 检查点，永久挂载）

| 检查点 | 时间 | 动作 |
|--------|------|------|
| 隔夜巡检 | 06:30 | SSH 查各副脑夜间产出 → 缺失自动补催 |
| 晨间汇总 | 07:30 | 汇总夜间成果 → 晨报待审清单 |

凌晨派发的任务，必须设 cron 检查点（如 06:30 查副脑夜间产出，缺失自动补催）。

---

## 五、铁律四：副脑卡点 30 分钟必须主动上报

- 卡点 30 分钟不报 = 失职（记入各副脑 SOP）
- 「等指令」思维 → 改造为「目标驱动」：任务带截止时间，到点未完成自动上报

---

## 六、验收标准（怎么算完成）

1. **三要素对照**：目标达成？验收标准过？截止时间守？完成即报？
2. **留痕验证**：产物落盘（ops/ 文件、日志），主脑可复查
3. **功能实测**：能跑通才算（不是写了就算）
4. **回执文件**：任务完成后写 `ops/task-<日期>-ack.txt` 回报

---

## 七、远程操作安全准则（配套）

### 操作铁律
1. **涉及 03/04 生产变更** → 必须先私信请示雷总
2. **重大生产问题** → 发现→汇报→审核→批准→由生产环境上的 OpenClaw 执行记录；主脑不得直接改动
3. **任何核心配置修改前** → 先备份（scp 拉本地或 cp xxx.bak）
4. **改完必须验证** → JSON语法/服务状态/功能
5. **无回滚路径不改**

### 安全分级

| 级别 | 操作 | 要求 |
|------|------|------|
| 🔴重大 | 密钥/域名/数据库/防火墙 | **请示雷总** |
| 🟡中 | OpenClaw配置/Nginx/插件 | 先备份再改 |
| 🟢常规 | 查日志/查状态/重启 | 标准流程 |

---

## 八、远程 SSH 操作推荐流程

```
scp 远程配置文件到本地备份
 → 本地改好并验证
 → scp 回远程
 → 重启
 → 验证功能
```

**SSH 命令模板：**
```powershell
ssh -o ConnectTimeout=10 -o StrictHostKeyChecking=no -o BatchMode=yes <SSH用户名>@<IP> "<命令>"
```

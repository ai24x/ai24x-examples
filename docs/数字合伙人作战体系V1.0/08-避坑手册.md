## 一、记忆与信息管理类

### 坑 1：memory_search 索引损坏 → 主脑「失忆」（2026-07-31）
- **事故**：memory_search 依赖 embedding key，未配置 → 索引损坏 → 主脑误判「失忆」→ SSH 用户名错误未发现 → 指挥链路瘫痪半天
- **教训**：
  - **memory_search 不可用 ≠ 失忆**。搜索失败时降级直接读文件：`MEMORY.md` → `memory/*.md` → `ops/*.md` → `docs/*`
  - 关键连接信息（SSH 用户名/IP/飞书Oid）以 MEMORY.md 为**单一事实源**，文档漂移是事故温床
  - 连接信息写入记忆前**必须实测**（SSH 连一次通过才算数）

### 坑 2：规则/决策不落盘 → 重启即忘
- **教训**：重要决策、规则、教训必须写进 MEMORY.md 或 memory/YYYY-MM-DD.md，不依赖会话记忆

## 二、SSH 与远程连接类

### 坑 3：SSH 用户名记错 → 四台全拒（2026-07-31）
- **事故**：用了 `ai24x@`（不存在此用户）→ 四台副脑全连不上；还误以为密钥问题，白折腾一轮
- **真相**：用户名是 **`Administrator`**（大写 A）
- **教训**：`ssh <SSH用户名>@<IP>`，不是 `ai24x@` / `administrator@` 或其他变体

### 坑 4：sshd_privsep 账户缺失 → 认证链路断裂
- **现象**：`lookup_sid failed: 1332`，连接时断时续
- **教训**：Windows OpenSSH 需要 `sshd_privsep` 账户，缺失需修复

### 坑 5：04 SSH 间歇性 Connection closed
- **现象**：<04IP> 时通时断（2026-08-02 01:40 起）
- **教训**：不影响派发，但影响主脑主动驱动 04；排查中

## 三、OpenClaw 配置与运行类

### 坑 6：`openclaw gateway restart` 卡死！
- **真相**：restart/stop 通过 WebSocket 发指令，有活跃连接时超时卡死
- **正确姿势**：
  ```powershell
  taskkill /f /fi "IMAGENAME eq node.exe"
  timeout 3
  schtasks /run /tn "OpenClaw Gateway"
  ```

### 坑 7：乱改模型配置 → 代理掉线（2026-08-03！）
- **事故**：给 deepseek 配置加了 `input: ["text","image"]` → OpenClaw 发送带图片结构的请求 → **DeepSeek 官方 API 拒绝该 schema**（`provider rejected the request schema or tool payload`）→ 每次请求失败 → 表现成「连不上」
- **教训**：
  - **禁止乱改模型配置**：给模型加 image/能力前，先确认上游 API 真实支持（DeepSeek 官方 API 不支持图片输入！）
  - 改配置必备份 + 改完必验证
  - **看不了图 ≠ 切模型/改配置**：图片任务用浏览器/截图/curl 另想办法，不许动主链路配置
  - 主会话固定 DeepSeek 默认，测自家平台用临时子 agent / curl / 浏览器

### 坑 8：baseUrl 缺 /v1 → 405 卡死（2026-08-02）
- **事故**：OpenClaw openai-completions 模式请求 `{baseUrl}/chat/completions`；填根域名 → `/chat/completions` → 405 → 自动重试 3 次 → 表现卡死
- **修复**：baseUrl 必须带 `/v1`：`https://api.your-domain.com/v1`
- **通用**：LobeChat/Open WebUI 等客户端同样填 `/v1`

### 坑 9：key 被自动脱敏 → 401（2026-08-02）
- **事故**：从终端/SSH 复制长密钥时被自动脱敏成 `sk-xxx…xxx`（带省略号）→ 写入配置 → 请求 401
- **修复**：key 交付改**分段文件**（key-part1/2.txt）+ 配置写入完整 key
- **注意**：飞书消息里发 key 也可能被打码成省略号，分段发或文件交付

### 坑 10：key 会被轮换 → 旧 key 失效
- **事故**：测试 key 可能被重新生成后旧 key 失效（401）
- **教训**：key 失效先查是否被轮换，再查权限

### 坑 11：网关重启写回丢 provider 配置
- **真相**：OpenClaw config 写回时自定义 provider 可能被抹掉
- **教训**：改完配置注意复查；重启后验证 provider 还在

### 坑 12：飞书插件 ID 是 `feishu` 不是旧版名
- 配置 `plugins.entries.feishu.enabled: true`，不是 `feishu-openclaw-plugin`

## 四、飞书协同类

### 坑 13：飞书群 @ 对副脑 agent 可能失效
- **事故**：群里 @ 副脑，副脑 agent 未触发（8/1 迁移任务零产出的帮凶）
- **修复**：派发任务用 **SSH message-file 驱动**（`openclaw agent --agent main --message-file`），飞书群仅作通知

### 坑 14：飞书跨应用 open_id 不通用
- **真相**：各副脑用独立飞书应用（不同 appId），主脑手里的雷总 open_id 只对主脑应用有效
- **修复**：副脑从「指挥部群成员列表」解析本应用视角的雷总 open_id 后再私信

### 坑 15：副脑心跳每小时发群 → 刷屏（2026-08-03 雷总反馈）
- **修复**：心跳改为落盘日志（`ops/sub-brain-heartbeat-0X.log`），主脑统一巡检汇总，不再每小时发群
- 失联兜底（主脑挂→私信雷总）保留

## 五、社交账号与风控类

### 坑 16：X 账号被封禁（2026-08-01）
- **事故**：AI 机器人操作翻阅过多 → X 临时/永久封禁
- **教训（铁律）**：
  - 控制操作频率（勿高频翻阅/点赞/关注）
  - 模拟真人行为节奏（随机间隔、合理动作序列）
  - 新号前 24-48h 低活跃、只读为主
  - 遇到风控提示立即停止操作，报主脑，勿重试硬冲
  - **宁慢勿封：账号是稀缺资产**

### 坑 17：Google 账号验证
- `<弃用邮箱>` → 不存在（Google 报「找不到此账号」）
- `<谷歌邮箱>` → 有效（2FA 配合通过），用于 X/Reddit OAuth 登录
- **教训**：账号先验证再依赖

## 六、任务管理与流程类

### 坑 18：任务派发无三要素 → 零产出（2026-08-01）
- **事故**：「准备一下」式指令 → 副脑收到但未执行 → 雷总问责
- **修复**：任务必须带 目标+验收标准+截止时间+完成即报；派发后 10 分钟验证送达；夜间设 cron 盯梢

### 坑 19：cron 检查产物用错时间窗 → 误报/误驱动（2026-08-03）
- **事故**：用「01:00 后产物」过滤 ops 目录，但验收产物是历史时间戳 → 误报「未完成」→ 误驱动 04 重跑含 Restart-Service 的旧任务
- **教训**：cron 检查产物必须结合记忆（验收产物可能是历史时间戳）；驱动前先确认是否已验收完成

### 坑 20：主脑失联无降级条款 → 无人上报（2026-08-02）
- **事故**：雷总关机主脑 → 副脑无失联路径 → 雷总问责
- **修复**：主脑失联降级协议（心跳/失联感知/降级动作/巡检冗余）——见 05 篇

### 坑 21：夜间任务无人盯梢 → 空转 6.5 小时
- **修复**：06:30 隔夜巡检 + 07:30 晨间汇总 cron 永久挂载

## 七、编码与脚本类

### 坑 22：PowerShell 写 .ps1 无 BOM → 中文乱码/语法错乱
- **真相**：write 生成的 .ps1 无 BOM 会被 PS5.1 按 GBK 解析 → 语法错乱
- **修复**：脚本重存为带 BOM 的 UTF-8

### 坑 23：`sc` 在 PowerShell 里是 Set-Content 别名
- **真相**：`sc query` 会出错
- **修复**：查服务必须用 `sc.exe query`

### 坑 24：副脑 SSH profile 是 `<副脑用户目录>` 不是 `<主脑用户目录>`
- **教训**：巡检脚本必须自适应定位 `.openclaw`；远程命令用 Base64 EncodedCommand 最稳

### 坑 25：正则替换 JSON 配置误判 → 文件损坏
- **事故**：正则没匹配到却误判有变化 → 写坏 openclaw.json
- **修复**：改配置用 Python 解析 JSON（备份+校验+回滚），别用正则硬改；改完立即 `ConvertFrom-Json` 校验

## 八、核心教训总结（浓缩版）

1. **连接信息实测后才可信**，写入记忆前 SSH 连一次
2. **搜索不可用 ≠ 失忆**，直接读文件
3. **改前必备份，无回滚不改**
4. **主链路配置（模型/网关）绝不乱动**，测新东西用隔离环境
5. **任务派发三要素 + 送达验证 + 夜间盯梢**
6. **宁慢勿封**（社交账号/爬虫）
7. **能落盘不靠记忆**，规则教训写进文档
8. **文档漂移是事故温床**，单一事实源（MEMORY.md）

# 05 · 心跳与失联降级协议

> 版本：V1.0 · 2026-08-03 · AI24X 实战沉淀
> 解决的问题：主脑挂了怎么办？副脑怎么感知、降级、直达老板？（容灾设计）

---

## 一、事故背景

雷总特意关机主脑 → 副脑失去 SSH 指挥通道 → 按规划应私信雷总汇报，但**无人上报** → 雷总问责。
根因：① 所有上报路径写「报主脑」，无失联条款 ② 夜间静默规则反向约束 ③ 盯梢 cron 全挂主脑网关=单点 ④ 主脑关机无停机公告。

---

## 二、失联感知（心跳机制）

### 主脑侧
- 主脑挂 cron：**每 60 分钟**向指挥部群发一条心跳 `🔋主脑心跳 HH:MM`（轻量）
- 主脑关机/网关停止 → 心跳自然停发 = 失联信号

### 副脑侧（各副脑本机挂 cron，每 60 分钟）
1. 读取指挥部群最近消息，找主脑最后一条消息时间戳
2. `距现在 > 120 分钟` → 判定「主脑失联」→ 写状态文件 `ops/main-brain-status.json`（{"status":"lost","since":"<时间>"}）
3. `距现在 ≤ 120 分钟` → 判定「主脑在线」→ 若之前是 lost，写回 online 并补发失联期摘要

### 探测方式优先级（任一可用即可）
1. 飞书 API 读群消息（本应用有权限时）
2. 本地 OpenClaw 会话/事件日志中主脑消息最后时间
3. SSH ping 主脑 IP（若开通入站）

### ⚠️ 心跳落盘 vs 发群（2026-08-03 优化）
- **副脑常规心跳**：改为**落盘日志**（`ops/sub-brain-heartbeat-0X.log`），不再每小时发群（避免刷屏）
- **失联兜底**：保留——主脑失联 >120min → 群发⚠️降级汇报 + 私信雷总
- **主脑心跳建议保留发群**：副脑失联探测依赖主脑心跳消息进转录，主脑心跳停发则探测无源

## 三、失联降级动作（触发后）

| 事项 | 失联时动作 |
|------|-----------|
| 🟢 岗位职责内任务 | 照常自主执行，成果落盘 ops/（日志留痕） |
| 🟡 需协同/拍板 | 暂停等雷总指令，不自行跨副脑重大协同 |
| 🔴 生产/密钥/支付/支出 | **一律暂停**，等雷总（雷总在 = 人肉指挥） |
| 卡点/异常 | 直接私信雷总，带前缀 **「⚠️主脑失联降级」** |
| 定期汇报 | 每 6 小时合并一条私信雷总：失联状态 + 已完成事项 + 待决策项（不刷屏） |

### 汇报渠道

| 事项 | 渠道 | 说明 |
|------|------|------|
| 每 6h 常规汇总 | **发指挥部群 + @雷总** | 群=临时指挥台，前缀「⚠️主脑失联降级」 |
| P0 紧急 / 敏感（密钥、支付异常） | **私信雷总** | 群消息会被淹没，紧急必须直达 |
| 卡点 / 异常 | **私信雷总** | 即时性优先 |

### 夜间豁免
- 默认 23:30-08:30 不打扰雷总（P0 除外）
- **主脑失联 >2h = P0 级事故** → 允许夜间汇报，仍按「每 6 小时合并一条」执行

## 四、盯梢冗余（不依赖主脑，防单点）

### 04（新加坡）承担「巡检冗余员」
- 04 本机挂 cron **每日 06:30**：SSH 检查 01/02/03 是否有夜间新产出（时间戳昨夜 23:30 之后）
- 发现缺失 → SSH 驱动对应副脑补做 → 汇总《隔夜巡检报告》私信雷总（主脑失联时）或发群（主脑在线时）
- 前置条件：04 公钥安装到 01/02/03

### 飞书群晨间打卡（全体）
- 各副脑每天 08:30 前在指挥部群发《夜间产出摘要》（≤5 行）
- 连续 2 天缺席 = 异常，雷总/主脑/04 巡检可见

---

## 五、主脑停机/开机公告协议

### 停机前
- 主脑发群公告：`🛑主脑停机公告：X 时起停机。副脑进入降级模式：上报直发雷总（前缀⚠️主脑失联降级），🔴任务暂停等雷总`

### 开机后
- 主脑发群公告：`✅主脑恢复，失联期结束。副脑补发失联期摘要`
- 主脑补跑一次隔夜巡检，核对失联期间产出
- 主脑把失联期副脑直报内容整理进晨报/战报

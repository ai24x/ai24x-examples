## 副脑03（国内生产）更新指南：a1（AI 行情官 V1.0 / `p/a1`）

目标：把“数据库字段升级 + 程序发布 + 公网验收 + 回滚”固化成**固定顺序**，做到可追溯、可回滚、可重复。

适用范围（唯一口径）：
- 代码目录：`C:\ai24x01`
- a1 前端（静态）：`p/a1/web`（生产建议由 Nginx 直接托管静态文件）
- a1 后端/API/管理：`p/a1/api/server`（生产：`127.0.0.1:8001`，PM2：`a-api-8001`）
- core 后端/API：`api/`（生产：`127.0.0.1:8002`，PM2：`core-api-8002`）
- 生产对外：仅 `80/443`，由 Nginx 同域反代到 `8001/8002`（端口口径见 `docs/PORTS.md`）

---

### 一、你最关心的两件事（结论）

- **数据库新增字段怎么“丝滑升级”？**
  - 生产必须走 **Expand → Deploy →（可选 Backfill）→ Switch** 的思路：先加字段/表（向前兼容），再发兼容代码，再通过配置开关启用。
  - 禁止“一步到位改表 + 立刻切代码 + 线上写入”：容易出现不可回滚的瞬断。

- **最新配置怎么更新？**
  - 运行时配置（如 `admin_config`）**不应随代码发布自动覆盖生产**。
  - 正确方式：上线后由管理后台保存（或用“配置 upsert 脚本”仅补齐缺省项）。

### 二、发布前强制备份（PG + 配置）

#### 2.1 PG 备份（强制）

> 生产发布前必须 `pg_dump` 成功，并把备份路径回传到发布记录。

PowerShell（副脑03）：

```powershell
$ROOT="C:\ai24x01"
Set-Location $ROOT

$ts = Get-Date -Format "yyyyMMdd-HHmmss"
$outDir = "C:\AI24X\bak\subbrain03-$ts\pg"
New-Item -ItemType Directory -Force -Path $outDir | Out-Null

# 从 a1 .env 读取 DSN，避免手抄
$envFile = "$ROOT\p\a1\api\server\.env"
$dsnLine = (Get-Content $envFile | Where-Object { $_ -like "AI24X_DATABASE_URL=*" } | Select-Object -First 1)
$dsn = ($dsnLine -split "=",2)[1].Trim()

& "C:\Program Files\PostgreSQL\15\bin\pg_dump.exe" -Fc -Z 6 `
  -f "$outDir\a1-prod-$ts.dump" `
  $dsn

Write-Host "OK: pg_dump => $outDir\a1-prod-$ts.dump"
```

### 三、数据库字段/表升级（Schema）——标准做法

> **重要**：新增字段=必须执行 SQL（迁移）。“覆盖程序文件”不会自动升级 PG 表结构。

#### 3.0 以后更新只分两类（生产强制口径）

- **类型 A：仅更新程序代码（无 Schema 变更）**
  - 动作：`pg_dump`（建议但非强制） → `git checkout <prod tag>` → `pm2 restart a-api-8001/core-api-8002` → 门禁 200
- **类型 B：新增字段/表/索引（只做 Expand）**
  - 动作：**先 `pg_dump`（强制）** → 执行迁移（只加不删） → `git checkout <prod tag>` → 重启 → 门禁 200
  - 说明：上线阶段不做 `DROP`（删除/收缩属于高风险动作，后置甚至不做）

#### 3.1 推荐方式：迁移脚本化

- 将迁移 SQL 放到：`db/migrations/`
- 迁移遵循“只扩展（Expand）”原则：
  - ✅ `CREATE TABLE IF NOT EXISTS ...`
  - ✅ `ALTER TABLE ... ADD COLUMN ...`（建议可空或有默认值）
  - ✅ `CREATE INDEX IF NOT EXISTS ...`
  - ❌ 不在高峰期做重写大表的变更
  - ❌ 不直接 `DROP COLUMN` / 改字段含义（要分阶段）

#### 3.2 迁移执行（副脑03）

当仓库已提供迁移脚本与执行工具后（建议由主脑提供一键脚本），发布顺序固定为：

1) `pg_dump` 成功  
2) 执行迁移 SQL  
3) 发布代码（git checkout prod tag）  
4) PM2 重启  
5) 门禁验收（见 §五）

### 七、OpenClaw 一键发布（副脑03保存专用）

用途：把“备份 → 切 prod tag → 迁移（有则执行，无则跳过） → 重启 → 门禁”固化为一次执行，减少手滑与口径漂移。

> 说明：
> - **无 DB 字段变更也能用**：迁移脚本会自动判断 `db/migrations/*.sql`，没有则提示并跳过。
> - 本脚本默认**每次都 pg_dump**（更稳，代价是多几分钟和多占一点磁盘）。
> - 你只需要修改 `$TAG_NAME`。

```powershell
$ErrorActionPreference="Stop"

# ===== 0) 固定目录 + 仓库硬校验 =====
$ROOT="C:\ai24x01"
if(!(Test-Path $ROOT)){ throw "ROOT not found: $ROOT" }
Set-Location $ROOT
git rev-parse --is-inside-work-tree | Out-Null
"OK: cwd=$((Get-Location).Path)"

# ===== 1) 固定 PM2_HOME（避免 list 为空/跑到另一实例）=====
$env:PM2_HOME = "$env:USERPROFILE\.pm2"
"OK: PM2_HOME=$env:PM2_HOME"
pm2 ping

# ===== 2) 发布前 PG 备份（强制）=====
$ts = Get-Date -Format "yyyyMMdd-HHmmss"
$outDir = "C:\AI24X\bak\subbrain03-$ts\pg"
New-Item -ItemType Directory -Force -Path $outDir | Out-Null

$envFile = Join-Path $ROOT "p\a1\api\server\.env"
if(!(Test-Path $envFile)){ throw "Env not found: $envFile" }
$dsnLine = (Get-Content $envFile | Where-Object { $_ -like "AI24X_DATABASE_URL=*" } | Select-Object -First 1)
if([string]::IsNullOrWhiteSpace($dsnLine)){ throw "AI24X_DATABASE_URL missing in $envFile" }
$dsn = ($dsnLine -split "=",2)[1].Trim()

$outFile = Join-Path $outDir ("a1-prod-$ts.dump")
& "C:\Program Files\PostgreSQL\15\bin\pg_dump.exe" -Fc -Z 6 -f $outFile $dsn
"OK: pg_dump => $outFile"

# ===== 3) 切换版本（只改这里的 tag 名称）=====
$TAG_NAME="prod-20260501-2"
git fetch --tags --prune
git checkout $TAG_NAME
"OK: git HEAD=" + (git rev-parse --short HEAD)

# ===== 4) 数据库迁移（幂等，可重复）=====
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\ai24x01\scripts\apply_pg_migrations.ps1" -Root "C:\ai24x01"

# ===== 5) 重启服务（生产口径：8001/8002）=====
pm2 restart a-api-8001
pm2 restart core-api-8002
pm2 save --force
pm2 list

# ===== 6) 门禁（必须全 200）=====
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8001/health").StatusCode
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8002/health").StatusCode
```

执行后必须回传 3 个证据：
- `OK: pg_dump => ...`
- `OK: git HEAD=...`
- `pm2 list` + 两个 health 状态码

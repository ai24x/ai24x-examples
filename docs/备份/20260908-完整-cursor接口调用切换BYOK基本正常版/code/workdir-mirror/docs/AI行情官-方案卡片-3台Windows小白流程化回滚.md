# AI 行情官｜灯塔版（1.01）方案卡片：3 台 Windows Server + 小白 + 需要流程化回滚

适用：副脑01（预演）/副脑03（国内生产）/副脑04（国际生产）均为 Windows Server；团队成员偏新人；目标是“少步骤、少手动、可回滚”。

---

## 1) 最推荐的执行方式（减少手滑）

- **主脑（你本地）负责**：改代码、跑通本地、打 tag、决定是否进入生产
- **副脑负责执行**：严格按 SOP 执行（备份 → 拉代码 → 迁移 → 重启 → 健康检查）
- **执行工具优先级**：
  1) OpenClaw 执行“标准任务包”（推荐，流程化、可审计）
  2) 远程桌面手工执行（不推荐长期使用）

---

## 2) 三环境最小“固定项”（防混淆）

- 三台机器目录统一：`C:\ai24x01`（或你们文档约定的统一路径）
- 三环境数据库不同名（不混）：`ai24x_a_pre` / `ai24x_a_cn` / `ai24x_a_intl`
- 三环境 `.env` 不入库，本机保存；密钥各自独立

---

## 3) 标准任务包输入/输出（给 OpenClaw）

输入（你给任务包的参数）：

- 环境：`pre` / `cn` / `intl`
- 目标版本：`rc-...`（预演）或 `prod-...`（生产）
- 是否包含 DB 变更：`yes/no`

输出（任务包必须回传）：

- 当前 commit/tag
- 备份文件路径（生产必有）
- `/health`、`/docs` 返回码
- 失败时：已执行的回滚动作与结果

---

## 4) 回滚策略（必须写进任务包）

- 优先回滚代码（最快）
- 不做破坏性迁移（能避免 DB 回滚）
- PG 异常可临时切回 SQLite 止血（重启恢复服务）

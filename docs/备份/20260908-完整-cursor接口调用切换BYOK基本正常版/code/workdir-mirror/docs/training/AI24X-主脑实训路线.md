# AI24X・主脑实训路线（边做项目边练）

**给谁用**：主脑本人——边开发 AI24X，边练 **AI 编程** 与 **智能体指挥**。  
**怎么用**：每天选一个小任务，做完打勾；底部 **复盘** 写三五行即可。  
**和规划的关系**：与 [AI24X-Token自由规划-1.0.md](../AI24X-Token自由规划-1.0.md) **§11（L1～L5）**、**§13 每日任务模板** 一致，这里是 **按周可执行的清单版**。  
**目录说明**：本文件位于 `docs/training/`；同目录索引见 [README.md](./README.md)。

---

## 一、每天固定节奏（10 分钟复盘就够）

1. **开始前**（复制下面「任务包」填空）  
2. **做事**：跑命令、改代码、看报错（把报错原文复制下来）  
3. **结束后**：勾选验收标准 + 写 **今日复盘三问**  

### 任务包模板（复制即用）

```text
今日目标：
验收标准（打勾用）：
1.
2.
3.
约束（例如：今天只改 api/，不动 web/）：
```

### 今日复盘三问（复制即用）

```text
1. 今天搞懂了哪一条调用链或哪一个命令？
2. 哪个错误下次可以更早发现？（缺依赖/端口/环境变量？）
3. 明天最小一步做什么？
```

## 二、阶段 0：环境跑通（L1 · 约 1 天）

| 序号 | 任务 | 验收（自己打勾） |
|------|------|------------------|
| 0.1 | 按仓库根目录 `README.md` 启动 API（或双击 `start_local.bat`） | [ ] 能打开 `http://localhost:8000/docs` 或 `/health` 正常 |
| 0.2 | 用终端请求一次 `/health`（PowerShell：`curl http://localhost:8000/health`） | [ ] 终端里看到 JSON，`status` 为 healthy |
| 0.3 | 打开 `api/main.py`，找到 `/v1/chat/run` 和健康检查 | [ ] 能说出请求大概从哪个函数进 |

**卡住时**：把 **完整报错 + 你执行的命令** 发给 AI 助手，不要只说「不行」。

---

## 三、阶段 1：读懂一条链 + 做小改动（L1→L2 · 约 2～3 天）

| 序号 | 任务 | 验收 |
|------|------|------|
| 1.1 | 用纸或本文档空白处写：`/v1/chat/run` 从路由到 service 的路径（文件名即可） | [ ] 写出至少 3 个文件/函数名 |
| 1.2 | 在 Swagger 或用 curl 发一次 chat（成功或 401 都行） | [ ] 能对照 `api/schemas.py` 说出 body 里关键字段 |
| 1.3 | **极小改动**：例如给响应加一个响应头 `X-AI24X-Trace`（或改进一行日志） | [ ] `git diff` 看得懂；改完 `/health` 仍正常 |
| 1.4 | `git commit` 一次，说明「改了什么、为什么」 | [ ] 仓库里有一条清晰提交 |

## 四、阶段 2 预告（完成阶段 1 再开）

- 计费/数据库字段与 `services` 对齐，加 **小测试或脚本**  
- `web/js/api.js` 与后端 **一个小联调**  
- 写第一份给 **OpenClaw / 副脑** 的「标准任务包」（目标 / 输出 / 完成定义）

（具体任务可写在同目录新建 `阶段2-任务清单.md`。）

---

## 五、本会话里已对齐的要点（备忘，非任务）

- **VIP**：统一 `POST /v1/chat/run`，靠 Key/策略分流，不把免费与付费拆成两个主 URL。  
- **战略**：底层质量与交付要硬；增长抓 **有真实调用需求** 的用户（见规划 **§17.7**）。  
- **实训原则**：你动手跑、你合并；AI 负责拆步、纠偏、验收标准。

# AI24X 超级智能体组织架构 V2.0 · 可复制可扩张方案

> 定稿：2026-08-13 ｜ 雷总拍板方向 ｜ 设计：技术安全官（Codex） ｜ 统筹：总司令（主脑）
> 目标：像超级大企业一样，发挥每个成员专长优势，全力协同把现有三项目做好，并支持未来无限复制扩充。

## 一、设计理念：三层模型 + 双线矩阵

```
┌─────────────────────────────────────────────────────┐
│  决策层（董事会）＝ 雷总：拍板 / 审批 / 资源 / 方向      │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────┴──────────────────────────────┐
│  指挥层（CEO+参谋部）＝ 总司令（主脑）：                │
│  指挥调度 · 全局监控 · 统一记忆 · 飞书单一出口 · 审批把关  │
└──────────────────────┬──────────────────────────────┘
          ┌────────────┼────────────┬──────────────┐
   事业部（项目线）      职能中台（专长池）       未来可无限扩张
 ┌─ 平台事业部/平台官     ┌─ 技术安全官（Codex）    → 新项目＝新增事业部
 ├─ 行情事业部/行情官     ├─ 生产运维官（03/04）     → 新成员＝按专长入池
 └─ 游戏事业部/游戏官     ├─ 构建测试官（01）        → 新规则＝更新模块
                         └─ 运营获客官（02·AI24X运营）        → 全部模板化复用
```

- **纵向＝事业部**：每个项目一个「项目官」（Codex 会话兼任），对交付结果负责
- **横向＝职能中台**：每个专长一个「职能官」，对专业执行负责
- **指挥层＝总司令**：统一调度资源、把关审批、汇总记忆
- **决策层＝雷总**：只做必须人来定的事（钱/资质/方向/大客户）

## 一·补充、双司令模式（2026-08-13 雷总定，最高效最短路径）

| 场景 | 总司令 | 职责 |
|---|---|---|
| 雷总在电脑前 | **本机 Codex（司令）** | 直接对话、直接执行、直接拍板协同，最短路径 |
| 雷总不在电脑前 | **主脑 openclaw（飞书「指挥官」）** | 7×24 监管、远程沟通协调、传达指令、汇总汇报 |

- 切换依据：雷总是否在电脑前（本地会话存在即司令主责；主脑始终后台值守，随时接棒）
- 同步机制：司令↔主脑 经 `docs\营销\收发\` + 桥接 cron 双向同步，状态不断层
- 角色定位不变：决策层=雷总，指挥层=在场总司令，职能中台/事业部=各官

## 五、可复制可扩充机制（重点）

| 要扩充什么 | 怎么扩 | 步骤 |
|---|---|---|
| **新项目** | 新增事业部 | ①复制 AGENTS.md 模板 → ②建 `收发\<新项目>\` → ③挂桥接 cron → ④总司令登记记忆 → ⑤上线 |
| **新成员** | 按专长入池 | ①填《成员档案卡》（专长/IP/权限/飞书oid）→ ②定主责+兼职 → ③入调度表 → ④能力验证 |
| **新规则** | 模块化更新 | ①归入对应领域规范（安全/运维/运营/调度）→ ②模板同步 → ③通知全员 |
| **新模型/工具** | 资源升级 | ①技术安全官接入评估 → ②路由配置 → ③实测审计 → ④上线 |

**关键：** 一切模板化、目录化、规则模块化——新增项目/成员不改变架构，只做"复制+填表"。

# A1（AI行情官）短信接口独立化方案

> 主脑排查 · 2026-08-04 · 分享给副脑03执行

## 一、现状（代码实测）

**A1 短信 = 代理主站模式（identity_proxy），不独立。**

调用链：
```
A1 /api/auth/sms/send (proxy_sms_send)
  → 转发主站 POST /v1/auth/sms/send（Header: X-SMS-Internal-Key）
  → 主站调 106 网关（sms.106jiekou.com/utf8/sms.aspx）发短信
  → 返回状态码 100=成功
```

关键代码：
- `p\a1\api\server\app\main.py:1705` `proxy_sms_send()` —— 转发主站
- `p\a1\api\server\app\config.py:179` `AI24X_IDENTITY_API_BASE`（主站地址）
- `p\a1\api\server\app\config.py:180` `AI24X_SMS_INTERNAL_KEY`（与主站对齐）
- A1 管理端 sms_106_* 覆盖项 → `_sms_forward_json()` 随转发提交主站（仍是主站发）

**根因（03 不能发短信）：** 主站04 改邮箱注册、关手机短信 → 主站短信通道失效/密钥不匹配 → A1 代理转发失败。

## 三、推荐方案 A：A1 本地直发 106

### 原理
A1 绕过主站，自己直接调 106 网关（与主站 sms_106_client.py 相同协议）。
106 网关是 HTTP GET 提交（account/password/mobile/content/signName 走 query），**不需要主站参与**。

### 代码改动（交科设）

**1. `p\a1\api\server\app\config.py`** — 增加本地 106 直发配置项：
```python
# 短信通道：identity_proxy（默认，转发主站）| local_106（本地直发）
sms_active_provider: str = os.getenv("AI24X_SMS_ACTIVE_PROVIDER", "identity_proxy")
# 本地直发 106 网关配置（sms_active_provider=local_106 时生效）
sms_106_endpoint: str = os.getenv("AI24X_SMS_106_ENDPOINT", "")
sms_106_account: str = os.getenv("AI24X_SMS_106_ACCOUNT", "")
sms_106_password: str = os.getenv("AI24X_SMS_106_PASSWORD", "")
sms_106_sign_name: str = os.getenv("AI24X_SMS_106_SIGN_NAME", "")
sms_106_template: str = os.getenv("AI24X_SMS_106_TEMPLATE", "")
```

**2. `p\a1\api\server\app\main.py`** — `proxy_sms_send()` 增加本地直发分支：
```python
@app.post("/api/auth/sms/send")
def proxy_sms_send(body, request):
    cfg = resolve_identity()
    prov = (cfg.sms_active_provider or "identity_proxy").strip().lower()

    if prov == "local_106":
        # 本地直发：不转发主站
        code = admin_otp_generate()  # 或按用途生成
        content = (cfg.sms_106_template or "您的验证码是{code}，{ttl}分钟内有效，请勿泄露。").replace("{code}", code)
        ok, raw, msg = send_sms_106_local(
            endpoint=cfg.sms_106_endpoint,
            account=cfg.sms_106_account,
            password=cfg.sms_106_password,
            mobile=body.mobile,
            content=content,
            sign_name=cfg.sms_106_sign_name,
        )
        if not ok:
            raise HTTPException(status_code=502, detail=f"短信发送失败：{msg}")
        admin_otp_put(body.mobile, code, ttl_s)
        return {"ok": True, "message": "验证码已发送"}

    # 原 identity_proxy 逻辑不变（转发主站）
    ...
```

**3. 新增 `send_sms_106_local()`**（可参考主站 `api/sms_106_client.py` 的 `send_sms_106` 复制实现）：
```python
async def send_sms_106_local(*, endpoint, account, password, mobile, content, sign_name=None, timeout_s=15.0):
    import httpx
    params = {"account": account, "password": password, "mobile": mobile, "content": content}
    if sign_name:
        params["signName"] = sign_name
    async with httpx.AsyncClient(timeout=timeout_s) as client:
        r = await client.get(endpoint, params=params)
    raw = (r.text or "").strip()
    ok = raw == "100"
    return ok, raw, {"100": "发送成功"}.get(raw, f"未知状态码: {raw}")
```

### 配置（03 执行）

在 A1 的 `.env`（`C:\ai24x01\p\a1\api\server\.env` 或生产实际路径）增加：
```env
AI24X_SMS_ACTIVE_PROVIDER=local_106
AI24X_SMS_106_ENDPOINT=<106网关地址，如 http://sms.106jiekou.com/utf8/sms.aspx>
AI24X_SMS_106_ACCOUNT=<106账号>
AI24X_SMS_106_PASSWORD=<106密码>
AI24X_SMS_106_SIGN_NAME=<签名，可空>
AI24X_SMS_106_TEMPLATE=您的验证码是{code}，5分钟内有效，请勿泄露。
```
- 106 账号可复用主站04现有账号（同一网关），或另开独立账号（更彻底）
- 模板必须含 `{code}` 占位符
- `AI24X_SMS_INTERNAL_KEY` 不再依赖主站（本地直发用不到，可保留不动）

### 验证（03 执行）
1. 重启 A1 服务（03 是 Nginx 直管，重启 a1-api）
2. 管理后台 → 短信诊断 `/api/admin/sms_diagnostics` → 应显示 `sms_active_provider=local_106`
3. 发一条真实测试短信到手机 → 收到即成功
4. 断网主站（或主站短信关闭）状态下重测 → 仍能收到 = 完全独立 ✅

## 四、备选方案 B：腾讯云短信

A1 代码已预留 tencent 通道（config.py 有 sms_tencent_secret_id/key/sdk_app_id/sign/template_id/region），但 `main.py:1691` 标注"当前为腾讯短信预留通道，未请求主站 106 诊断"——**发送逻辑未实现**，需科设补全（调腾讯云 Sms 发送接口，返回 100 类成功码）。

配置项：
```env
AI24X_SMS_ACTIVE_PROVIDER=tencent
AI24X_SMS_TENCENT_SECRET_ID=...
AI24X_SMS_TENCENT_SECRET_KEY=...
AI24X_SMS_TENCENT_SDK_APP_ID=...
AI24X_SMS_TENCENT_SIGN=...
AI24X_SMS_TENCENT_TEMPLATE_ID=...
AI24X_SMS_TENCENT_REGION=ap-guangzhou
```
适用：已有腾讯云短信账号；否则用方案A（106 网关，主站已有账号）。

## 五、注意事项
1. **代码改动交科设**：方案 A 改动点已在第三节列出，改动小、隔离（只影响 proxy_sms_send 分支）
2. **106 账号余额**：直发走 106 网关，确认账号有余额（状态码 106=余额不足）
3. **模板审核**：106 模板需含 {code}，签名按网关要求
4. **不改主站**：本方案 04 侧零改动，主站保持邮箱注册不受影响
5. 若选方案C（管理端覆盖）仅是过渡，不解决独立性，不推荐

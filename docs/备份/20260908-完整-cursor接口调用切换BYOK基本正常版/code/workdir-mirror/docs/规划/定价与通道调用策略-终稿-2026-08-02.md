## 0. 执行摘要

| 判断 | 结论 |
|------|------|
| 现网会不会「无限亏钱」？ | **按量付费路径目前远高于成本**（Builder 锚 ≈$40/M flash），亏钱主风险不在 flash，而在 **降价时 VIP mult 未同步**、**Pro 日赠滥用贵模**、**免费池失控** |

> **关键**：系统**不会**按实时上游价扣用户款；只扣「钱包 token × mult」。售价必须覆盖「你实际会打到的那条上游」的成本。

### 1.2 用户扣费公式（必须记住）

```
钱包扣减 = max(1, 上游返回 total_tokens × M)
```

| 路径 | M |
|------|---|
| flash / L1 / L0 / QI | `LAYER_COST_MULT` → **1** |
| pro / L2 | **5**（现网） |
| ultra / L3 | **8**（现网） |
| VIP 点名 | 目录 `billing_mult`（1～22） |
| 免费共享 | **不扣钱包**（仅日帽计数） |

套餐隐含售价锚（现网）：

| 套餐 | 价 / 额度 | 钱包 $/M |
|------|-----------|----------|
| Starter | $1 / 1 万 | **$100**（限购体验） |
| Builder / Scale 预充 | $20/50 万、$100/250 万 | **$40** ← VIP 页估价用这个 |
| Pro Pass（已下架） | $15 + 日赠 10 万×30≈300 万 | 吃满日赠 ≈ **$5/M**（仅 flash） | 2026-08-03 起前台下架，仅后台「老用户补资格」 |

### 1.3 成本地板（防两套价打穿）

对每个对外可调模型定义：

```
C_floor = max(各「启用且可能路由到」的上游 blended $/M) × 1.15
         （1.15 = 支付费+失败重试+运维缓冲）
S_min   = C_floor / (1 − 目标毛利率)     # 建议毛利率 40% → /0.6
```

**blended** 暂用 `(cost_in + cost_out) / 2`（与仓库一致）；上线后用近 30 天账单修正。

| 代表模型 | 目录成本 blended | 若只走硅基更低价 | **定价用 C_floor（取高）** |
|----------|------------------|------------------|----------------------------|
| DS Flash | ~$0.21 | 直连≈同 | **$0.24**（×1.15） |
| DS Pro | ~$0.65 | 直连≈同 | **$0.75** |
| Kimi K3 | OR ~$9.0 | 硅基可明显更低 | **先按 OR $9×1.15≈$10.4**，硅基切主后再下调 |
| MiniMax M3 | ~$0.75 | 接近 | **$0.86** |
| GPT-5 级 | ~$5.6 | 厂直/OR | **$6.5** |
| Claude Opus 级 | ~$15 | 厂直/OR | **$17.3** |

**降价铁律**：若把 flash 售价锚从 $40 降到 $S_flash，则

```
billing_mult_min = ceil( C_floor / S_flash × 1.01 )
```

例：`S_flash=$0.50`，Kimi `C_floor≈$10.4` → **mult ≥ 21**（现网 ×12 **会亏**）。  
**只降套餐额度、不同步抬 VIP mult = 自杀。**

## 2. 优化后的定价策略（对外）

### 2.1 双轨定位

| 轨 | 给谁 | 打法 |
|----|------|------|
| **A 量产** | 投流 / 开发者日常 | `flash`/`pro`/`auto` · **可比 $/M** · 中国强模 |
| **B 会员** | 要指定名模 | VIP 点名 · **不承诺全球最低价** · 覆盖 C_floor |

话术：国际投流主打「China LLMs · one key · flash 单价能打」；**禁止**再暗示「全模型比 OR 便宜」。

### 2.2 目标售价带（用户真实 token）

| 档位 | 目标售价 S | 相对 C_floor | 说明 |
|------|------------|--------------|------|
| **flash** | **$0.45 / M** | ≈ 成本 1.9× | 投流主锚（建议值；可在 0.40～0.50 微调） |
| **pro** | **$1.40 / M** | ≈ 成本 1.9× | |
| **ultra** | **$2.50 / M** | 视 L3 实际上游 | 若 L3 仍是 DS Pro 族可并入 pro |

| 国际 VIP 点名 | ≥ `S_min` 且 ≥ 官方×1.8 | 不拼补贴站 | |

支付费率按 **4%** 预留进 1.15 缓冲，不再另扣一层（避免叠床架屋）。

### 2.3 套餐数值（Phase 1 · 钱包 token 仍 = flash 当量）

设 **S_flash = $0.45 / M** → `$1 = 约 222 万` 钱包 token。

| 套餐 | 售价 | 建议 `credit_tokens` | 隐含 $/M | 角色 |
|------|------|----------------------|----------|------|
| **Starter** | **$2** | **300,000**（限购 1） | ≈$6.7（略贵可接受） | 钩子够跑通；告别 $1/1 万=$100/M |
| **Builder** | **$20** | **40,000,000** | **$0.50** | 主充值（略高于锚，促升级） |
| **Pro Pass** | **$15** | 0 预充 | 见日赠 | VIP + 点名权 |
| **Scale** | **$99** | **180,000,000** + VIP30 | ≈$0.55 | 量大优惠约 10% |

### 2.4 Pro Pass 日赠（防亏重点）

现网：日赠 **10 万/天** ×30 ≈ 300 万 flash 当量；在 $0.45/M 下「礼物价值」≈ **$1.35** 成本级，**远低于 $15**，flash 路径仍赚。

风险在于：用户用日赠额度打 **高 mult 名模**（扣的是钱包当量，但上游按真模计费）。

**规则（必做其一）**：

1. **推荐**：日赠 lot **仅允许** `flash/auto/shared`（pro/VIP 点名只能花预充包）；或  
2. 日赠降为 **3 万/天**，且 VIP 点名 mult 已按地板上调；或  
3. 日赠保持 10 万，但点名额外收「点名日费」（产品复杂，暂缓）

**本终稿默认选 1**（实现成本中等，毛利最稳）。

## 3. 系统程序 · 通道调用策略

### 3.1 总原则

```
付费请求：成本可控上游优先 → 稳定官方兜底 → 聚合兜底
免费请求：仅廉价/赠送池 → 严日帽 → 永不打付费旗舰 Key
用户可见：永远是 flash/pro/ultra/auto/vip-* ，不露厂商
售价保护：任何可路由上游的 C_floor 必须 ≤ 用户有效售价 × 0.6
```

### 3.2 付费通道（有余额 / VIP）

#### A. 品牌档 `flash` / `auto`

| 顺序 | 上游 | 条件 |
|------|------|------|
| 1 | **DeepSeek 直连** Flash | `DEEPSEEK_API_KEY` 可用（稳、价清） |
| 2 | **OpenRouter** `deepseek/deepseek-v4-flash` | 直连失败或未配 |
| 3 | **硅基** 等价 Flash/小模 | 仅作三级；避免 silently 换模质变 |

> 现网 OR 模式常「先 OR 再 DS failover」。**建议改为：付费 flash 默认直连优先**（`TOKEN_LLM_UPSTREAM=direct` 或改链式顺序），OR 作 failover——账单更干净，少「两套价」幻觉。

#### B. 品牌档 `pro` / `ultra`

| 顺序 | 上游 |
|------|------|
| 1 | DeepSeek 直连 Pro |
| 2 | OR deepseek-v4-pro |
| 3 | （ultra）若配置更高配中国模则走专用 id，否则同 pro |

`LAYER_COST_MULT` 用 §2.5 新值。

#### C. VIP 中国名模点名

| 顺序 | 上游 |
|------|------|
| 1 | **硅基流动**（有模型映射时）← 降本主力 |
| 2 | OpenRouter 同模 |
| 3 | 降级到 `vip-ds-pro` / flash（**须在产品上提示或接受「保活降级」**；扣费仍按点名 mult → 毛利增、体验风险） |

#### D. VIP 国际旗舰点名

| 顺序 | 上游 |
|------|------|
| 1 | 厂直连（若 Key 启用） |
| 2 | OpenRouter |
| 3 | **禁止**硅基「同名冒充」 |
| 4 | 失败则报错，不静默换成 flash（国际旗舰） |

**TokenLab**：ToS 通过后插入为「与 OR 并列的国际备用」，灰度 <10% 流量。  
**LAYSO**：仅运维手工试单，**不进自动路由**。

### 3.3 免费通道（余额不足或用户选 shared）

| 项 | 策略 |
|----|------|
| 入口 | `model=shared` / `auto` 且走共享池；或余额=0 引导 |
| 池成员 | **主：`silicon-qwen`（SILICONFLOW_API_KEY_FREE 优先）**；备：`or-auto`（OR free key） |
| 调度 | `failover`（默认）；有两条 free key 才 `rotate` |
| 日帽 | **每用户 30 次 / 3 万 token**（现网）；投流期可收紧到 15 次 / 1.5 万 |
| 禁止 | 免费池调用 VIP 点名、GPT/Claude、付费 OR 主 Key |
| 升级 | 有余额时 CTA 引导 Builder；`upgrade_first=true` 保持 |

### 3.4 模式开关（运维）

| 变量/旗标 | 建议生产值 |
|-----------|------------|
| 付费主路径 | DeepSeek 直连优先（flash/pro） |
| `TOKEN_LLM_L0_USE_SILICON` | `1`（共享/L0） |
| `TOKEN_LLM_DS_FAILOVER` | 开（OR 为主时） |
| OR 主 Key | 保留作 VIP 国际 + failover |
| OR/硅基 **Free Key** | 仅绑免费池，与付费 Key 隔离 |
| Mock 支付 | 生产关 |

### 3.5 程序护栏（建议立项，Phase 1.5）

1. **成本地板校验**：管理台保存 `billing_mult` / 套餐额度时，若 `S_flash×mult < C_floor` → 拒绝保存  
2. **上游账单周报**：04 导出 OR/硅基/DS 上周 $/M，与目录 `cost_*` 对比，偏差 >20% 告警  
3. **VIP 日赠用途限制**（§2.4 选项 1）  
4. 路由日志带 `provider + upstream_model + bill_mult`（已有部分，补全便于核算）

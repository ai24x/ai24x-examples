## 三、什么时候升级最合适

### 3.1 原则

1. **按触发升，不按日历盲升**  
2. **两项拆开**：谁先顶谁先升（通常流量→EdgeOne，内存/放量保险→VPS）  
3. **升配钱 < 已验证获客钱**：先有「注册→试用→付费」信号，再为放量买保险  
4. **磁盘已缓解**：43G 余量 → **不为盘提前升 VPS**

### 3.2 推荐时间窗（经营节奏）

| 阶段 | 业务状态 | 基础设施 | 年费约 |
|------|----------|----------|--------|
| **现在 · Phase 1** | 1.0 上线、SEO/社区冷启动、小额真付验证 | **维持**；清 2G 旧备份；周监控 | **≈ ¥7k** |
| **窗口 A** | EdgeOne 月流量 **>35–40G**，或投流预估打穿 50G | **只升 EdgeOne 基础版** | ≈ ¥11.4k |
| **窗口 B** | 内存持续 **>70%**，或 Show HN / 付费投流 **前 1 周** | **只升 VPS ¥470（16G）** | ≈ ¥11k |
| **窗口 C · 最合适双升** | 同时接近：① 投流/大规模获客 ② 付费客户进入「可覆盖成本」区（见下） | **VPS B + EdgeOne 基础版** | **≈ ¥15.4k** |

### 3.3 「最合适双升」的经营门槛（建议）

双升年增约 **¥8,470**（≈ **¥700/月**）。建议满足下面 **至少 2 条** 再双升：

| # | 门槛（满足越多越合适） |
|---|------------------------|
| 1 | 近 30 天 **有稳定付费**（Markets Pro / Token / BYOK 任一），不是零星 1 单 |
| 2 | 国际侧 **月经常性收入（MRR）≳ ¥2,000–3,000**（约 10–15 个 Markets 月费 Pro，或等价 Token 毛利） |
| 3 | 已排期 **付费投流 ≥$300** 或等价 SEO/HN 放量，且门禁（支付/落地页）已齐 |
| 4 | 监控已黄灯：流量>35G **或** 内存>70% |

**反例（现在不适合双升）**：付费还在个位数、流量/内存都绿、只是「心里觉得该升」→ 先维持 ¥7k 舰队。

### 3.4 客户量粗对照（辅助，不如监控准）

| 形态 | 现配置大致可撑 | 建议进入升配窗口 |
|------|----------------|------------------|
| 偏 Markets Pro | 活跃 Pro <80 | ≈100 活跃 / 月活 150–200 |
| 偏 Token 重度 | 中重度 <30–40 | ≈50 或同时流式十几～三十路 |
| 混业 | Pro 50–80 + Token 20–30 | 达此或监控红灯 |

## 四、双升之后还不够：后期升级流程与方案（Phase 3+）

> **前提**：04 已是 **4核16G180G**，EdgeOne 已是 **基础版 500G**，监控仍红灯。  
> **红线**：禁止再在 04 上「无限升同机规格」；按下面 **先诊断 → 再治本 → 再拆机** 执行。

### 4.1 诊断：症状 → 走哪条路

| 主要症状 | 先看指标 | 优先方案 | 不要先做 |
|----------|----------|----------|----------|
| API 慢 / 超时 / 流式卡顿 | 04 CPU>60% 或 内存>80%；8002 连接多 | **L1 拆 Token 网关到副脑05** | 再升同机 CPU |
| 静态站偶发慢、流量账单高 | EdgeOne 用量、回源比>60% | **L0 缓存/防刷**；必要时 **L4 升标准版** | 盲目加 VPS |
| 支付/登录正常，仅聊天 API 炸 | 仅 `/v1/chat` 延迟高 | **L1 拆网关**（账户仍留 04） | 整站搬迁 |
| DB 慢、锁等待、磁盘 IO | PG CPU/连接数/盘 | **L2 库独立或托管** | 先加美西节点 |
| 美欧用户延迟差、SG 本身不忙 | 探针延迟、区域分布 | **L3 美西/欧边缘节点** | 国内 03 升配 |
| 国内 a1 高峰拖垮？ | 看是否误共用资源 | **L5 03 单独扩**（与国际无关） | 动 04 |

### 4.2 总流程（每次扩容都走同一套）

```
① 连续 3–7 天监控留证（内存/CPU/EdgeOne/慢请求）
        ↓
② 雷总拍板：走 L0 / L1 / L2 / L3 / L4（可组合，默认一次只动一层）
        ↓
③ 司令写方案卡：目标架构 + 预算 + 回滚 + 验收清单
        ↓
④ 新机/新套餐开通（雷总付费）→ 副脑部署 → 影子流量或灰度
        ↓
⑤ DNS/EdgeOne 回源切换（低峰）→ 公网验收 → 群回执
        ↓
⑥ 观察 72h → 旧路径下线或保留冷备 → 更新本规划修订记录
```

**门禁**：无 7 日监控证据、无回滚步骤、无双推指令 → **禁止上生产拆机**。

### 4.3 分层方案详表

#### L0 · 治本（先做，0～很少加钱）

| 项 | 动作 | 验收 |
|----|------|------|
| 限流 | API Key / IP / 用户级 QPS；免费档更严 | 滥用 QPS 下降，正常用户无感 |
| 配额 | Token 日额度、Markets AI 次数已有则收紧告警 | 账单异常尖峰消失 |
| 缓存 | EdgeOne 静态长 TTL；`?v=` 发版；HTML 刷新 SOP | 回源比 **<40%** |
| 防刷 | WAF / CC；管理页白名单 | 攻击流量不进源站 |
| 进程 | 禁在 04 跑重扫描/大备份；dump 外迁 | 盘与 CPU 平稳 |

**触发进入下一层**：L0 做完 1–2 周，内存仍>80% 或 API 错误率仍高 → **L1**。

#### L1 · 拆 Token 流式网关（首选扩容，新增「副脑05」）

**目标架构**：

```
EdgeOne
  ├─ www / markets 静态 / open 文档     → 回源 04（或继续边缘缓存）
  ├─ 账户 / 支付 / Webhook / console API → 回源 04（AI24X-core 轻量面）
  └─ api.ai24x.com /v1/* 流式与高 QPS  → 回源 05（新机 · Token Gateway）
04 SG：PostgreSQL 主库（初期仍可留 04）+ 支付中台
05 SG（或同区）：只跑网关进程，连 04 的 DB 或只读副本
```

| 步骤 | 谁 | 内容 |
|------|-----|------|
| 1 | 雷总 | 开 **副脑05**：建议同区新加坡，起步 **2核8G 或 4核8G**（年费另计，约 ¥1.6k–4k 级，以官网为准） |
| 2 | 司令 | 代码：网关进程可独立启动；`.env` 分库连接串；健康检查 `/health` |
| 3 | 04/05 | 05 部署代码 + NSSM；防火墙仅 EdgeOne 回源 + 04 内网/白名单 |
| 4 | 雷总/司令 | EdgeOne：`api.ai24x.com` 回源改 05；www 支付回调仍 04 |
| 5 | 04 | 灰度：先 10% 或仅新 Key；再全量 |
| 6 | 全员 | 验收：支付入账、流式对话、admin、markets 履约互不影响 |
| 7 | 04 | 观察 72h 后，04 可降负或维持；**不要立刻降配省钱**（留缓冲 1 个月） |

**回滚**：EdgeOne 回源切回 04 IP；05 关机保留镜像。

**预算感**：多一台小机，通常 **远小于** EdgeOne 标准版；优先于 L4。

#### L2 · 数据库独立

| 触发 | PG 连接打满、备份拖垮盘、慢查询主导延迟 |
|------|------------------------------------------|
| 方案 A | 同机升级盘/内存不够时：开 **DB 专用机** 或云厂商托管 PG |
| 方案 B | 04 留主库，05 网关走 **只读副本**（读多写少的报表/列表） |
| 流程 | 备份 → 迁库/建副本 → 改 `DATABASE_URL` → 双写或切换窗口 → 验收订单/余额一致性 |
| 回滚 | 连接串切回旧库；保留迁库前 dump |

#### L3 · 加地理节点（美西 / 欧）

| 触发 | 04/05 **不忙**，但美欧用户延迟差、大客户要就近 |
|------|--------------------------------------------------|
| 方案 | 美西小机跑 **只读网关** 或静态就近；源站库仍 SG；顺序：**先美西 → 再欧区合规**（见岗位规划） |
| 流程 | 开机器 → 部署只读配置 → EdgeOne 按区域回源或 DNS 权重 → 探针对比延迟 |
| 注意 | 支付 Webhook、写库 **仍回 SG 主**；避免多主写 |

#### L4 · EdgeOne 基础版 → 标准版

| 触发 | 月流量稳定 **>400–450GB**，且 L0 回源比已优化 |
|------|-----------------------------------------------|
| 动作 | 升标准版（约 **¥3,800/月**）；复核套餐流量与请求包 |
| 注意 | 这是 **CDN 账单问题**，解决不了 04 内存；勿用标准版替代 L1 |

#### L5 · 国内 03 单独扩

与国际双升/拆机 **解耦**。a1 高峰只动 03；禁止把国内重任务塞进 04/05。

### 4.4 推荐升级顺序（一张图）

```
双升后仍红灯
    │
    ├─► L0 治本（1–2 周）──── 够用则停
    │         │仍不够
    ▼         ▼
  以 API/内存为主 ──► L1 副脑05 拆网关 ──► 仍 DB 瓶颈 ──► L2
  以流量账单为主 ──► L0 后再 L4（标准版）
  以海外延迟为主 ──► L3 美西（库仍 SG）
  以国内行情为主 ──► L5 只动 03
```

### 4.5 验收与回执模板

```

⚠️ Phase3未完成｜原因：…｜已回滚/待人工：…
```

### 4.6 目标架构（中期完整版）

## 五、按此经营，盈利能力怎么看

### 5.1 成本地板（先认清）

| 层 | 现在/年 | 双升后/年 |
|----|---------|-----------|
| 云主机 01–04 + EdgeOne | ≈ **¥7k** | ≈ **¥15.4k** |
| + 域名/短信/邮件/杂项（估） | +¥2–5k | +¥2–5k |
| **固定基础设施（粗）** | **≈ ¥1.0–1.2 万** | **≈ ¥1.8–2.1 万** |

这只是「开机费」。真正变量是：

- **上游 Token 成本**（充值业务）→ 平台吃服务费/差价，毛利率取决于定价与损耗  
- **Markets / BYOK 订阅** → 边际成本低，**毛利好**（主要吃服务器与客服时间）  
- **支付手续费**（PayPal/Dodo 等）→ 按流水扣  

### 5.2 盈亏粗账（国际侧示意）

假设 Markets 月费 Pro **$24.9 ≈ ¥180**，毛利按 **70%**（扣支付与少量履约，示意）：

| 稳定月费 Pro 数 | 年订阅收入约 | 年毛利约（70%） | 相对「双升后基建 ¥15.4k」 |
|-----------------|--------------|-----------------|---------------------------|
| 10 | ¥2.2 万 | ¥1.5 万 | 刚盖住基建，**推广费几乎为 0** |
| 20 | ¥4.3 万 | ¥3.0 万 | 有余量，可小额投流 |
| 50 | ¥10.8 万 | ¥7.6 万 | **健康**：可认真投推广 |
| 100 | ¥21.6 万 | ¥15 万 | 基建占比低，主战场变获客效率 |

Token 充值：流水大、毛利薄，要单独算「净服务费」；**不要用流水当利润**。

### 5.3 总判断

| 判断 | 说明 |
|------|------|
| **现在** | 固定成本低（≈¥7k/年舰队），**适合验证产品与获客**；盈利能力取决于何时做出稳定付费，不取决于是否升配 |
| **双升后** | 基建仍属「小团队可承受」；若迟迟做不出 **月经常性收入数千元**，升配会变成纯成本压力 |
| **结构优势** | Markets/BYOK 订阅型 **可规模盈利**；Token 要靠量与控损；SEO/社区 CAC≈0 是利润放大器 |
| **风险** | 过早双升 + 猛投广告 + 转化未通 → 现金烧在「机器+广告」两端 |

**一句话**：按现模型，**先做出 10–20 个稳定付费**，基建和利润都舒服；**50 个 Pro 量级**开始像样；升配本身不是利润瓶颈。

## 六、推广费投多少合适

对齐作战方案门禁：**先免费渠道出信号，再小额付费流放大**。

### 6.1 阶段预算（建议）

| 阶段 | 月经常性收入（MRR）粗标 | 推广费怎么定 | 参考量级 |
|------|-------------------------|--------------|----------|
| **验证期**（现在） | ≈0–¥1,000 | **几乎不投**；SEO/社区/GitHub | 投流试水 **$100**（约 ¥700）一批，门禁齐才开 |
| **验证通过** | ¥1,000–3,000 | 推广 ≤ **毛利的 30–50%** 或 ≤ **收入的 20–30%** | $100→$300/批 |
| **增长期** | ¥3,000–10,000 | 付费流 **占收入 15–25%**；ROI≥1.5 才加码 | 月推广可到 ¥1–3k+ |
| **放量期** | >¥10,000 | **占收入 20–30%**（订阅业务可偏高）；严格 CAC 回收 | 与双升基建同期合理 |

### 6.2 三条硬纪律

1. **门禁未齐不放大**：支付通、落地页通、归因通（作战方案已有闸门卡）  
2. **按批「停/续/加码」**：每批有结论；死渠道立刻停  
3. **基建与广告别同月双倍加码**：若刚双升（+¥700/月），投流加码宜分月，避免现金双杀  

### 6.3 经验比例（订阅 + API 混合）

| 用途 | 占「毛利」建议 | 占「销售额」粗参考 |
|------|----------------|--------------------|
| 付费广告 | 毛利的 **20–40%**（验证期可到 50%，必须有回收期） | 销售额的 **10–25%** |
| SEO/内容（时间+外包） | 另计；现金占比可低 | — |
| 基建升配 | **事件驱动**，不按销售比例固定抽成 | 双升年增约 ¥8.5k，用 **2–5 个年费 Pro** 或等价 MRR 覆盖心理账 |

**不合适**：销售额还不稳定就把推广拉到收入 40%+ 且无 CAC 上限。

## 八、分阶段清单

### Phase 0 ✅ EdgeOne 接入完成

### Phase 1 · 现在（全舰队 ≈ ¥7k/年）

|---|------|

## 一、全链路（谁在采、谁在推）
1. **采集聚合**：`api/admin_ops_service.py::admin_ops_alerts` + `api/ops_alert.py::collect_alerts`
   - 覆盖：支付待履约 / 密钥缺失 / VIP 点名降级 / 健康探针 / 支付通道就绪 / 近 24h 支付失败 / 上游通道失败率与熔断 / 价格毛利（倒挂·低毛利·降本机会）
2. **巡检推送**：`api/scripts_ops_alert.py`（建议计划任务 `AI24X_OpsAlert`，每 15 分钟）
   - `run_check`：聚合 → 分级 error=P0 / warn=P1 / info（默认不推）→ 冷却 60 分钟去抖 → 恢复发「已恢复」
   - 通道：飞书机器人 webhook（组群）+ SMTP 邮件（P0/P1）+ 106 短信（仅 P0）
   - 落盘 `api/data/ops_alert_state.json`（last_push_at / last_push_text / active codes）
3. **私信兜底**：`api/scripts_feishu_alert_poll.py`（建议计划任务 `AI24X-Alert-Feishu-PM`，每 5 分钟，部署在 7×24 主机，读 openclaw.json 凭证）
   - 分支 A：`last_push_at` 变化 → 私信 `last_push_text`（去重）
   - 分支 B（1b）：`last_push_at` 为空 → 直接拉 `/live` 私信当前 P0/P1（**2026-08-07 新增兜底**）
   - 分支 C：值班重提醒 30 分钟（配置类 sf_free_key_missing / or_free_key_missing 不参与）
   - 深夜 23:30-08:30 非 P0 静默

## 二、为什么「后台有告警但飞书没收到」？
- 后台「当前告警」来自 `/v1/admin/token/alerts/live`（**实时聚合**，不依赖推送），所以后台有、飞书没有是正常现象。
- 飞书私信依赖巡检脚本产生 `last_push_at`；若产线**未注册 `AI24X_OpsAlert`**（或注册脚本路径仍指向本机 `E:\AI24X\...`），`last_push_at` 一直为空 → 旧版轮询两个分支都不动作。
- 2026-08-07 起：轮询脚本内置分支 B 兜底，`last_push_at` 为空也会私信实时 P0/P1。
- 排查命令：
  - `GET /v1/admin/token/alerts/latest`（看 `last_push_at` 是否为空）
  - `GET /v1/admin/token/alerts/live`（看当前实时聚合）
  - `python scripts_ops_alert.py --dry-run`（产线巡检预览）
  - `python scripts_feishu_alert_poll.py --dry-run`（轮询预览）

## 四、值班重提醒机制
- 触发：仍有未恢复预警（active_count>0）且距上次私信 >30 分钟。
- 2026-08-07 起：配置类（`sf_free_key_missing` / `or_free_key_missing`）不重复值班提醒，只推状态变化。
- 深夜 23:30-08:30 非 P0 静默（`feishu_notify._in_silent_hours`）。

## 五、2026-08-07 优化记录
1. `sf_free_key_missing` 由 P1 → **INFO**：生产 FREE Key 已按设计置空回落 COM 主 Key，属成本提示而非故障，不再刷 P1。
2. 新增 `sf_no_key`（**P0**）：硅基主 Key 全缺才报，真故障才响。
3. 轮询新增分支 B：`last_push_at` 为空时直接私信实时 P0/P1，链路不再依赖巡检任务是否注册。
4. 配置类告警不参与 30 分钟值班重提醒，避免刷屏。

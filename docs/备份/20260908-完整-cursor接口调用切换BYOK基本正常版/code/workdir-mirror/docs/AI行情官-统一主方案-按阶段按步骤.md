## 1) 阶段划分（先稳再快）

### 阶段 1：先把 A 项目上线链路跑通（不纠结主站）

目标：

- `a.ai24x.com` 静态页 + API 同域反代可用
- 登录 → 查询 → 扣次 → VIP（可先人工开通）闭环可用
- 有清晰的备份与回滚路径

交付：

- API 健康检查 `/health` 200
- `/docs` 可访问
- `/api/kline` 可用，扣次规则正确

### 阶段 2：数据库切换到 PostgreSQL（避免上线后迁库）

目标：

- 三环境各自 PostgreSQL（独立库）就位：预演/国内/国际不混用
- AI 行情官后端切 `AI24X_DB_KIND=pgsql` 后稳定运行
- 演练一次“PG 故障 → 切回 SQLite”止血流程

交付：

- 生产发布前 `pg_dump` 备份机制可用
- 回滚卡片可执行

### 阶段 3：标准化发布（预演→生产）与日常迭代

目标：

- 固定发布节奏：本地→预演→国内→国际
- 数据库变更脚本化（迁移可重复执行、可校验）
- 用 OpenClaw 执行标准任务包（减少手滑）

## 3) 每次发布的最小 SOP（推荐直接照抄）

详见方案卡片：`docs/AI行情官-方案卡片-发布总流程最精简不出错.md`

你只需要记住两点：

- **生产先备份**（有备份才允许迁移/重启）

## 4) 数据库字段/表结构更新（最稳做法）

## 其它可选付费数据源（补充清单，适合刚起步对比）

> 说明：下面这些供应商里，“**起步更友好**”通常意味着：有清晰的自助开通入口/试用入口、可用 Token/License 鉴权、文档明确、能先把 **日K + 复权** 跑通当兜底；“**机构级**”往往更稳，但采购/授权/集成成本更高。

### TuShare Pro（起步更友好，偏“数据接口”）

官网：`https://www.tushare.pro/`

适用性（对本项目）：
- 适合做 **日K兜底 + 本地聚合周/月**（把周/月都压成“日K + 聚合”可以显著降低供应商差异与成本）
- 上线前需要重点确认：北交所覆盖、复权因子口径、频控/配额与商用授权

购买/权限与限制（官方口径，建议上线前核对）：
- 积分与频次权限表：`https://tushare.pro/document/1?doc_id=290`
- 各 API 最低积分门槛：`https://tushare.pro/document/1?doc_id=108`
- 积分权限表（腾讯文档，可能需登录）：`https://docs.qq.com/sheet/DT0FIYUxYakJ5c1FF?tab=BB08J2`
- `rt_k`（A 股实时日线，单独开权限，常见为月付）：`https://tushare.pro/document/2?doc_id=372`

本项目接入建议（MVP）：
- 先只接 **`daily + adj_factor`** 做“个股日K前复权(qfqday)兜底”
- 周/月统一由日K聚合，避免买错模块、也减少接口差异
- `rt_k` 仅在你们明确要“盘中实时日线”时再单独购买并开启（`AI24X_TUSHARE_USE_RT_K=1`）

### 米筐 RQData（起步~中型团队友好，偏“量化数据服务”）

文档入口：`https://www.ricequant.com/doc/rqdata/`

适用性（对本项目）：
- 适合当备源：历史日K/分钟K较成熟，Python 生态友好
- 需要重点确认：license 鉴权方式、QPS/流量计费口径、北交所覆盖、复权口径

### Choice 数据量化接口（东方财富，偏“机构/终端生态”）

官网：`https://quantapi.eastmoney.com/`

适用性（对本项目）：
- 优点：厂商级数据服务，接口形态更“产品化”
- 注意：通常需要试用/商务对接；成本与授权条款要提前确认（商用、二次分发等）

### 同花顺 iFinD 数据接口（偏“机构/终端生态”）

官网：`https://quantapi.51ifind.com/`

适用性（对本项目）：
- 优点：覆盖面广、生态成熟
- 注意：授权与部署方式（本机终端/服务器授权/代理模式）需要提前确认；对“纯后端服务化调用”的限制要问清楚

### Wind 万得数据接口（机构级，通常更贵）

数据接口服务：`https://www.wind.com.cn/portal/zh/WDS/sapi.html`

适用性（对本项目）：
- 适合“机构级稳定性/覆盖”的长期方案
- 对刚起步：通常预算与采购流程更重；可先作为备选对比

### 实时行情型（更偏“低延迟/推送”，不是最优的日K兜底首选）

> 如果你们后续要做“实时推送/盘口/逐笔”，这类更合适；但若只是做“日K兜底”，优先选上面偏历史/日线稳定的供应商，成本更可控。

## 接入帮助（按你当前后端结构落地）

你当前项目（`p/a/api/server/app/`）已经有：
- **多源拉取**：腾讯（主）+ 东财（备）+ 新浪（少量指数备）
- **熔断**：腾讯失败次数触发短期熔断
- **缓存**：内存缓存 + SQLite 持久化缓存（`kline_cache`）
- **可观测性**：`/api/status/market-data`（需 `X-Admin-Key`）输出数据源与熔断状态

付费接口建议按“Provider 插件化”接入，保持前端不改：

### 1) 统一 Provider 输出协议（强烈建议）

把所有数据源都输出成你前端已能消费的“腾讯形状”：

- `{"code": 0, "data": { "<KEY>": { "qfqday": [...], "day": [...], "qfqweek": [...], "week": [...], "qfqmonth": [...], "month": [...] }}}`

这样前端 `pickTencentKlineRows()` / 周月聚合逻辑不用动。

### 2) 配置开关（默认关闭，应急开启）

建议新增环境变量（示例命名）：

- `AI24X_PAID_PROVIDER=jqdata|gm|off`（默认 `off`）
- `AI24X_JQDATA_USER=...` / `AI24X_JQDATA_PASS=...`（或 token）
- `AI24X_GM_TOKEN=...`
- `AI24X_PAID_PROVIDER_PRIORITY=tencent,eastmoney,sina,paid`（控制优先级，建议默认“公共源优先，付费兜底最后”）
  - 目前已接入：`tushare`（用 `AI24X_TUSHARE_TOKEN`）

上线后你只需改配置并重启（或热更新）即可启用付费兜底。

### 2.1) 推荐的上线策略（省钱 + 可控）

- **默认不开通包月/包年**：公共源稳定就一直跑公共源。
- **先把接入打通并灰度验证**：确保付费源输出形状与现有系统兼容（你们已要求“腾讯形状”），且缓存/限流策略有效。
- **出现大面积不可用/投诉时再按月开通**：充值包月 → 把 `AI24X_PAID_PROVIDER` 打开即可，不用改前端。
- **可选：仅 VIP 允许走 paid**：
  - 公共源正常时：免费用户永不触发 paid（控成本）
  - 公共源异常/熔断时：VIP 优先 paid 兜底（保口碑）

### 2.2) 后台“配置管理小模块”（后续实现要点）

如果你们要在后台做一个“随时开关付费源 / VIP 才启用”的小模块，建议最小化成这几项可改配置：
- **paid 开关**：`paid_provider`（off / tushare / jqdata / gm / ...）
- **路由优先级**：`paid_provider_priority`（默认公共源优先；应急时把 paid 提前）
- **rt_k 开关（TuShare 专用）**：`tushare_use_rt_k`（仅购买实时日线权限后开启）
- **策略开关**：`paid_vip_only`（仅 VIP 允许使用 paid；公共源异常时才触发）

本项目已落地（当前实现）：
- **TuShare Provider**：后端已接入 `tushare`，可稳定获取 A股/北交所 `daily + adj_factor`，并输出为前端可复用的“腾讯形状”
- **路由按优先级执行**：后端会按 `paid_provider_priority` 的顺序尝试（例如 `paid,tencent,eastmoney,sina` 或 `tencent,eastmoney,sina,paid`）
- **C 方案（推荐）**：VIP 优先走 paid；免费优先公共源；并可用 `paid_vip_only` 控制“仅 VIP 允许走 paid”
- **后台开关已实现**：`/admin` 页面增加“数据源开关”卡片（需 `X-Admin-Key`），配置落到 SQLite 表 `admin_config`，保存后约 5 秒内生效
- **缓存/并发隔离**：K 线缓存与 singleflight 以 `vip/free` 分桶，避免免费用户命中到付费缓存（或反之）

实现建议：
- 配置以环境变量为“基线”，后台修改写入一份本地 `admin-config.json`（或 SQLite 表），重启/热加载生效
- 所有变更要可审计（谁在什么时候开了付费开关，持续多久）
- 要有“自动回落”：比如 paid 连续失败 N 次时自动把 paid 降级到末尾，避免二次故障放大

### 3) 限流与成本控制（必须做）

付费源启用后，务必在后端加：
- **按用户/按 IP 的 rate limit**（你已有 `_rate_limit`）
- **按 secid+period 的强缓存**（你已做 SQLite + TTL）
- **“数据质量门槛”**（例如北交所日线至少 N 根，不足则判失败并切回其它源）

## 建议的“报价填表模板”（给商务/采购用）

你可以把下面这段复制到对外邮件/企业微信，向两家同时要报价：

**需求概述**
- 用途：Web 应用行情/K 线展示，失败时自动切换为备源
- 市场：A 股 + 指数 + 北交所（重点）
- 频率：日线（必须），周/月可由日线合成；分钟线（可选）
- 复权：前复权（必须）
- 请求模式：后端服务调用（非浏览器直连）
- 并发：峰值 QPS（填你的预估）
- 覆盖：至少近 10 年日线历史（填你的预估）

**报价希望包含**
- 套餐名/有效期/价格（含税）
- 日请求或流量上限、并发连接数
- 超额计费方式
- SLA（可用性/故障补偿）、IP 白名单/鉴权方式
- 北交所覆盖情况与口径说明

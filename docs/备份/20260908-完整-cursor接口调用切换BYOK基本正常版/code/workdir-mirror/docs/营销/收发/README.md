# Codex ↔ 主脑直连协议（2026-08-07 验证通过）

> 通道：本机直连（类似 SSH 协议），不依赖飞书群 @。飞书仅作人工可见层（主脑自动推送汇报）。
> 验证记录：Codex → openclaw agent --agent main → 主脑回复 OK（7.5s）；端到端测试主脑汇报已送达飞书；老板飞书私信 → 主脑 session 日志 → Codex 读取通过。
> **唯一绝对路径**：`E:\AI24X\ai24x-website\ai24x01\docs\营销\收发\`（主脑必须用绝对路径，禁止解析到自己的 workspace）

## 一、通道架构

```
Codex（本机）
  │ ① 写指令文件 → 收发\指令\YYYYMMDD-HHMM-序号.md
  ▼
openclaw agent --agent main --message-file <指令文件> --json --timeout 180
  │ ② 本机直连网关 ws://127.0.0.1:18789
  ▼
主脑 openclaw（agent main，AI24X 指挥）
  │ ③ 执行：分派各副脑 / 查清单 / 回执
  ▼
  ├─ ④ --json 结果回 Codex（审批矫正）
  └─ ⑤ 飞书通道推送汇报（老板手机可见，含重大问题审批请求）
```

## 二、命令规范

```powershell
openclaw agent --agent main --message-file <指令文件> --json --timeout 180
# 可选：指令正文注明「完成后通过飞书汇报本条结果」
```

## 三、收发目录约定（绝对路径）

- `收发\指令\`：Codex 下发的指令文件（主脑可读）；命名 `YYYYMMDD-HHMM-序号.md`；**老板 `司令:`/`总司令:` 消息（兼容旧 `cx:`）由主脑转达落盘至此**
- `收发\回复\`：Codex → 老板 的回复落盘（主脑转达用）；命名与指令同名 + `-out`
- 文件即审计：任何指令/回复都有持久记录

## 四、角色与顺序（老板审批流程）

1. Codex 下发指令（直连，记录到 收发\指令）
2. 主脑执行 + 汇报（直连结果 + 飞书推送）
3. Codex 审批矫正：能解决的直接解决；需老板拍板的 → 飞书推送
4. 老板手机飞书：随时查看汇报、回复审批意见
5. 老板审批意见 → 私信主脑（`司令:`/`总司令:` 前缀给司令；兼容旧 `cx:`）或回司令对话 → 继续执行

> 老板在飞书私信的是「AI24X指挥」机器人（主脑 openclaw 飞书通道），openclaw 收到私信即唤醒主脑处理。

## 五、注意事项

- 指令要明确「做什么 + 汇报格式 + 是否飞书推送 + 是否等审批」
- 危险/高成本操作（发版、投流出钱、删数据）指令必须带「先报老板审批」
- 主脑忽略同应用自发的群消息，因此 Codex 不用机器人身份发群指令，一律走直连

## 六、老板消息协议（v0.2 · 2026-08-07）

**老板在飞书给主脑发消息，用前缀区分接收者：**

| 前缀 | 含义 | 处理 |
|------|------|------|
| `司令:` / `总司令:` | 给 Codex 司令 | 主脑原样转达司令（写入 收发\指令\ + session），司令处理后由主脑飞书回复 |
| `cx:`（旧别名，兼容） | 给 Codex 司令 | 同上 |
| `cx:`（旧别名，兼容） | 给 Codex 司令 | 同上 |
| （无前缀） | 给主脑 | 主脑正常处理 |

- 代号说明：正式代号 **`司令:`**（或 **`总司令:`**）；旧 `cx:` 保留为兼容别名（历史消息与肌肉记忆仍可用）
- 示例：`司令: 帮我确认 /v1/models 发版了没有`
- 司令回复经主脑转达时带 `[司令]` 标记，方便老板识别来源
- 协议持续迭代：每次改进在此追加版本号与变更说明
## 七、Codex 会话唤醒约定（v0.3 · 2026-08-07）

> 背景：Codex 会话是被动触发的，无常驻轮询；老板飞书发 司令: 后消息能落盘，但需 Codex 会话处理。

- 电脑前：老板每次回到 Codex 对话，司令先检查 `收发\指令\` 积压 司令: 消息并处理
- 手机在外：老板 司令: 消息由主脑落盘保存；老板下次打开 Codex 对话时 Codex 处理；或老板在对话里说一声「有 cx 消息」Codex 立即处理
- 主脑侧：司令处理完写回复到 `收发\回复\`，主脑读取转达飞书（带 [司令] 标记）
- 实测：2026-08-07 22:29 老板 司令: 消息 → 司令处理 → [司令] 回复 → 飞书送达 ✅

## 七之二、称呼规范（2026-08-07 老板定）
- Codex（本会话/桥接）= **司令 / 总司令**；主脑 openclaw（飞书 bot「AI24X指挥」）= **指挥 / 指挥官**。
- 老板消息里带 cx: 前缀=给司令；无前缀=给指挥官。
- 文档/记忆/汇报统一用此称呼。

## 七之三、飞书单一出口规则（2026-08-07 老板定）
- **飞书出口只有主脑一个**：所有给老板的飞书消息（司令回复、汇总、异常）统一由主脑（openclaw）通过其飞书通道转达；司令【不】直发飞书。
- 司令回复流程：司令落盘 收发\回复\ → 主脑读取 → 飞书转达（带 [司令]）→ 移入 _sent\。
- 例外：仅当主脑通道故障/失联时，司令才用 scripts\feishu_send.ps1 兜底直发，并必须在消息中注明「兜底直发」。
- 主脑转达前必须确认对应回复文件未在 _sent\（防重复，23:26 曾同一条转两遍）。

## 七之四、指挥失联降级预案（2026-08-08 定）
- 判定：司令连续 2 次 openclaw agent --agent main 调用失败/超时 = 指挥失联。
- 降级动作：① 老板回本对话（司令）直接接管调度；② 司令本机直连 01（本机 OpenClaw）发紧急操作，结果落盘 收发\回复\ 保审计；③ 需远程机（02/03/04）的操作暂缓，待指挥恢复；④ 指挥恢复后补同步审计。
- 不设常规直连：保持司令→指挥→副脑单线派发，指挥统一调度/验收/审计；直连仅限失联降级。

## 八、P3 SIGKILL 根因（2026-08-07 23:16 定位）
- 根因：主脑 exec 工具约 120s 超时杀掉整个进程树 → codex exec 被 SIGKILL。23:02 两次被杀均为长链条任务（Codex→主脑→SSH四台副脑→汇总）同步等待超时所致；第三次成功是因主脑已先干完活。
- 根治：cx_bridge.ps1 v2 改派发+确认模式（任务预算≤100s，长任务只派发不同步等待）；长任务由主脑直接执行并飞书汇报；已派发不重复驱动；主脑 exec 调用上限 115s；规则已并入主脑 TOOLS.md。

## v0.4.6（2026-08-09 凌晨）cx_bridge 编码修复
- 症状：主脑驱动的 Worker 模式把中文任务传 codex exec 时乱码，codex exec resume exit 2，无回复输出。
- 根因①：cx_bridge.ps1 为 UTF-8 带 BOM 文件，改写成无 BOM 后 PS5.1 按 GBK 误读导致解析错乱；根因②：中文 prompt 走命令行参数传给 codex.ps1→node 时编码损坏。
- 修复：脚本保持 UTF-8 带 BOM；Worker 模式改 $prompt | codex exec ... -（stdin 传参）+ $OutputEncoding = UTF8。已实测中文回执闭环（01:13）。
- 纪律：改动 cx_bridge.ps1 必须保持 UTF-8 带 BOM，勿用无 BOM 编码写回。

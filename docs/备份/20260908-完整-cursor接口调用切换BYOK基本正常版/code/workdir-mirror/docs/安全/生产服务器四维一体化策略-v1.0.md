> 核心原则：**管理面严格，服务面开放，封禁最小化，爬虫甄别友好**

## 一、分层原则（专业运维视角）

| 层面 | 端口 | 策略 |
|---|---|---|
| 管理面 | SSH 22 / RDP 3389 | 严格白名单，仅主脑/雷总终端/副脑互访 |
| 服务面 | 80 / 443（网站+API） | 默认开放，永不因管理面误判封禁 |
| 收录引擎 | 80 / 443 爬虫访问 | rDNS 验证后放行，永不禁封 |
| 公网用户 | 80 / 443（访问/调 API） | 正常服务，不被爆破封禁连带误伤 |

## 二、关键改造点

### 1. 自动封禁规则改为「端口定向」
- **现状问题**：Block-Attack-* 规则为「协议:任何」，整 IP 全封 → 会连带封掉该 IP 的网站访问/API 调用（共享 IP 用户、爬虫全中招）
- **改造**：自动封禁只针对 22/3389 端口（管理面），**禁止**整 IP 封 80/443
- 封禁命令模板：
  ```
  netsh advfirewall firewall add rule name="Block-SSH-Brute-<IP>" dir=in action=block protocol=TCP localport=22 remoteip=<IP>
  ```

### 2. 爬虫友好白名单（rDNS 验证，防伪造）
- 触发爬虫识别时：先反解 PTR，匹配官方域名后缀才放行，禁止仅凭 IP 白名单（防攻击者伪造爬虫 IP）
- 官方后缀清单：
  | 引擎 | PTR 后缀 | 端口 |
  |---|---|---|
  | Googlebot | *.googlebot.com | 80/443 |
  | Bingbot | *.search.msn.com | 80/443 |
  | Baiduspider | *.baidu.com / *.baiduspider.com | 80/443 |
  | GPTBot (OpenAI) | *.openai.com | 80/443 |
  | ClaudeBot (Anthropic) | *.anthropic.com | 80/443 |
  | PerplexityBot | *.perplexity.ai | 80/443 |
  | Applebot | *.apple.com | 80/443 |
  | Yandex | *.yandex.ru / *.yandex.com | 80/443 |
- 放行规则模板：
  ```
  netsh advfirewall firewall add rule name="Allow-Crawler-<Engine>" dir=in action=allow protocol=TCP localport=80,443 remoteip=<验证后IP>
  ```

### 3. 管理面白名单（保持不变，补充）
- trusted-ips.json 继续作为管理面唯一依据：主脑 122.239.106.193（动态，定期更新）+ 115.223.183.83 + 雷总终端 + 副脑互访
- 主脑 IP：never_block=true（救援通道，永不禁封）

### 4. 公网 API 用户保护
- 应用层限流（API key 维度）由业务代码负责，**不依赖 IP 封禁**
- 防火墙层面不封 80/443 的任何 IP（除确证 Web 攻击且仅封攻击特征端口）

## 每次更新必做清单 1.0（预演副脑01 / 生产副脑03）

适用：每次发布/升级/联调（含环境配置变更、HTTPS、PM2 重启、数据库字段迁移）。

> 唯一口径来源仍为 `docs/副脑统一操作手册.md`；本文件是“可直接转发执行”的精简版。

---

### 共同前置（两边都必须）

- **目录门禁**：必须在 `C:\ai24x01`（硬校验 `Get-Location`）
- **代码更新**：
  - 预演：`git pull`
  - 生产：建议 `git fetch --tags` + `git checkout prod-...`（或你们生产 tag）
- **生产 Git 状态门禁**（生产必须做）：若出现 `You are not currently on a branch.`，必须先 `git checkout master`（或明确 prod tag）再更新，否则 `git pull` 不会生效
- **副脑03拉取口径（防更新无效）**：只允许 `git pull origin master`（不要随手 `git pull`，避免拉到错误 remote）
- **强制 PQ**：确认 `.env` 的 DB 连接串都是 `postgresql://...`，禁止 sqlite
- **依赖一致性门禁（paid 可选依赖）**：若本次涉及 paid（TuShare）或 requirements 变更，必须用 `python -m pip install -r requirements.txt` 并 `python -c "import tushare"` 验收（确保装在 PM2 使用的 python）
- **配置覆盖**：把主脑下发的 env 放到 `C:\env-pack\`，再运行手册里的“专属一键脚本”
- **PM2 必回传**：`pm2 list`（确认进程名/端口没跑偏）
- **入口路径门禁（避免 /i/ 子路径事故）**：发布后必须至少打开一次 `https://<域名>/i/<邀请码>`，并在 F12 Network 确认 `/css/base.css` 与 `/js/shell.js` 为 200/304（不是 `/i/css/...`）

### 极简：副脑03更新指令（直接复制执行）

```powershell
Set-Location C:\ai24x01

git status
git checkout master
git pull origin master
git log -1 --oneline

pm2 restart a-api-8001
pm2 restart core-api-8002
pm2 save
pm2 list
```

> **注意（2026-07-27 事故）**：仅 `pm2 restart` **不会**重读 `ecosystem.config.cjs`。若 pull 后新路由仍 404 / 行为仍旧，必须：  
> `pm2 delete a-api-8001` → `pm2 start ecosystem.config.cjs --only a-api-8001` → 环回+公网打 `/api/public/build_stamp`。  
> 详见 `docs/联调/事故-pm2-restart未加载新代码.md`。

### 副脑01（预演）每次更新必做（`w1` + `a1`）

- **env-pack 必备**：
  - `C:\env-pack\api.env`（core：`DATABASE_URL=.../ai24x_core_pre` + `SMS_INTERNAL_KEY`）
  - `C:\env-pack\a1.env`（a1：`AI24X_DATABASE_URL=.../ai24x_a_pre` + 微信/短信配置）
- **数据库检查/建库**：确认 `ai24x_core_pre`、`ai24x_a_pre` 存在；没有就创建
- **PM2 重启（预演口径）**：
  - `pm2 restart core-8000 a1-api-18011 a1-web-18001`
  - 停用旧版避免串线：`pm2 stop a-api-18031 a-web-18001`
- **HTTPS（如涉及域名联调/微信回调）**：
  - WACS 多域名证书：`a1.ai24x.com` + `w1.ai24x.com`
  - Nginx `/api/` 必须反代到 `http://127.0.0.1:18011/api/`
- **门禁（必须全 200）**：
  - `http://127.0.0.1:8000/health`
  - `http://127.0.0.1:18011/health`
  - `https://a1.ai24x.com/health`
  - `https://w1.ai24x.com/`（主页至少 200）

### 副脑03（生产）每次更新必做（`www` + `a`）

- **发布前备份（强制）**：
  - 数据库 `pg_dump`（至少 `ai24x_core_cn`、`ai24x_a_cn`；按实际库名）
  - 备份 Nginx 配置与证书目录（例如 `C:\nginx\conf\`、`C:\nginx\ssl\`）
  - 备份 `.env`（`api\.env`、`p\a\api\server\.env`）
- **env-pack 必备**：
  - `C:\env-pack\api.env`（core：`DATABASE_URL=.../ai24x_core_cn`）
  - `C:\env-pack\a.env`（a：`AI24X_DATABASE_URL=.../ai24x_a_cn`）
- **数据库检查/建库**：确认 `ai24x_core_cn`、`ai24x_a_cn` 存在；没有就创建（正常应已存在）
- **PM2 重启（生产唯一口径）**：
  - `pm2 restart core-api-8002 a-api-8001`
- **HTTPS**：
  - WACS 多域名证书：`www.ai24x.com` + `a.ai24x.com`
  - Nginx 反代：
    - `a.ai24x.com` → `http://127.0.0.1:8001`
    - `api.ai24x.com` → `http://127.0.0.1:8002`
- **门禁（必须全 200）**：
  - `https://www.ai24x.com/`
  - `https://a.ai24x.com/health`
  - `https://a.ai24x.com/docs`

### 若本次更新包含“数据库字段变更 / 表结构变更”

- **先副脑01跑迁移并通过门禁**，记录迁移文件名（`db/migrations/<MIGRATION>.sql`）
- **生产先备份再迁移**：迁移失败立刻停止，必要时按备份回滚

---

### 仅一次性场景：继承“后台配置（admin_config 等）”或灾备恢复（用 dump 导入）

> 重要：这是 **初始化/灾备/明确全量恢复** 才允许的操作。  
> **日常上线/字段新增/小改动** 一律不要用 `pg_restore --clean` 覆盖生产库，避免把“已上线真实数据”清空。

#### 预演（副脑01）允许：从主脑 dump 恢复到预演库

- 你需要主脑先生成并下发：
  - `ai24x_core_pre.dump`（core 预演库）
  - `ai24x_a_pre.dump`（a1 预演库）
- 副脑01 放到：`C:\bak\incoming\`
- 恢复命令（示意，执行前务必停服务）：
  - `pg_restore ... -d ai24x_core_pre --clean --if-exists ai24x_core_pre.dump`
  - `pg_restore ... -d ai24x_a_pre --clean --if-exists ai24x_a_pre.dump`

#### 生产（副脑03）默认禁止：覆盖式 restore

- 生产环境除非是**明确的灾备演练/全量恢复窗口**（并且已完成多重确认与备份），否则不要做：
  - `pg_restore --clean --if-exists -d ai24x_core_cn ...`
  - `pg_restore --clean --if-exists -d ai24x_a_cn ...`
- 生产日常“配置继承”优先策略：
  - **走 env-pack**（环境变量）
  - 或用“只导入配置项”的方式（逐条写入 `admin_config`），不要动业务数据表

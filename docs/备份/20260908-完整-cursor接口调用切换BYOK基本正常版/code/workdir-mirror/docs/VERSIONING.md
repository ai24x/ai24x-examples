## 子项目版本与封存规则（唯一口径）

目标：避免多会话/多人协作时“顺手改老版本”，导致线上口径与排障依据混乱。

### 1) 版本号与目录命名

- **当前在线/当前开发的主版本**：使用 `p/a1`、`p/a2`、`p/a3`… 这种“阶段版本目录”。
- **每一个“大阶段”**（重要功能/架构/口径变更）完成后，新建下一个目录继续迭代：
  - 示例：`p/a1`（V1.0）→ `p/a2`（V2.0）→ `p/a3`（V3.0）
- **对外域名**永远指向“当前版本”的前端目录（例如 `a1.ai24x.com` → `p/a1/web`）。

### 2) 封存（只读）规则

以 `p/a` 为例：

- **状态**：永久封存（只读归档）。
- **允许**：对照排查、回溯历史、应急回滚依据。
- **禁止**：任何功能/文案/配置变更。
- **唯一例外**：线上重大事故必须热修时，可在封存版本修补，但必须：
  - 同步把修补回补到当前主版本（`p/aN`），确保“现行口径”不分裂
  - 并在 `docs/` 或 `memory/` 记录原因与影响范围

### 3) Git 侧建议（防误改）

- 每次冻结一个阶段版本时，建议打 tag：例如 `a1.0-freeze`。
- 如需长期维护某个线上版本，可建 `release/a1` 分支，仅接受紧急修复（可选）。

# 域名分层与反向代理示例（www / api / a）

本文件提供一个**最小可用**的落地参考：主站与多个子项目用子域名隔离部署。

> 注意：以下示例用于说明结构；生产请按你的服务器路径、证书与安全策略调整。

## 1. 推荐端口约定（本机/单机）

按“端口池规范”：

- 服务器端口池：8000+
  - `www.ai24x.com`：`127.0.0.1:8000`（如需进程；纯静态可不占端口）
  - `a.ai24x.com`：`127.0.0.1:8001`
  - `api.ai24x.com`：`127.0.0.1:8002`
- 本地开发端口池：18000+（推荐与服务器端口池隔离）
  - `www`：`127.0.0.1:18000`（可选）
  - `a`：`127.0.0.1:18001`
  - `api`：`127.0.0.1:18002`

> 国际（intl）建议单独端口段（见 `docs/PORTS.md`）：例如 9000+，避免与 cn 8000+ 混淆。

## 2. Nginx 示例（概念版）

### 2.1 `www.ai24x.com`（静态主站）

- `root` 指向仓库（或发布目录）里的 `web/`
- `try_files` 兜底到 `404.html`

### 2.2 `api.ai24x.com`（AI24X 统一 API）

- `proxy_pass` 到 `http://127.0.0.1:8000`

### 2.3 `a.ai24x.com`（AI 行情官｜灯塔版（1.01））

- `proxy_pass` 到 `http://127.0.0.1:8001`
- 若将来需要把 `p/a/web/` 也同域托管，可增加静态 location（或由后端挂载）

## 3. CORS 建议

- 尽量做到 **同域同源**（前端与后端在同一子域），可显著减少跨域复杂度。
- 若必须跨域（如 `www` 调 `api`），则：
  - API 端按域名白名单配置 CORS（避免 `*` + credentials）
  - 前端统一通过配置文件/环境切换 API base

## 4. 国内验证 → 副脑03 部署建议（高层）

- 国内验证先保证：**主站可用性** 与 **AI 行情官｜灯塔版（1.01）（第一个子项目）** 的闭环。
- AI24X 统一 API 分阶段上线：先最小链路（health/鉴权/路由）再逐步补齐计费与支付。
- 数据层不要混用国际生产库：国内验证与国际生产至少 **分库/分环境变量**。

## 5. 国际站（intl）落地提示（最小约定）

- 建议将 intl API 作为独立环境部署（**分库**、支付/上游/回调配置独立），并用独立子域名或独立端口段区分：
  - **对外统一入口**：`api.ai24x.com`（国内优先阶段也可先指向 cn；后续再切到 intl 或做区域路由）
  - **预留（不对外公布）**：
    - `api-cn.ai24x.com`（cn，可选）
    - `api-intl.ai24x.com`（intl，可选）
- 反代时请避免把两个环境同时挂到同一子域名下；若需要灰度/切流，建议在 Nginx 层做可回滚的 upstream 切换，并配套状态页与观测。

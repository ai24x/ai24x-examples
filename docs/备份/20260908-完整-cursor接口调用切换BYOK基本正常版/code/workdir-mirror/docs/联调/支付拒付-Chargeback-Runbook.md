# PayPal / 支付拒付（Chargeback）处理 Runbook

> 对内运维文档。用户端不承诺现金提现；返利仅 token 入账可抵扣 API。

## 1. 发现渠道

- PayPal 商户后台 Dispute / Chargeback 邮件
- 微信/支付宝商户后台争议单
- 用户客服工单声称「未到账 / 要退款」

## 2. 15 分钟内必做

1. 记下：`out_trade_no`（T…）、PayPal Capture ID / 微信/支付宝交易号、用户 `auth_user_id`、套餐、金额。
2. 查库订单：`token_pay_orders`（或现表名）状态是否 `paid`、履约是否已写入 ledger。
3. 查流水：该用户是否有对应 `topup` 入账；余额是否已被消耗。
4. **暂不**直接在商户后台点「全额退款」除非已确认未履约或明确欺诈误判且余额仍在。

## 3. 判定与动作

| 情形 | 动作 |
|------|------|
| 已支付未履约（订单 pending、无 ledger） | 补履约或官方渠道退款；记事故 |
| 已履约且余额仍在 | 冻结用户 → 扣回等额 token → 再同意退款/应诉 |
| 已履约且已消耗大半 | 应诉提供：订单、webhook/通知日志、ledger、API 调用记录；拒全额退时说明已交付虚拟服务 |
| 明显盗刷/同一指纹多号 | 冻号 + 拒绝退款应诉 + 拉黑支付指纹 |

冻结：管理台或 `POST /v1/admin/...` 用户冻结（内部钥）。扣回：人工调账（ledger 记 `adjust`/`chargeback` note），勿静默改余额。

## 4. 返利相关

- 若该笔为**被邀请人首充**且已触发 L1/L2 返利：扣回被邀请人余额时，同步评估是否冲销推荐人返利（同 note 关联 `out_trade_no`）。
- 对外口径：**返利是 token 额度，不是现金，不可提现。**

## 5. 应诉材料清单

- 订单创建时间、金额、币种、plan_id
- Webhook / 异步通知原文摘要（脱敏）
- 用户注册邮箱/手机、IP（日志）
- Token 入账 ledger id + 后续 consume 记录
- 网站条款中「虚拟商品 / 数字服务」相关条款截图

## 6. 回滚与监控

- 大面积异常拒付：临时关 `TOKEN_PAY_ENABLED` 或关 PayPal 通道，保留微信支付宝或反之。
- 每日看：拒付率、同 IP 多账号首充、异常大额 Scale 包。

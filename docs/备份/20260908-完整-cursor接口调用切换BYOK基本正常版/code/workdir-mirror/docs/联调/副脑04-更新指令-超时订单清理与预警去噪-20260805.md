## 本包

| 项 | 说明 |
|----|------|
| 预警去噪 | `pay_pending_backlog` 只统计「有效待履约」（超时未付按渠道窗口过滤：微信/支付宝 24h、PayPal 72h）；历史积压不再误报 P1 |
| 超时订单清理 | 无渠道交易号的超时 pending → 作废为 failed；有交易号（PayPal）的超时单**保留**待对账（可能已收款未发放，勿作废）；dry_run 默认；单次作废 >200 中止保护 |
| 清理入口 | 独立脚本 `api/scripts_token_pending_cleanup.py`（`--apply` 才落库）；计划任务 `AI24X_PendingCleanup`（每天 06:00）；管理端点 `POST /v1/admin/token/orders/cleanup`（X-Admin-Key，body dry_run 默认 true） |
| 管理台 | Token 订单新增「清理过期单」按钮（dry-run 预览 + 二次确认）；过期单区分「已过期」/「已过期·待对账」标识 |

## 验收

1. 预警去噪：管理台预警中心或 `GET /v1/admin/token/alerts/latest`
   - `pay_pending_backlog` 应消失，或消息带「有效待履约 N 笔（另有过期未付 M 笔已过滤）」
2. 清理端点 dry-run 预览：
```powershell
curl.exe -sS -X POST https://api.ai24x.com/v1/admin/token/orders/cleanup `
  -H "X-Admin-Key: <内部密钥>" -H "Content-Type: application/json" -d "{\"dry_run\":true}"
# 期望 ok:true + valid / voidable_no_txn / kept_for_reconcile
```
3. 清历史积压（安全：无交易号才作废；有交易号的保留）：
```powershell
cd C:\ai24x01\api
python scripts_token_pending_cleanup.py --apply
```
4. 管理台：Ctrl+F5 硬刷新 token-admin.html → Token 订单 →「清理过期单」按钮可用；过期单显示「已过期」或「已过期·待对账」
5. **对账提醒**：`kept_for_reconcile`（有交易号的超时 PayPal 单）→ 跑 PayPal 对账确认 capture 状态；若已收款未发放 → 走补单履约（🔴 需雷总确认后执行）

## 注意

- 清理不可逆：仅「无交易号 + 超时」的订单会被作废为 failed；有交易号的永远保留
- 首次部署后，历史积压中无交易号的超时单可手动 `--apply` 立即清，也可等计划任务每天 06:00 自动清
- 本包同时包含 web 静态更新（token-admin.html），无需单独部署

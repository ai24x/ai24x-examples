# Cursor 修复建议汇总 — Token 接口平台（2026-08-04）

> 范围：`api/` 主项目（不含 `p/` 子项目）。来源：上线前代码审查。
> 说明：本机为本地测试环境；涉及生产环境变量的项（A5/A6/T7 等）上线时需在 04 服务器核对，代码类问题请按 T1–T14 直接修复。

- A4 `api/data/llm_keys_override.json` 明文存上游 Key；`OPENROUTER_API_KEY="iamlei888"` 疑似占位符，上线前核对真实 Key。

## T1 支付履约幂等（防重复到账） — P0

- 位置：`api/token_pay_service.py` `_fulfill_order_row` / `try_fulfill`（约 :236）
- 问题：先查 `status=pending` → 入账 → 再置 paid，非原子；微信 notify + “确认到账”并发、PayPal webhook 重试 + capture 并发、多 worker 可一笔钱到账两次。
- 修法：履约入口先原子抢占状态：
  `UPDATE token_pay_orders SET status='paid', transaction_id=:txid, paid_at=now() WHERE out_trade_no=:otn AND status='pending'`，`rowcount==1` 才继续入账；0 行则回读判断是否同一 txid 的重复通知（返回 duplicate 成功）。入账抛错需回滚状态。或用 `SELECT ... FOR UPDATE` 锁行后校验再入账。
- 验收：并发 10 个相同 out_trade_no 的履约只入账 1 次；`token_pay_orders` 与 `billing_ledger` 一一对应。

## T2 扣费预授权 + 原子批次扣减 — P0

- 位置：`api/token_mvp_service.py` `assert_can_spend`(:512) / `consume_tokens`(:559，:599 `if avail < tokens: tokens = avail`)；`api/services.py` 两个扣费调用点（:251 / :519）
- 问题：1）余额只剩 1 token 也能拿满 `max_tokens=16384` 输出，只扣 1 token（pro/ultra 还有 3x/6x 倍率）；2）批次扣减读-改-写无锁，并发请求可同时通过预检并透支（丢失更新，余额虚高）。
- 修法：
  1. 预检按预估成本校验：`prompt/messages 估算 token + max_tokens` × 层倍率（L2=3 / L3=6）作为 need_tokens，不足直接 402，不放行到上游。
  2. `consume_tokens` 改原子扣减：`UPDATE token_credit_lots SET amount_remaining = amount_remaining - :take WHERE id=:id AND amount_remaining >= :take`，循环直至扣完或不足；实际扣减=成功更新行之和，不足部分不超扣。
  3. 记账（BillingLedger）与实际扣减一致，响应如实返回。
- 验收：余额 100 并发 10 个 16k 请求，实际消费≤100；批次 remaining 不为负且总和=wallet.balance_tokens。

## T3 流式扣费补 USD 主余额 — P0

- 位置：`api/services.py` `stream_chat_request`（:519）
- 问题：真流式结束只扣 tokens 不扣 `balance_usd`，非流式两者都扣（:251-256），账目不一致、漏收。
- 修法：流式结束调用 `consume_tokens(..., amount_usd=round(token_count/1e6 * flash_ref_usd_per_m * 100))`，与非流式同口径。
- 验收：同模型同 token_count，流式与非流式扣减的 balance_tokens / balance_usd 一致。

## T4 mock 支付生产硬禁 — P0

- 位置：`api/token_pay_service.py` `token_pay_mock_allowed`(:102)、`mock_fulfill`(:329)；`api/main.py:1889`
- 问题：env / 管理台覆盖文件可把 mock 开进生产，任意登录用户可建单后 mock 到账免费拿余额。
- 修法：`token_pay_mock_allowed()` 开头 `if is_prod(): return False`；`mock_fulfill` 同样加一道硬判断。保留 dev/local 联调。
- 验收：`APP_ENV=production` 时 mock_fulfill 恒 403。

## T5 PayPal webhook 验签强化 — P0

- 位置：`api/main.py` `billing_paypal_webhook`（:2056）
- 问题：sandbox 模式放行未验签事件，可伪造 `PAYMENT.CAPTURE.COMPLETED` 免费履约。
- 修法：改为 `if not verified: return 400`（不分模式）；sandbox 联调用真实 `PAYPAL_WEBHOOK_ID` 或改走 capture 查单，不依赖免验签。
- 验收：任意模式下伪造事件均被拒绝。

## T6 返利 / 日赠幂等（DB 约束兜底） — P1

- 位置：`api/models.py`（Referral / BillingLedger / TokenWallet）；`api/token_mvp_service.py` `bind_referral_on_register` / `settle_referral_on_topup`(:1109) / `ensure_period_bonus`(:360)
- 问题：无唯一约束，并发可重复绑定邀请、重复结算返利、重复发 VIP 日赠。
- 修法：加唯一索引 `Referral(referee_id, level)`、`BillingLedger(auth_user_id, entry_type, note)`；绑定/发放改 `INSERT ... ON CONFLICT DO NOTHING` + 幂等返回。
- 验收：并发注册同一邀请码仅一条 L1/L2；并发充值仅结算一次返利；同日 VIP 日赠仅入账一次。

## T7 价格口径一致性校验 — P1

- 位置：`api/token_plans.py` `_resolve_plan` / `list_public_plans`；`api/data/token_plans_override.json`
- 问题：override 的 `price_fen` 与 `price_usd` 可严重偏离（现 10k/100k 差 100 倍）。
- 修法：`_resolve_plan` 校验 `price_fen` 与 `price_usd × 汇率 × 100`，偏差>5% 打告警日志；`list_public_plans` 的 CNY 展示价以 USD×汇率重算，避免各渠道标价不一致。
- 验收：`/v1/billing/plans` price_yuan 与 price_usd×7.2 一致。

## T8 X-Forwarded-For 信任修正 — P1

- 位置：`api/security_util.py` `client_ip`、`api/sms_abuse_guard.py`、`api/email_abuse_guard.py`；Nginx `db/nginx/conf.d/*.conf`（`$proxy_add_x_forwarded_for`）
- 问题：取 XFF 第一个值，攻击者可伪造 IP 绕过短信/邮箱/邀请/IP 限流。
- 修法：统一 `client_ip`：优先 `X-Real-IP`；或取 XFF 右侧第一个可信段。Nginx 改 `proxy_set_header X-Forwarded-For $remote_addr;`。
- 验收：带伪造 XFF 的请求，限流键/审计 IP 仍是真实出口 IP。

## T9 管理密钥拆分与审计 — P1

- 位置：`api/main.py` `_require_internal_key`(:1756)；`api/config.py`
- 问题：所有 admin 接口与短信共用 `SMS_INTERNAL_KEY`，无审计、无 IP 白名单。
- 修法：新增 `ADMIN_API_KEY`；admin 接口改 `_require_admin_key`；充值/冻结/改密/改价/改上游 Key/改开关写审计（actor、action、payload 摘要、时间）；生产可加来源 IP 白名单。
- 验收：短信与 admin 密钥独立；高危操作可追溯。

## T10 验证码体系加固 — P1

- 位置：`api/email_otp_memory.py`、`api/sms_otp_memory.py`、注册/重置调用处
- 问题：进程内存（多 worker 不共享、重启丢失）；校验无次数限制可爆破；`@example.com`/`*.local` 回显验证码。
- 修法：验证码落 DB/Redis；校验加失败次数限制（如 5 次/10 分钟锁定）；`is_prod()` 时强制不回显验证码并拒绝测试邮箱注册。
- 验收：2 worker 下发码可跨 worker 验证；连错 5 次锁定；生产注册接口不返回验证码。

## T11 登录爆破防护 — P2

- 位置：`api/main.py` `auth_login`(:921)
- 问题：无频控/锁定。
- 修法：按账号+IP 失败计数（DB/Redis），连续失败延迟或锁定，成功登录清零；与冻结逻辑区分。
- 验收：同一账号连续错误密码后需等待或验证码。

## T12 CORS 收紧 — P2

- 位置：`api/main.py` CORSMiddleware
- 问题：`CORS_ORIGINS` 默认 `*`。
- 修法：生产从配置读取白名单（www/console 域名）；本地保持 `*` 不影响。
- 验收：生产环境非白名单来源被拒。

## T13 免费共享池风控与告警 — P2

- 位置：`api/free_shared.py`
- 问题：每账号日 10 万 token/50 次免费走平台付费 Key，无上游用量告警，批量注册可转嫁成本。
- 修法：按 IP/设备指纹加共享池日配额；上游 token/费用小时级聚合告警；超阈值自动熔断。
- 验收：批量注册无法无限放大共享用量；上游成本有监控与告警。

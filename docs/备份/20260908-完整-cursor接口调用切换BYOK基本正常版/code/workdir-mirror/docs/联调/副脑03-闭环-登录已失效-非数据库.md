| 项 | 结论 |
|----|------|

根因仍是：主站签发 JWT 的 `SECRET_KEY` ≠ 行情官验签的 `AI24X_JWT_SECRET`（或新代码未进到正在跑的 `a-api-8001`）。

## 一步确认：新代码进进程了没有？

主脑已加探针。你执行：

```powershell
Set-Location C:\ai24x01
git pull origin master

# 磁盘上有没有
Select-String -Path p\a1\api\server\app\main.py -Pattern "session_resign|build_stamp|_session_from_identity_payload"

pm2 restart a-api-8001 --update-env
pm2 save
Start-Sleep -Seconds 2

# 本机环回
Invoke-RestMethod http://127.0.0.1:8001/api/public/build_stamp
# 公网
Invoke-RestMethod https://a.ai24x.com/api/public/build_stamp
```

期望两边都返回：`"stamp": "20260727-resign-v2"`、`"session_resign": true`  
若公网 404 / 没有 stamp → **Nginx 指错上游或未重启到新代码**。

## 双保险（推荐同时做）

在 `p\a1\api\server\.env` **增加一行**（值 = 主站 `api\.env` 的 `SECRET_KEY` 原文，记事本行级改）：

```env
AI24X_IDENTITY_JWT_SECRET=<与 api/.env 的 SECRET_KEY 完全相同>
```

然后：

```powershell
pm2 restart a-api-8001 --update-env
```

这样：即使仍转发主站 token，a1 也能验过；登录重签后也能验本站 token。

## 本机闭环（有测试账号时）

```powershell
# 登录拿 token 后立刻 /api/me（把手机号密码换成实测账号）
$login = Invoke-RestMethod http://127.0.0.1:8001/api/auth/login -Method POST -ContentType 'application/json' -Body '{"phone":"1xxxxxxxxxx","password":"你的密码"}'
$login.user.id
Invoke-RestMethod http://127.0.0.1:8001/api/me -Headers @{ Authorization = "Bearer $($login.token)" }
```

期望 `/api/me` 200。若这里都 401 → 把 `build_stamp` + 该错误贴回主脑。

## 二、配置步骤（OpenClaw 接入）

### 1. 编辑 openclaw.json

在 `models.providers` 下新增：

```json
{
  "models": {
    "providers": {
      "ai24x": {
        "baseUrl": "https://api.your-domain.com/v1",
        "api": "openai-completions",
        "apiKey": "<YOUR_AI24X_API_KEY>",
        "models": [
          {
            "id": "flash",
            "name": "AI24X Flash",
            "reasoning": false,
            "input": ["text"],
            "cost": { "input": 0.14, "output": 0.28, "cacheRead": 0.028, "cacheWrite": 0 },
            "contextWindow": 128000,
            "maxTokens": 4000,
            "api": "openai-completions"
          }
        ]
      }
    }
  }
}
```

### 2. 保存后等待热加载（约 3 秒），验证配置生效

### 3. 切换模型测试

```bash
/model ai24x/flash                      # 会话内切换
openclaw run --model ai24x/flash "接入成功"   # 子任务指定模型
```

## 三、验证命令

```bash
# 1) 接口连通

# 2) 模型列表

# 3) 对话验证

  -X POST -H "Content-Type: application/json" \
```

## 五、踩坑记录（实测，重要）

1. **baseUrl 必须带 /v1**：填 `https://api.your-domain.com/v1`（OpenClaw 拼 `{baseUrl}/chat/completions`）。
   填根域名会请求 `/chat/completions` → **405** → 自动重试约 3 次 → 表现「卡死」。
   ⚠️ LobeChat 等 UI 客户端同样填 `/v1`。
2. **Key 有效期**：测试 key 默认 7 天有效；到期后重新生成。
3. **Key 防截断**：复制 key 时注意别被终端/消息自动脱敏成 `sk-xxx…xxx`（带省略号）→ 401。
4. **次要限制**：① 流式是假流（先整段生成再切 SSE）② 平台 tools 为提示词兼容非原生 ③ max_tokens 上限 4000，contextWindow 勿配过大（建议 128000）。
5. **LobeChat 注意**：「使用 Responses 规范」开关需关闭（平台暂未实现 /v1/responses）。
6. **建议**：OpenClaw 测自家平台用**临时子 agent**，不要 pin 主会话（主会话保持稳定模型直连）。

## 六、常见错误排查

| 报错 | 原因 | 解决 |
|------|------|------|
| 401 invalid_api_key | key 错误/过期/被轮换 | console 重新生成 |
| 405 | baseUrl 填错路径（多拼了一层） | 按第五节修正地址 |
| 429 | 限流 | 稍后重试 / 检查套餐 |
| 404 路径不存在 | 接口路径拼错 | 确认使用 /v1/chat/completions |

## 七、平台侧改进路线（P0 三项）

1. **真流式（token 级 SSE）**：先整段生成再切 SSE 会感觉「卡住」
2. **原生 tools/function calling**：实现 OpenAI `tools` 标准协议（当前是提示词兼容）
3. **max_tokens 上限提升**：flash 4000 / pro 8192 / ultra 16384

P1：/v1/responses 兼容端点、usage 流式返回、错误信息细分（invalid_api_key / insufficient_quota / key_disabled）
P2：key 管理控制台补强、超时上限快速失败、文档更新

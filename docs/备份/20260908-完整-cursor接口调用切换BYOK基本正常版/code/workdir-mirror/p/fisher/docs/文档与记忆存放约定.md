# Fisher：文档 vs 记忆（Memory）— 放哪里好？

## 结论（推荐）

| 内容类型 | 推荐位置 | 原因 |
|----------|-----------|------|
| **全组织 / 多子项目** 的架构决策（不可逆或难逆） | 仓库根目录 **`memory/decisions/DEC-xxxx-*.md`** | 全仓唯一口径；与 `DEC-0007` 等并列，便于检索与审计。 |
| **本会话 / 指挥官** 的作战卡、当日收尾、Runbook | **`memory/daily/YYYY-MM-DD.md`**（根目录） | 与 `.cursor/rules` 里「作战卡」约定一致；跨子项目汇总方便。 |
| **山海渔产品策划、数值、合规、美术清单** 等「项目内圣经」 | **`p/fisher/docs/`** | 跟代码同 PR、同发布节奏；贡献者只 clone 子树时仍可读。 |
| **仅 Fisher 的临时草稿**（可选） | **`p/fisher/docs/archive/`** 或本地不提交 | 避免根 `memory` 被单项目草稿刷屏；定稿后迁入 `docs/` 或提炼为 DEC。 |

## 不推荐的做法

- 把 **组织级 DEC** 只写在 `p/fisher/docs/`：其他子项目与主站同事不易发现，易重复决策。  
- 把 **长篇产品稿** 只写在 `memory/daily/`：日报文件会膨胀，且与「决策」混在一起难维护。

## 与本项目已落盘文件的对应关系

- 默认身份与真源边界（组织决策）：`memory/decisions/DEC-0009-山海渔-Fisher身份默认独立与真源边界.md`  
- 产品完整规划：`p/fisher/docs/产品规划-山海渔-完整版-v1.0.md`  
- 工程架构汇总：`p/fisher/docs/架构与落地汇总.md`

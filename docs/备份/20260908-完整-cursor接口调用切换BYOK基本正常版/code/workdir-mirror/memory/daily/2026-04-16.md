### 任务包：部署发布（每次发版通用，副脑01/03/04按环境执行）

- **输入参数**：
  - 环境：`pre | cn | intl`
  - 目标版本：`rc-...`（pre）或 `prod-...`（cn/intl）
  - 是否 DB 变更：`yes | no`
- **固定动作（必须按顺序）**：
  - pre：
    - `git fetch --tags` → `git checkout <rc-tag>`
    -（如依赖变更）`pip install -r p/a/api/server/requirements.txt`
    -（如 DB 变更）执行迁移脚本并验收
    - PM2 `reload/restart`
    - 验收：`/health`、`/docs`
  - cn/intl：
    - **先 pg_dump 备份（必须回传备份路径）**
    - `git fetch --tags` → `git checkout <prod-tag>`
    -（如依赖变更）安装依赖
    -（如 DB 变更）先迁移再验收（生产先备份）
    - PM2 `reload/restart`
    - 验收：`/health`、`/docs`
- **回滚优先级（失败必做并回传）**：
  1) 先回滚代码到上一个稳定 tag/commit → PM2 reload
  2) 若迁移不可兼容：用发布前 `.dump` 执行 `pg_restore --clean --if-exists`
  3) PG 连接异常可止血：切回 SQLite（`AI24X_DB_KIND=sqlite`）→ 重启
- **回传输出（必须）**：
  - 当前 tag/commit
  - 备份文件路径（cn/intl 必须有）
  - `/health`、`/docs` 状态码
  - 若失败：回滚动作与结果

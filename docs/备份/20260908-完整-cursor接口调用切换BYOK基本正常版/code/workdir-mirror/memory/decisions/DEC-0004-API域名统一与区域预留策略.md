# DEC-0004：API 域名统一与区域预留策略（api.ai24x.com / api-cn / api-intl）

日期：2026-04-16  
范围：AI24X 统一 API（`api/`）对外入口、国内/国际环境隔离、运维灰度入口

## 背景

国内优先阶段需要尽量降低开发者接入成本，避免文档/SDK/控制台出现多套 API Base URL；同时又要为后期国际化（支付/合规/数据主权/上游供给差异）预留“可硬隔离与可切流”的抓手。

## 决策

### 1) 对外只公布一个入口（长期不变）

- **对外统一**：`api.ai24x.com`
- 官网、文档、SDK、示例、控制台全部以该域名为唯一入口（避免“国内/国际二等入口”的割裂感）。

### 2) 区域入口仅预留，不对外公布（运维/灰度/应急）

- `api-cn.ai24x.com`：cn 预留入口（可选）
- `api-intl.ai24x.com`：intl 预留入口（可选）

> 这两个域名用于灰度、切流、企业客户固定区域或合规要求时的硬隔离；默认情况下不出现在对外文档与控制台中。

### 3) 隔离的本质在“环境与数据”，不在域名

无论入口是否统一，cn 与 intl 必须做到：

- **分库**（用户/订单/账单/日志/密钥策略不混）
- **支付与结算配置隔离**（退款/争议处理链路独立）
- **上游供给与路由表隔离**（按区域维护）

## 落地位置（文档）

- `docs/站点与子项目规划.md` §7.1：对外统一 `api.ai24x.com`，`api-cn`/`api-intl` 仅预留不公开
- `docs/PORTS.md`：intl 端口段示例使用 `api-intl.ai24x.com`（预留）
- `docs/部署-域名与反向代理示例.md`：反代提示补齐“对外统一入口 + 预留入口”

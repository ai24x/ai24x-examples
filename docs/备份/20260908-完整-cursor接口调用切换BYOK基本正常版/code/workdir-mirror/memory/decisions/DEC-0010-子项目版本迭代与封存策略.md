# DEC-0010：子项目版本迭代与封存策略（p/a 封存、p/aN 迭代）

## 结论（唯一口径）

- `p/a`：**永久封存（只读归档）**，停止更新，只用于历史对照与应急回溯。
- 现行与后续版本：按阶段使用目录 **`p/a1`、`p/a2`、`p/a3`…** 迭代开发与上线。
- 对外域名永远指向“当前阶段版本”（例如 `a1.ai24x.com` → `p/a1/web`）。

## 背景（为什么要这么做）

- 多会话/多人协作下，老版本“顺手改一下”会造成口径分裂、线上行为不可追溯、回滚依据不可信。
- 目录阶段版本能同时满足：**可回溯**、**可并行**、**上线口径清晰**、**出事可快速回退**。

## 规则（允许/禁止）

### 封存版本（以 `p/a` 为例）

- **允许**：查历史、对照排障、应急回溯。
- **禁止**：任何功能/文案/配置变更。
- **唯一例外**：线上重大事故必须热修时，可在封存版本修补，但必须同步回补到当前主版本（`p/aN`），并记录原因与影响范围。

### 阶段版本（以 `p/a1`、`p/a2` 为例）

- 所有新需求、修复、优化只进入当前主版本目录。
- 进入下一“大阶段”时，复制出新目录继续迭代（保持上一阶段版本可对照/可回退）。

## Git 建议（增强防误改）

- 每次阶段冻结建议打 tag（示例：`a1.0-freeze`）。
- 可选：建立 `release/aN` 分支，仅接受紧急修复。

# DEC-0009：山海渔（Fisher）— 身份默认独立与真源边界

## 状态

已定稿（2026-04-20）

## 背景

Fisher（`p/fisher/`）为独立子项目；同时存在主站 `api/` 与子站 `p/a`（AI 行情官）的统一身份方案（见 DEC-0007）。需在「速度 / 风险 / 未来统一账号」之间选定默认边界。

## 决策

1. **默认策略（首版至产品验证前）**：Fisher **不强制**与主站 `api/` 做 JWT 级统一身份；小程序经 **微信 `code2session`**，由 **Fisher 自建 `fisher-api`** 建立会话与用户主档（`openid` / `unionid` 与内部 `user_id`）。
2. **游戏与经济真源**：金币、积分、渔获、仓库、渔市、冷却、排行等 **仅存在于 Fisher 自建数据库**，由 `fisher-api` 校验与落库；**不**写入主站 `api/` 业务表。
3. **管理后台**：与行情官分离；**独立域名、独立管理员密钥**（不与 `p/a` 的 `AI24X_ADMIN_KEY` 混用）。
4. **升级路径**：若后续需「全站一个 AI24X 账号」（www / 行情官 / 游戏同一用户、权益互通），再引入与 DEC-0007 对齐的身份契约；游戏数据仍留在 Fisher 库，仅增加平台 `sub` 映射与影子扩展表。届时应另发 DEC 修订本条或立新 DEC 引用本条。

## 理由

- 优先缩短闭环与降低首版耦合；避免主站发版节奏阻塞游戏上线。  
- 经济真源与身份真源解耦：即使未来统一身份，也不强制迁移游戏历史表到主站。

## 后果

- 早期用户与主站 `auth_users` **可能无自动关联**；若后期统一身份，需设计 **账号绑定 / 合并** 流程与数据迁移脚本（另项任务）。

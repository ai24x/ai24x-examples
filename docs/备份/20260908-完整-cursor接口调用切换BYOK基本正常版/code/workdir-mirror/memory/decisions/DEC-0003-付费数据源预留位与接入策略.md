# DEC-0003：付费数据源预留位与接入策略（AI 行情官｜灯塔版（1.01））

日期：2026-04-15  
范围：`p/a`（AI 行情官｜灯塔版（1.01））行情/K线数据源

## 背景

北交所/部分标的在公共数据源（腾讯/东财）侧可能出现空数据、超时、限流或结构变更，导致前端出现 `Failed to fetch` 等体验问题。为降低上线风险，需要规划“多源兜底 + 缓存 + 可观测 + 付费应急源”。

## 决策

- **短期（当前阶段）**：只做 日K/周K/月K；公共数据源 + 缓存/熔断/诊断先顶住。
- **付费数据源**：先 **预留扩展位**，默认关闭；后续如线上稳定性需要，再申请账号/Token 接入。
- **技术原则**：
  - 统一输出为“腾讯形状”payload，前端解析与聚合逻辑保持不变。
  - 付费源只需保证 **日K稳定**；周/月统一由日K聚合，减少供应商差异与成本。
  - 开关可配置：不开启不产生付费调用。

## 已落地内容（代码/运维）

- **缓存**：内存 + SQLite 持久化缓存（短期上游抖动可顶住；重启可恢复部分结果）
- **可观测**：`/api/status/market-data`（需 `X-Admin-Key`）
- **扩展位**：
  - 配置：`AI24X_PAID_PROVIDER=off|jqdata|gm|...`（默认 `off`）
  - 占位 Provider：`fetch_paid_kline()`（未实现，避免误用）

## 何时启用付费源（触发条件建议）

- 某市场/关键标的连续出现“空数据/超时/熔断”且影响用户
- 上线后需要更严格的可用性（SLA）或需要分钟级/实时数据
- 有明确的成本边界与调用配额评估结论

## 接入周期（经验值）

- 最小可用（日K+复权+缓存+开关）：0.5～2 天（拿到账号/Token 即可）
- 稳妥上线（监控/报警/质量门槛/灰度/演练）：2～5 天

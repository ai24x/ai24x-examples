# DEC-0005：文档口径与归档规则（唯一口径）

## 结论

- `docs/` 根目录 **只保留现行唯一口径**（统一主方案 + 方案卡片 + 索引）。
- 任何 **重复 / 多余 / 过时 / 容易误导的旧流程** 文档，一律移入 `docs/archive/obsolete/`（只存档，不参与当前规划与开发决策）。
- `docs/README.md` 只链接现行文档；历史内容只通过 `docs/archive/README.md` 进入。

## 背景（为什么要这么做）

项目同时涉及多环境（预演/国内/国际）与多策略（SQLite↔PostgreSQL 可回滚）。如果旧文档留在根目录，新手在发布/回滚时极易误读、按错，风险高。

## 落地规则

详见：`docs/文档规则-唯一口径与归档.md`

## 影响范围

- `docs/`、`docs/archive/`、`docs/_compat/` 的组织方式与索引策略
- 以后所有“帮助说明/部署指令/发布卡片”的写法与保存位置

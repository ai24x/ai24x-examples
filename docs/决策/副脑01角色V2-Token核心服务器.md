# 副脑01 · 角色定位（V2优化版）

> **硬件**：4核8G 云端（五脑中配置最高）
> **新定位**：Token 平台核心服务器 + 缓存代理 + 预发布环境 + 质量管道

---

## 为什么调整

原方案只让副脑01做代码 Review 和测试，4核8G 严重浪费。优化后它变成 Token 平台的**第一道关卡**。

---

## 四大职责

| 优先级 | 职责 | 资源占用 |
|--------|------|---------|
| P0 | **① Token API 核心服务** · 跑 api/main.py + 模型路由网关 | ~30% |
| P0 | **② 缓存代理层** · 相同请求命中缓存→不调模型→省钱 | ~20% |
| P1 | **③ 预发布环境** · 代码先部署到副脑01测通→再推副脑03生产 | ~20% |
| P2 | **④ 质量管道（后台）** · 自动 Pull + Review + 测试 + 飞书报告 | ~5% |

### ① Token API 核心服务
- 运行 `/v1/chat/run` 模型路由网关
- 聚合 DeepSeek / Kimi / 智谱等多家模型
- 用户鉴权 + 限流 + 计费

### ② 缓存代理层（最值钱的功能）
- 相同请求返回缓存结果，不重复调模型 API
- 命中率预估 20-30%
- 按每月 100 万次请求算，缓存命中 30% = 每月省 ¥500-1000

### ③ 预发布环境
- 代码先在副脑01 部署测试
- 验证通过后再通知副脑03 上线生产
- 避免直接上生产出问题

### ④ 质量管道（后台不阻塞）
```
Cursor 推送 GITEE → 副脑01 自动拉取 → 跑 Review + 测试 
→ 飞书报告（不阻塞任何流程）
```

## 工作流

```
用户请求 → ①副脑01 API网关 → 缓存命中？→ 直接返回
                         ↓ 未命中
                    ②调模型API → ③缓存结果 → ④计费扣减
```

```

→ 副脑01后台自动Review（不阻塞）
→ 你要发版时：先部署到副脑01 预发布验证
→ 通知副脑03 上线生产
```

# 子项目套餐统一支付中台 · 设计文档（2026-08-28）

> 状态：方案待雷总拍板｜作者：司令｜关联：DEC-0013（账单三车道）、统一账单 Step1/Step2（open credits 跳 www）

## 一句话结论

**core 升级为「统一支付中台」：所有子项目的套餐订单都进 core 订单表（`product` 区分），支付/Webhook/到账在 www 完成，子项目只暴露「开通权益」回调接口；后台一处查全所有订单。**

## 一、现状盘点（三车道）

| 车道 | 在哪买 | 订单库 | 履约 | 后台可见 |
|------|--------|--------|------|----------|
| AI Gateway credits（托管） | www Account | core `token_pay_orders`（product=token） | core 本地入账 | ✅ token-admin 可查 |
| Markets VIP | www Account | core `token_pay_orders`（product=markets） | core 签名回调 markets `/api/subscribe/fulfill` | ✅ 可查 |
| **BYOK 服务费** | open（www 不卖，DEC-0013） | **open 库 `token_pay_orders`（product=byok）** | open 本地 `activate_subscription` 写 `byok_subscriptions` | ❌ **www 后台查不到** |

痛点：BYOK 订单独立在 `ai24x_open_cn`，token-admin「支付与订单」看不到；用户跨站查单要跳 open；后续新子项目会继续复制这种割裂。

## 二、目标架构

```
                 ┌───────────────────────── core（www / api.ai24x.com）────────────────────────┐
用户 → 任意子站 → │ 下单 API（Bearer 或服务代理）→ token_pay_orders（product=byok/xxx）        │
                 │ Dodo checkout → 支付 → webhook → _fulfill_order_row                        │
                 │   ├─ token   → 本地入账（BillingLedger）                                    │
                 │   ├─ markets → 签名回调 markets /api/subscribe/fulfill                     │
                 │   └─ byok    → 签名回调 open /v1/admin/byok/fulfill（新增）                 │
                 └───────────────┬────────────────────────────────────────────────────────────┘
                                 │ X-Admin-Key（共享密钥，open .env 已同配）
                                 ▼
                 ┌───────────────────────── open（BYOK 子服务）──────────────────────────────┐
                 │ /v1/admin/byok/fulfill：email 找本地用户 → activate_subscription 幂等激活 │
                 │ byok_subscriptions 仍是权益权威（订阅状态/到期日 open 自己管）             │
                 └────────────────────────────────────────────────────────────────────────────┘
```

原则：
1. **支付统一**：收银、订单、Webhook、到账、退款都在 core；子项目不碰钱、不碰 Dodo 密钥。
2. **权益自治**：订阅/额度/使用状态仍在各子项目库，core 只负责「支付成功后通知开通」。
3. **后台一处查全**：token-admin 按 `product` 筛选即可看到全部子项目订单（已有筛选+用户标注能力）。

## 三、BYOK 迁移设计（首个接入案例）

### 3.1 下单
- open 前端维持现状调 open 后端 `POST /v1/billing/dodo/order`（界面零改动）。
- open 后端改为**服务代理**：带 `X-Admin-Key` 调 core 新端点 `POST /v1/admin/billing/dodo/order`（body：`email/phone` + `plan` + `product=byok`）。
- core 端点：用 email/phone 查 `auth_users`（无则 409 报错）→ `create_dodo_order(product="byok")` → 建订单 + Dodo checkout → 返回 `checkout_url`。
- open 后端把 `checkout_url` 原样返回前端（`out_trade_no` 一并返回）。

### 3.2 支付与履约
- Dodo 支付成功 → Webhook 打到 www core（现有端点，已配 `payment.succeeded/failed`）。
- core `_fulfill_order_row` 新增 `product=byok` 分支 → `_fulfill_byok_remote`（复制 markets 回调范式）：
  `POST open/v1/admin/byok/fulfill`，header `X-Admin-Key`，body：`email` + `plan` + `source_order=out_trade_no` + `channel_tag`。
- open 端点：校验密钥 → email 找本地用户 → `activate_subscription`（**幂等**：`source_order` 已存在或订阅已激活则直接返回 ok）→ 返回 `{"code":0}`。
- core 收到 `code=0` 才算履约成功；失败不标 paid，随「查单/对账」重试（与 markets 同机制）。

### 3.3 查询/回跳
- open 前端支付回跳/轮询：调 open 后端 `POST /v1/billing/dodo/query` → open 转发 core 查订单状态（服务代理）；订阅是否开通以 open 本地 `byok_subscriptions` 为准（权益权威）。
- open 订单列表：存量订单仍显示；新增订单从 core 代理拉取合并展示，标注「www 统一支付」。

### 3.4 存量兼容
- open 现有 Dodo Webhook 端点**保留**：只处理 open 库已有订单；core byok 订单不在 open 库 → open 侧幂等忽略（需补「订单不存在→返回 200 忽略」）。
- core Webhook 收到 open 存量订单 → core 库无此单 → 幂等忽略（需补同逻辑，核对现状）。
- 迁移前已开通的 BYOK 订阅不受影响（open 库权益不动）。

## 四、子项目接入标准（固化，后续子项目照抄）

新子项目（如未来 AI 行情官国际版内购、数据 API 订阅等）接入统一支付：

1. **注册产品**：core `api/pay_products.py` `PRODUCTS` 加一项（plans、`price_usd`、`dodo_product_id`、`fulfill.url` + `fulfill.secret`）。
2. **商品同步**：Dodo 后台建商品或跑自动同步 → 回写 `dodo_product_id`（改价走雷总审批）。
3. **子服务履约端点**：实现 `POST /fulfill`（鉴权 header + `out_trade_no/user/plan/source`，**幂等**）。
4. **前端接入**：复用 www 控制台统一支付弹窗（多通道选择已具备）；子站独立购买页 = 后端服务代理 core 下单（同 BYOK 模式）。
5. **后台零开发**：token-admin「支付与订单」按 `product` 筛选自动可见，用户标注自动生效。
6. **验收**：下单 → 支付 → Webhook → 履约 → 后台订单可见 → 权益激活，五步全通。

## 七、风险与注意

- **双 Webhook**：open 与 www 两个 Dodo Webhook 端点都会收到全部事件 → 双方必须「未知订单幂等忽略」，否则日志噪音/误报。
- **账号映射**：core email ↔ open 本地用户；理论上注册即同步，若缺用户则履约报错 → 后台人工补。
- **密钥**：`X-Admin-Key` 用现成 ADMIN_API_KEY（open/core 同配，记忆六十八），不入 git。
- **改价红线**：BYOK 价格/商品 ID 改动仍走雷总审批（DEC-0013）。

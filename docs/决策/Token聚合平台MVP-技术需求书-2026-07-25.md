## 一、项目定位

**一句话**：国内中小开发者的一站式多模型 API 聚合平台。

**核心价值**：把 DeepSeek、Kimi、智谱、豆包、MiniMax 等国产模型的 API 统一到一个入口、一套密钥、一个计费体系下。

**目标形态**：
```
开发者注册 → 获取统一 API Key → 调 /v1/chat/run → 按 Token 扣费
              ↓
      背后自动路由到最优模型/最低价格
```

## 二、模型路由分层策略

### 总原则：免费优先 → 低价次之 → 高价兜底

| 层级 | 策略 | 模型 | 价格 ¥/M token | 说明 |
|------|------|------|---------------|------|
| L0 | **免费引流** | GLM-4-Flash（智谱） | ¥0 | 免费额度先用光 |
|  |  | SiliconFlow（DS-V4-Flash） | ¥0.5/1.0 | 低价通道 |
| L1 | **白菜主力** | DeepSeek Flash 直连 | ¥0.14/0.28 | 日常 90% 流量 |
| L2 | **VIP 增强** | DeepSeek Pro | ¥1.74/3.48 | VIP 用户 |
|  |  | 豆包 Pro（火山引擎） | ¥3.0/9.0 | 兜底 |
| L3 | **扩展国产** | Kimi K3 | ¥2/8 | 已接入备用 |
|  |  | MiniMax | 待接入 | 国产候选 |
|  |  | 通义千问 | 待接入 | 国产候选 |
| L4 | **国际模型** | GPT-4o / Claude（二期） | 二期 | 出海阶段 |

### 容错链（按首次实现简化为两套）

```
FREE 请求 → SiliconFlow →  DeepSeek Flash → GLM-4-Flash → 503
              ↓ 3s超时     ↓ 3s超时          ↓ 3s超时
                    逐级 fallback

VIP 请求 → DeepSeek Flash → DeepSeek Pro → 豆包 Pro → Kimi K3 → 503
              ↓ 5s超时       ↓ 5s超时        ↓ 5s超时     ↓ 5s超时
```

### 熔断规则（MVP 简化版）
- 连续失败 5 次 → 熔断 60 秒
- 熔断结束后放 1 个探测请求
- 恢复后自动切回优先链路

## 四、三接口详细设计

### 4.1 API Keys (`/v1/keys`)

```
GET  /v1/keys           → 当前用户的 Key 列表
POST /v1/keys           → 创建新 Key（传 name）
DELETE /v1/keys/{id}    → 删除指定 Key
```

**数据模型**（新建表 `api_keys`）：
```sql
CREATE TABLE api_keys (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES auth_users(id),
    name VARCHAR(64) NOT NULL DEFAULT '默认密钥',
    key VARCHAR(128) UNIQUE NOT NULL,    -- sk-xxxxx
    created_at TIMESTAMP DEFAULT NOW(),
    last_used_at TIMESTAMP,
    is_active BOOLEAN DEFAULT TRUE
);
```

### 4.2 计费 (`/v1/billing`)

```
GET  /v1/billing/balance   → 余额（token数）
POST /v1/billing/topup     → 充值（人工确认后调用）
GET  /v1/billing/usage     → 用量明细（按天/模型）
```

**计费逻辑**：
- 免费用户：每月赠 10,000 token
- VIP 用户：¥19.9/月 → 约 500,000 token/天
- 扣费时机：`/v1/chat/run` 返回后，按 model + 实际 token 数扣减
- 余额不足 → HTTP 402

**数据模型**（新建表 `billing_records`）：
```sql
CREATE TABLE billing_records (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES auth_users(id),
    type VARCHAR(16) NOT NULL,    -- 'consume' / 'topup' / 'bonus'
    amount INTEGER NOT NULL,       -- 正=充值 负=消耗
    model VARCHAR(32),             -- 消费时记录模型
    tokens INTEGER,                -- 消费时记录token数
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 4.3 推荐返利 (`/v1/referrals`)

```
GET  /v1/referrals/code       → 我的邀请码
GET  /v1/referrals/stats      → 邀请统计
GET  /v1/referrals/earnings   → 返利明细
```

**返利规则**：
- 一级返利 10%（被邀请人首次充值金额）
- 二级返利 2%（被邀请人邀请的下一个人充值）
- 返利可提现或抵扣 API 费用

**数据模型**（新建表 `referrals`）：
```sql
CREATE TABLE referrals (
    id UUID PRIMARY KEY,
    referrer_id UUID NOT NULL REFERENCES auth_users(id),
    referee_id UUID NOT NULL REFERENCES auth_users(id),
    level INTEGER NOT NULL DEFAULT 1,     -- 1=一级 2=二级
    reward INTEGER NOT NULL,               -- 返利金额（分）
    status VARCHAR(16) DEFAULT 'pending',  -- pending / settled
    created_at TIMESTAMP DEFAULT NOW()
);
```

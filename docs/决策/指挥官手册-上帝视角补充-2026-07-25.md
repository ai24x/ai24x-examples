## 补充 ① · 文件存储规则

所有新增文件、生成产物一律写入 E 盘，永不写 C 盘。

| 内容 | 存储路径 |
|------|---------|
| Canvas HTML 文件 | `E:\AI24X\canvas\` |
| 帮助指南文档 | `E:\AI24X\帮助指南\` |
| 项目工程代码 | `E:\AI24X\ai24x-website\` |
| OpenClaw 配置 | `C:\Users\Admin\.openclaw\` （仅配置文件，系统限制） |
| 工作记忆 | `C:\Users\Admin\.openclaw\workspace\memory\` （仅文本，可忽略） |

> 规则：除了 OpenClaw 自身的配置文件和轻量级工作记忆外，其他一切产出存 E 盘。

## 补充 ② · 静默时段策略

| 时段 | 行为 |
|------|------|
| 08:00-23:00 | 正常模式：Heartbeat 巡检、晨晚报推送、主动汇报 |
| 23:00-08:00 | 静默模式：只收不发、不推消息、不主动打扰雷总 |
| 紧急（全天） | 服务器宕机 · 数据库故障 · 支付异常 → 即刻飞书告警 |
| 非紧急推迟 | 成本日报 · 项目进展 · 非关键告警 → 静默缓存，08:00 后合并推送 |

## 补充 ③ · 告警升级矩阵

| 级别 | 事件 | 响应 |
|------|------|------|
| 🟢 INFO | 备份成功 · 日报生成 · 任务完成 | 记录日志 + 合并到下次晨晚报 |
| 🟡 WARN | 模型切换 · CPU >80% · 备份延迟 · API 慢响应 | 飞书推送（静默时段缓存） |
| 🟠 ERROR | 副脑离线 · 模型全挂 · 磁盘 >90% | 飞书推送 + @雷总 |
| 🔴 CRITICAL | 数据库宕机 · 支付故障 · 公网不可达 | 飞书 @雷总 + 连续提醒直到确认 |

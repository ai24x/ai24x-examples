# 文档规则：唯一口径与归档（长期有效）

目标：**永远先打开 `docs/README.md`**，再进对应子目录；杜绝根目录散落多份总纲。

---

## 1) 目录分层（强制）

| 路径 | 用途 |
|------|------|
| **`docs/README.md`** | 唯一总索引 |
| **`docs/规划/`** | 现行总纲、产品/市场 |
| **`docs/开发/`** | 接口任务、实现说明 |
| **`docs/决策/`** | Cursor 协作、拍板记录 |
| **`docs/联调/`** | DeepSeek / SMTP / 支付 / 安全 |
| **`docs/历史/`** | 旧版总纲（只读） |
| **`docs/archive/`** | 更早过时材料 / obsolete / legacy-reports |
| **`docs/` 根下运维文** | 端口、PM2、Nginx、a1 方案卡片等（逐步可再归入 `运维/`） |
| **`memory/daily/`** | 当日作战卡（可执行，不替代总纲） |

仓库**根目录**不得维护总纲/任务正文；仅允许短 stub 指向 `docs/...`。

---

## 2) 什么必须进历史/归档

- 被新总纲替代的旧版（v3.3 / v3.4…）→ `docs/历史/`
- 重复、冲突、一次性救火文 → `docs/archive/obsolete/` 或 `legacy-reports/`

---

## 3) 现行 Token 口径三件套

1. `docs/规划/开发总纲-AI24X-API-v3.5.md`
2. `docs/开发/开发任务-Token聚合MVP.md`
3. `docs/决策/Cursor协作流程指南.md`

岗位与发版：`docs/规划/主脑副脑岗位与国际Token供给-1.0.md`（v1.0.6+）· `docs/联调/Token发版-Gitee与副脑04.md`（正式；03 文为备份说明）

---

## 4) 修改纪律

- 改口径：改 `规划/` 总纲，并同步 `docs/README.md` 链接
- 改历史：原则上不改；顶部可加「仅存档」
- 新帮助文档：先归类到 规划/开发/决策/联调，再写
- 文件名：规划类用中文；代码路径保持英文

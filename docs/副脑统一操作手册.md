# 副脑统一操作手册

## 🎯 标准化开发流程
**核心原则**: 本地 ai24x01 = 线上 ai24x01

## 📌 固定配置
- **Gitee 仓库**：`https://gitee.com/ai24x/ai24x-website.git`
- **访问令牌**：在 Gitee **个人设置 → 私人令牌** 自行创建；**仅保存在本机或环境变量，勿写入仓库、勿提交 Markdown**
- **本机/服务器根目录（唯一口径）**：`C:\ai24x01`
- **默认分支（唯一口径）**：优先使用 `main`（如仓库仍为 `master`，以实际为准）

## ✅ 每次更新必做清单（精简版）

见 `docs/每次更新必做清单-1.0.md`（可直接转发给副脑执行）。

## 🔄 强制操作流程

### 1. 首次克隆（只做1次）
```powershell
Set-Location C:\
git clone https://gitee.com/ai24x/ai24x-website.git ai24x01
Set-Location C:\ai24x01
```

### 2. 每次开发前（防冲突）
```powershell
Set-Location C:\ai24x01
git pull
```

### 3. 开发完成后
```powershell
Set-Location C:\ai24x01
git add -A
git commit -m "update"
git push
```

## 📁 目录结构规范
```
ai24x01/  (必须一致)
├── api/       后端接口
├── web/       前端页面
├── db/        数据库SQL
├── config/    配置
├── scripts/   脚本
└── docs/      文档
```

## 🚨 铁律
1. **结构必须一致**，不许乱建目录
2. **每次开发前必须git pull**，防止冲突
3. **提交信息要清晰**，说明更新内容
4. **使用私人令牌** 进行 HTTPS 推送时认证（令牌不放仓库）
5. **端口口径唯一来源**：一律以 `docs/PORTS.md` 为准；任何“临时改端口”必须先更新 `docs/PORTS.md` 再执行（避免副脑01/03 端口漂移）
6. **PM2 进程名必须按端口命名**：例如 `a1-web-18001`、`a1-api-18011`、`core-8000`（便于一键重启、避免重启错服务）
   - 生产（副脑03）统一：`a-api-8001`、`core-api-8002`（见 `ecosystem.config.cjs`）
7. **数据库变更必须可迁移/可回滚**：只要涉及 PostgreSQL 表结构/索引/字段变更，必须提供迁移脚本并先在副脑01跑通，再上副脑03；上线前必须备份（`pg_dump`）
8. **副脑默认不改代码（只做环境配置/运维落地）**：除非主脑明确要求“改某文件某几行”，否则副脑任务范围仅限：
   - `.env`（仅本机私密，不入库）
   - Nginx 反代/证书
   - PM2 启停/重启/日志
   - 门禁验收（health/docs/关键 URL）
9. **`p/a` 永久封存不再动**：`p/a1` 是唯一维护版本；`p/a` 仅用于只读对照（见 `p/a/ARCHIVED.md`）

## 🧭 环境矩阵（唯一口径：副脑只按表操作）

> 目的：把“域名/端口/目录/DB 名”一次性固定，避免副脑01/03 因口径漂移导致 502、跑错服务、误用错误数据库配置。

## 🧱 数据库唯一口径：全环境强制 PostgreSQL（PQ），SQLite 禁用

- **主站 core（`api/`）**：`DATABASE_URL` 必须为 `postgresql://...`（代码层已禁用 sqlite）。
- **a1 / a（行情官）**：`AI24X_DB_KIND` 必须为 `pgsql` 且必须配置 `AI24X_DATABASE_URL=postgresql://...`（代码层已禁用 sqlite）。
- 结论：任何机器出现“还能跑 sqlite”，都视为配置未覆盖或跑错目录，必须按本手册重新对齐。

## 🤖 OpenClaw 指令规范（防“跑错目录/更新不全”事故）

背景：OpenClaw 默认可能在 `C:\Users\Administrator\.openclaw\workspace` 执行命令；如果不强制进入 `C:\ai24x01`，会出现“看似执行了更新，但实际更新的是另一份目录”的事故。

### 1) 固定根目录（唯一口径）

- 副脑01/03 统一根目录：`C:\ai24x01`
- **所有 OpenClaw 指令必须使用绝对路径**，并在开头做硬校验；校验失败必须立刻停止。

### 2) 通用指令头（必须粘贴在每次任务最前面）

PowerShell：

```powershell
$TARGET="C:\ai24x01"

if(!(Test-Path $TARGET)){ throw "目标目录不存在：$TARGET" }
Set-Location $TARGET
if((Get-Location).Path -ne $TARGET){ throw "未进入目标目录，当前为：$((Get-Location).Path)" }

# 防止进错仓库：必须是 git 仓库
git rev-parse --is-inside-work-tree | Out-Null

# 可选：remote 粗校验（防止进入了别的 repo）
$rem = (git remote -v | Out-String)
if($rem -notmatch "ai24x"){ throw "疑似进入错误仓库：remote 不匹配`n$rem" }

Write-Host "OK: cwd=$((Get-Location).Path)"
```

### 3) 危险命令二次校验（必须）

任何包含以下命令的任务，执行前都必须再次输出并确认：

- `pwd` / `Get-Location`
- `git rev-parse --show-toplevel`
- `git remote -v`

危险命令包括：`git reset --hard`、`git clean -fd`、删除/覆盖配置文件、批量移动目录等。

### 4) 必回传的 3 个证据（每次任务末尾必须输出并贴回）

- 当前目录：`Get-Location`
- 代码版本：`git rev-parse --short HEAD`
- 服务状态：`pm2 list`（或关键 URL 健康检查状态码）

## 🚀 副脑01/03：统一升级指令（程序 + 数据库 + 校验门禁）

适用：副脑01预演 / 副脑03生产。目标：**避免 502（Nginx 反代到后端失败）**、避免“更新了但实际没生效”。

### 1) 升级步骤（可复制执行，生产慎用 reset）

> 预演机（副脑01）可用 `reset/clean` 强制对齐远端；生产机（副脑03）默认不建议强制覆盖，除非已确认是镜像目录且无手工改动。

```powershell
# 0) 固定目录 + 硬校验（必须）
$TARGET="C:\ai24x01"
if(!(Test-Path $TARGET)){ throw "目标目录不存在：$TARGET" }
Set-Location $TARGET
if((Get-Location).Path -ne $TARGET){ throw "跑错目录：$((Get-Location).Path)" }
git rev-parse --is-inside-work-tree | Out-Null

# 1) 更新代码
git fetch --all
git pull
git rev-parse --short HEAD

# 2) 如本次含 DB 变更：先备份（必须回传备份路径）
# pg_dump -Fc -Z 6 -f "E:\BACKUP\pre\pg\ai24x01-$((Get-Date).ToString('yyyyMMdd-HHmmss')).dump" "postgresql://<USER>:<PWD>@127.0.0.1:5432/<DBNAME>"

# 3) 切换到 a1（避免仍跑旧版 p/a；若列表里没有则跳过）
pm2 stop a-api-18031
pm2 stop a-web-18001
pm2 restart core-8000
pm2 restart a1-api-18011
pm2 restart a1-web-18001
pm2 save
pm2 list

# 4) 硬校验门禁（必须全 200，否则不要宣称“升级成功”）
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:18011/health").StatusCode
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:18011/api/kline?secid=1.000001&period=day&count=10").StatusCode
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8000/login.html").StatusCode
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:18001/index.html").StatusCode
```

## 📦 env-pack（推荐）：副脑只“覆盖配置 + 重启 + 门禁”，不手工点来点去

目标：减少重复配置操作，避免副脑改错/漏改。做法：由主脑维护一份**不入库**的“环境包”，副脑只负责按命令覆盖到固定路径。

### 1) 环境包内容（两份文件）

- **core**：`api.env` → 覆盖到 `C:\ai24x01\api\.env`
- **a1**：`a1.env` → 覆盖到 `C:\ai24x01\p\a1\api\server\.env`
- （副脑03 如需 a 灯塔版：另加）`a.env` → 覆盖到 `C:\ai24x01\p\a\api\server\.env`

> 注意：`*.env` 含口令/密钥，**禁止提交 Git**；仅走内部安全渠道分发。

### 2) 副脑执行（唯一口径）

PowerShell（副脑01/03 通用）：

```powershell
$ROOT="C:\ai24x01"
if(!(Test-Path $ROOT)){ throw "目标目录不存在：$ROOT" }
Set-Location $ROOT

# 0) 覆盖配置（按你收到的 env-pack 路径替换）
Copy-Item -Force "C:\env-pack\api.env" "$ROOT\api\.env"
Copy-Item -Force "C:\env-pack\a1.env"  "$ROOT\p\a1\api\server\.env"

# 1) 重启
pm2 restart core-8000
pm2 restart a1-api-18011
pm2 restart a1-web-18001
pm2 save

# 2) 门禁（必须全 200）
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8000/docs").StatusCode
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:18011/health").StatusCode
```

### 3) env-pack 的“最少环境差异项”（副脑只允许改这些）

- **域名类**：Nginx 的 `server_name` 与证书（WACS/证书路径）
- **DB 连接串**：
  - core：`api\.env` 的 `DATABASE_URL`
  - a1：`p\a1\api\server\.env` 的 `AI24X_DATABASE_URL`（库名按环境矩阵：`ai24x_a_pre` / `ai24x_a_cn`）
- **短信内部密钥对齐**：
  - core：`SMS_INTERNAL_KEY`
  - a1/a：`AI24X_SMS_INTERNAL_KEY`
  - 要求：两边字符串必须完全一致
- **微信支付私钥路径**（如联调支付）：`AI24X_WECHAT_MCH_PRIVATE_KEY_PATH`（按本机真实路径）

## 🧾 OpenClaw 一键指令（专属：副脑01 / 副脑03）

> 原则：副脑只做环境配置与运维落地（`.env` / Nginx / PM2 / 门禁 / 备份）。禁止改任何代码文件。

### 副脑01（预演）专属：w1 + a1（微信支付/短信/HTTPS 一把梭）

目标：
- 域名：`https://w1.ai24x.com`、`https://a1.ai24x.com` 可访问（无“不安全”）
- a1 API：`https://a1.ai24x.com/api/`、`/docs`、`/health` OK
- 微信回调：`https://a1.ai24x.com/api/billing/wechat/notify` 可达（生产必须不跳过验签）
- DB：全 PQ；a1 库名 `ai24x_a_pre`；core 库名 `ai24x_core_pre`

PowerShell（整段复制执行）：

```powershell
# ===== 0) 硬校验：必须在 C:\ai24x01 =====
$ROOT="C:\ai24x01"
if(!(Test-Path $ROOT)){ throw "目标目录不存在：$ROOT" }
Set-Location $ROOT
if((Get-Location).Path -ne $ROOT){ throw "跑错目录：$((Get-Location).Path)" }
git rev-parse --is-inside-work-tree | Out-Null
Write-Host "OK: cwd=$((Get-Location).Path)"

# ===== 1) 拉代码（只 pull，不改代码）=====
git pull
git rev-parse --short HEAD

# ===== 2) 覆盖 env-pack（只用 C:\env-pack；由主脑下发）=====
if(!(Test-Path "C:\env-pack\api.env")){ throw "缺少 C:\env-pack\api.env" }
if(!(Test-Path "C:\env-pack\a1.env")){ throw "缺少 C:\env-pack\a1.env" }
Copy-Item -Force "C:\env-pack\api.env" "$ROOT\api\.env"
Copy-Item -Force "C:\env-pack\a1.env"  "$ROOT\p\a1\api\server\.env"

# ===== 3) DB 检查/建库（已存在则跳过；口径：ai24x_core_pre / ai24x_a_pre）=====
$psql = (Get-Command psql -ErrorAction SilentlyContinue).Source
if(-not $psql){
  $psql = "C:\Program Files\PostgreSQL\15\bin\psql.exe"
}
if(!(Test-Path $psql)){ throw "未找到 psql，请安装 PostgreSQL 15 并确保 psql 可用：$psql" }

# 注意：以下用本机超级用户/管理员连本地 5432；若你用其他账号，请自行替换 -U
$pgUser = "postgres"
$dbs = @("ai24x_core_pre","ai24x_a_pre")
foreach($db in $dbs){
  $exists = & $psql -h 127.0.0.1 -p 5432 -U $pgUser -d postgres -tAc "SELECT 1 FROM pg_database WHERE datname='$db';"
  if(($exists|Out-String).Trim() -ne "1"){
    Write-Host "Creating database: $db"
    & $psql -h 127.0.0.1 -p 5432 -U $pgUser -d postgres -c "CREATE DATABASE $db;"
  } else {
    Write-Host "DB exists: $db"
  }
}

# ===== 4) 免费 HTTPS（WACS 多域名）=====
# 4.1 Nginx 80 必须放行 /.well-known/acme-challenge/ -> C:\nginx\acme
# 4.2 WACS 签发（若已签过可重复运行；会复用/续期）
if(Test-Path "C:\wacs\wacs.exe"){
  & "C:\wacs\wacs.exe" --target manual --host a1.ai24x.com --host w1.ai24x.com --validation filesystem --webroot "C:\nginx\acme" --store pemfiles --pemfilespath "C:\nginx\ssl\ai24x-multi" --installation none
} else {
  Write-Host "WARN: 缺少 C:\wacs\wacs.exe，跳过自动签证书"
}

# 4.3 reload nginx
if(Test-Path "C:\nginx\nginx.exe"){
  & "C:\nginx\nginx.exe" -t
  if($LASTEXITCODE -eq 0){ & "C:\nginx\nginx.exe" -s reload }
} else {
  Write-Host "WARN: 缺少 C:\nginx\nginx.exe，跳过 nginx reload"
}

# 4.4 续期自检（每 3 天一次 renew）
if(Test-Path "C:\wacs\wacs.exe"){
  schtasks /Create /F /SC DAILY /MO 3 /TN "WACS-Renew" /TR "\"C:\wacs\wacs.exe\" --renew --quiet" /ST 03:20 | Out-Null
}

# ===== 5) PM2（a1 口径）=====
pm2 start ecosystem.local.config.js
pm2 stop a-api-18031
pm2 stop a-web-18001
pm2 restart core-8000
pm2 restart a1-api-18011
pm2 restart a1-web-18001
pm2 save
pm2 list

# ===== 6) 门禁（必须回传）=====
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8000/docs").StatusCode
(Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:18011/health").StatusCode
(Invoke-WebRequest -UseBasicParsing "https://a1.ai24x.com/health").StatusCode
(Invoke-WebRequest -UseBasicParsing "https://w1.ai24x.com/").StatusCode
```

## 🔐 HTTPS（免费证书）唯一口径：Windows + Nginx + win-acme（WACS）

目标：让预演/生产域名都无“不安全”提示，并让微信回调 `https://<a1>/api/billing/wechat/notify` 可用。

### 0) 固定约定

- Nginx：`C:\nginx\nginx.exe`
- ACME webroot：`C:\nginx\acme\`
- 证书输出（PEM）：`C:\nginx\ssl\ai24x-multi\`（多域名一张证书）
- WACS：`C:\wacs\wacs.exe`

### 1) Nginx（80）必须放行 ACME 验证路径（不能被 301 吞掉）

在每个域名的 `listen 80` server 段里加：

```nginx
location ^~ /.well-known/acme-challenge/ {
  root C:/nginx/acme;
  default_type text/plain;
}
```

### 2) WACS 签发多域名证书（示例：副脑01）

副脑01域名：`a1.ai24x.com` + `w1.ai24x.com`

```powershell
C:\wacs\wacs.exe --target manual --host a1.ai24x.com --host w1.ai24x.com --validation filesystem --webroot "C:\nginx\acme" --store pemfiles --pemfilespath "C:\nginx\ssl\ai24x-multi" --installation none
```

副脑03域名：`a.ai24x.com` + `www.ai24x.com`（同理替换 `--host`）

### 3) Nginx（443）挂证书

在对应 `listen 443 ssl;` 段里：

```nginx
ssl_certificate     C:/nginx/ssl/ai24x-multi/fullchain.pem;
ssl_certificate_key C:/nginx/ssl/ai24x-multi/privkey.pem;
```

### 4) 续期自检（建议每 3 天一次）+ 续期后自动 reload Nginx

创建脚本：`C:\wacs\reload-nginx.ps1`

```powershell
& "C:\nginx\nginx.exe" -t
if ($LASTEXITCODE -ne 0) { exit 1 }
& "C:\nginx\nginx.exe" -s reload
```

计划任务（每 3 天一次 renew）：

```powershell
schtasks /Create /SC DAILY /MO 3 /TN "WACS-Renew" /TR "\"C:\wacs\wacs.exe\" --renew --quiet" /ST 03:20
```

并在 WACS 为该证书配置“续期成功后执行脚本”：`powershell -ExecutionPolicy Bypass -File C:\wacs\reload-nginx.ps1`

### 5) HTTPS 验收门禁（必须）

- `https://<domain>/health` 200
- `https://<domain>/docs` 可打开
- `https://<a1-domain>/api/billing/wechat/notify`：微信商户平台回调能打通（生产必须不跳过验签）

## 🧩 HTTPS 安装经验总结（来自副脑02｜给副脑03/运维参考）

方案：**win-acme（WACS） + Let's Encrypt（HTTP-01） + Nginx** 自动证书 + 自动续期。

### 1) 下载 win-acme（WACS）

- 建议下载 **x64 trimmed 精简版**（一般够用）
- 下载镜像（示例）：`https://gitcode.com/gh_mirrors/win-acme/releases`
- 目录建议：`C:\wacs\wacs.exe`

### 2) Nginx 80 端口：必须放行 `/.well-known/acme-challenge/`（不要被 301 吞掉）

示例（80 只负责验证 + 跳转；其它请求再跳转 443）：

```nginx
server {
    listen 80;
    server_name w1.ai24x.com a1.ai24x.com;

    # 关键：ACME 验证路径必须不走重定向
    location /.well-known/acme-challenge/ {
        root C:/ai24x01/web;  # 验证文件存放目录（示例）
    }

    # 其余请求才重定向到 HTTPS
    location / {
        return 301 https://$host$request_uri;
    }
}
```

踩坑：如果 80 端口统一跳转到 443，HTTP-01 验证会失败（常见报错类似 “Invalid response from https://...”）。

### 3) WACS 非交互模式一条命令签发（示例：w1+a1）

> 说明：多个域名用逗号分隔；有几个域名就写几次 `--webroot`（与 `--host` 顺序对应）。

```powershell
cd C:\wacs

wacs.exe --source manual `
  --host w1.ai24x.com,a1.ai24x.com `
  --validation filesystem `
  --webroot C:\ai24x01\web `
  --webroot C:\ai24x01\p\a1\web `
  --store pemfiles `
  --pemfilespath C:\nginx\ssl\temp `
  --accepttos `
  --emailaddress admin@ai24x.com `
  --setuptaskscheduler
```

参数要点：
- `--source manual`：手动域名（非 IIS）
- `--validation filesystem`：HTTP 文件验证
- `--store pemfiles`：导出 PEM（Nginx 可直接用）
- `--setuptaskscheduler`：自动创建 Windows 计划任务续期

### 4) 证书导出文件（示例路径）

```text
C:\nginx\ssl\temp\
  w1.ai24x.com-crt.pem
  w1.ai24x.com-key.pem
  w1.ai24x.com-chain.pem
  w1.ai24x.com-chain-only.pem
```

### 5) Nginx 443 挂证书（示例）

```nginx
server {
    listen 443 ssl;
    server_name a1.ai24x.com;

    ssl_certificate     C:/nginx/ssl/temp/w1.ai24x.com-crt.pem;
    ssl_certificate_key C:/nginx/ssl/temp/w1.ai24x.com-key.pem;

    # ... 其余反代配置
}
```

### 6) 验证（示例）

```powershell
# 重启 Nginx
taskkill /F /IM nginx.exe
nginx.exe
Start-Sleep 3

# 检查监听
netstat -ano | findstr ":443" | findstr "LISTENING"

# 测试
curl -k https://a1.ai24x.com/
curl -k https://w1.ai24x.com/
curl -k https://a1.ai24x.com/health
```

### 7) 自动续期

若签发时使用了 `--setuptaskscheduler`，Windows 计划任务会创建 renew：
- 一般每天 9:00～13:00 随机延迟运行 `wacs.exe --renew`
- 常见策略：到期前较早（例如 60 天）开始自动续签

### 8) 防火墙（443 不通时）

```powershell
netsh advfirewall firewall add rule name="Nginx HTTPS (443)" dir=in action=allow protocol=TCP localport=443
```

### 9) 踩坑记录（务必注意）

- 80 端口必须保留 `/.well-known` 不走重定向，否则验证失败
- 不要用 PowerShell 自签名证书（常见私钥格式导致 Nginx 不认）
- 不必下载插件版（pluggable）；多数场景 trimmed 精简版够用
- WACS 非交互模式更省事；证书目录建议统一：`C:\nginx\ssl\temp\`

### 2) 502 排查原则（必背）

- `127.0.0.1:18011/health` 不是 200：先修 `a1-api-18011`（进程/依赖/配置/DB）。
- 本机 `18011` 都是 200，但域名 `a1.ai24x.com/api/*` 是 502：问题在 **Nginx `/api/` 反代**（端口/路径/尾斜杠）。

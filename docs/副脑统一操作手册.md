## 🔄 强制操作流程

### 1. 首次克隆（只做1次）
```bash
git clone https://gitee.com/ai24x/ai24x-website.git ai24x01
cd ai24x01
```

### 2. 每次开发前（防冲突）
```bash
cd ai24x01
git pull
```

### 3. 开发完成后
```bash
cd ai24x01
git add .
git commit -m "更新ai24x01"
git push
```

```

├── db/        数据库SQL

├── scripts/   脚本

```

## 🚨 铁律
1. **结构必须一致**，不许乱建目录
2. **每次开发前必须git pull**，防止冲突
3. **提交信息要清晰**，说明更新内容
4. **使用私人令牌** 进行 HTTPS 推送时认证（令牌不放仓库）
5. **端口口径唯一来源**：一律以 `docs/PORTS.md` 为准；任何“临时改端口”必须先更新 `docs/PORTS.md` 再执行（避免副脑01/03 端口漂移）
6. **PM2 进程名必须按端口命名**：例如 `a1-web-18001`、`a1-api-18011`、`core-8000`（便于一键重启、避免重启错服务）
7. **数据库变更必须可迁移/可回滚**：只要涉及 PostgreSQL 表结构/索引/字段变更，必须提供迁移脚本并先在副脑01跑通，再上副脑03；上线前必须备份（`pg_dump`）

## 🧱 PostgreSQL（PQ）数据库变更：副脑01/03统一流程（必按此执行）

适用场景：新增表/字段、改字段类型、加索引、改约束等。

### 1) 主脑提交物（必须入库）
- 迁移脚本目录（建议）：`db/migrations/`
  - `YYYYMMDDHHMM__<short>.sql`（up）
  - 可选：`YYYYMMDDHHMM__<short>__down.sql`（down）
- 同步更新：`docs/PORTS.md`（如涉及端口/进程名变化）

### 2) 副脑01（预演）执行顺序
```powershell
Set-Location C:\ai24x01
git pull

# 0) 备份（预演也备份，验证恢复路径）
# pg_dump <conn> -f C:\bak\ai24x01-pre-<timestamp>.sql

# 1) 执行迁移（按文件名顺序）
# psql <conn> -f db\migrations\<migration>.sql

# 2) 重启相关服务
pm2 restart core-8000
pm2 restart a1-api-18011
pm2 save
pm2 list
```

### 3) 副脑03（生产）执行顺序（更严格）
```powershell
Set-Location C:\ai24x01
git pull

# 0) 生产必须先备份
# pg_dump <conn> -f C:\bak\ai24x01-prod-<timestamp>.sql

# 1) 执行迁移（同副脑01跑过的同一份脚本）
# psql <conn> -f db\migrations\<migration>.sql

# 2) 重启相关服务
pm2 restart core-8000
pm2 restart a1-api-18011
pm2 save
pm2 list
```

### 4) 回滚口径（两条路）
- **回滚代码**：`git checkout <上一个prod tag>` + `pm2 restart ...`
- **回滚数据库（兜底）**：用备份恢复（按你们 `pg_restore/psql` 标准操作）

## ⚠️ 常见错误处理

### 错误1：推送被拒绝
```bash
# 先拉取远程更改
git pull origin master --allow-unrelated-histories

# 解决冲突后提交
git add .
git commit -m "解决冲突"
git push
```

### 错误2：认证失败
```bash
# 使用 SSH 或凭据管理器重新登录；勿在 URL 中硬编码令牌并提交
git remote -v
# git remote set-url origin git@gitee.com:ai24x/ai24x-website.git
```

### 错误3：目录结构不一致
```bash
# 检查当前目录结构
tree -L 2

# 按照标准结构创建目录
mkdir -p api web db config scripts docs
```

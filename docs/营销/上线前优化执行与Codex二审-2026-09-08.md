### S5 — 并发扣款预留（reserve → settle / release）

**文件**

- `api/token_mvp_service.py`（已同步到 `p/open/api/token_mvp_service.py`）
  - `reserve_tokens`：上游前 FIFO 原子预扣，`entry_type=hold`
  - `release_hold`：失败/不计费退回（`refund` + `hold_void`）
  - `consume_tokens`：若存在 hold → 多退少补后改为 `consume`
- `api/services.py`、`p/open/api/services.py`
  - `process_chat_request` / `stream_chat_request`：预扣 + finally/失败释放
  - `preflight_stream`：**仍只用** `assert_can_spend`（避免与流式二次预扣）

**账本类型新增（无迁移，复用 `billing_ledger.entry_type` String(16)）**

- `hold` / `hold_void` / `refund`（`source=hold_rel` 的退回 lot）

**风险点（请 Codex 重点看）**

- 预估不足时 settle 会再扣差额；差额不够则夹断（与旧 consume 夹断语义一致）
- 预估过高会短期占用额度；失败路径必须 `release_hold`（已接 except / `_finalize`）
- 退回 lot 有效期写死 365 天（简化实现，非原 lot 到期日）
- BYOK / shared 不计平台 token 时须释放 hold（已接）

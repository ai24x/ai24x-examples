## 七、踩坑清单（都实测踩过）

1. **base_url 必须带 `/v1`**：不带 → 405/404
2. **`wire_api` 必须 `responses`**：用 `chat` → 启动直接报错
3. **key 设置后要新开终端**（setx 不作用于当前窗口）
4. **PowerShell 内联引号吞 `$` 变量** → 一律用 .ps1 脚本文件
5. **curl JSON 传参被 PowerShell 吞引号** → 用 `Set-Content` 写 JSON 文件 + `curl --data-binary "@file"`
6. **脚本里 Authorization 写死 `***` 占位符** → 造成假 401/429，必须插入真实 key
7. **429 不一定是限流**：Codex "exceeded retry limit" 可能是底层 400/401 重试超限，先逐模型 curl 定位
8. **判断限流范围**：全模型 429=网关/key 级；个别模型 400/429=模型级问题
9. **model metadata 缺失警告无害**（context window 用默认值），但补上体验更佳

## 九、体验优化要求（雷总拍板 · 2026-08-10 补充，Codex 实现/案例需体现）

### 1. 模型可选（桌面版左下角可切换）
- [model_aliases] 已配 13 个模型：vip-gpt56-luna / terra / ds-flash / ds-pro / kimi-code / hy3 / glm / mimo / minimax / qwen-max / qwen122b / gpt4o-mini / llama4
- 要求：桌面版左下角模型下拉**可选且切换即时生效**，选中即用，不重启

### 2. 会话不变（切模型不丢会话）
- 会话按 session 文件存储（~/.codex/sessions/），**切换模型不删会话**
- 要求：切换模型后，历史会话列表完整保留，可从历史列表点回任意会话继续

### 3. 避免「切模型=新会话」的费劲
- 目标：**切模型 = 同会话内无缝切换**（模型换、上下文连续、AGENTS.md 记忆不丢）
- Codex 实现层面：确认切模型是否应保留当前会话上下文；若当前版本不支持同会话切模型，需给出最优操作路径（如历史会话继续 vs 新会话）并写入案例
- 案例中写明：用户切换模型后的正确操作方式，避免误解为「会话丢失」

**验收**：以上三项在案例文档中明确说明；修复 tools 后实测验证模型切换 + 会话连续性。

## 04 侧 nginx / 运维清单（请按序执行）

### P0 — 修复 GSC 报错的 URL 形态

1. **`/blog/*` 旧路径**：若仍有历史 `/blog/xxx` 404，统一 **301 → `/blog/index.html`** 或对应新 Hub 页（按 GSC 抽样 URL 定）。
2. **垃圾路径 404**：`/$`、`/百万`、`/1M`、`/v1/auth/` 等返回 **404**（勿 500）。
3. **`try_files`**：静态站支持 `.html` 后缀（`$uri $uri.html $uri/`）。
4. **redirect 壳页 301**：
   - `www.ai24x.com/docs.html` → `open.ai24x.com/docs.html`
   - `www.ai24x.com/api.html` → `open.ai24x.com/docs.html`
   - `www.ai24x.com/models/*` → `open.ai24x.com/models/*`
   - `www.ai24x.com/guides/*`（非 openrouter 两篇）→ `open.ai24x.com/guides/*`
5. **robots.txt / sitemap.xml**：从 `web/` 同步到 www 根，确认 `curl -I` 为 **200**、`Content-Type` 正确。

### P1 — GSC 复验

6. 部署后 `curl -sI https://www.ai24x.com/sitemap.xml` 确认 200。
7. GSC → **Sitemaps** 重新提交 `https://www.ai24x.com/sitemap.xml`。
8. **URL 检查** 对 5 篇 Hub + 首页 + pricing 请求「编制索引」。
9. 从 **页面索引 → 未收录** 导出仍含 404/5xx/canonical 的 URL，对照 nginx 日志补规则。
10. **5xx 日志**：`grep ' 50[0-9] '` access/error log，重点 `/blog/*`、误抓的 `/v1/*`。

### 回滚

- 还原上一版 `web/robots.txt`、`web/sitemap.xml`、nginx site 配置 → `nginx -t && reload`。
- GSC 无需操作，旧 sitemap 会自动过期。

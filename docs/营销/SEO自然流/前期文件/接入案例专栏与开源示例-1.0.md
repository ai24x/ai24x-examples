## 1. 要不要做？

**要做，但是内容资产，不是又一个产品线。**  
国外开发者冲名模时，第二信任信号常是：**有没有我正在用的工具的现成接法**（OpenClaw、Cursor、Continue、Open WebUI、LiteLLM、Dify、n8n…）。

| 价值 | 说明 |
|------|------|
| 吸引力 | 「China models · drop into OpenClaw / OpenAI-compatible stack」比空喊 multi-model 更硬 |
| 应用范围 | 用户把流量带进自己的 Agent/IDE/工作流 → 你们只卖 Token |
| 增长 | 开源仓库 = SEO + GitHub star + 副脑可维护的长尾 |

## 2. 专栏形态（站内）

建议路径：`docs` / 独立 `guides` 页（英文默认）→「Integrations」。

每篇固定模板（短、可复制）：

1. 适用谁（1 句）  
2. 前置：AI24X Key、推荐档位 `flash`/`pro`  
3. 配置片段（env / JSON / 截图位）  
4. 验证：一条 curl 或应用内烟测  
5. 常见错：401 / 余额 / model 名（对外别名，不暴露上游乱跳）  
6. 进阶：VIP 点名某中国模（若该应用支持自定义 model）

**宣传页**：英文 Why us / Pricing 旁链 *Integration guides*，不在 hero 堆案例名。

## 3. 国际知名应用 · 优先列表（可扩）

| 优先级 | 应用/栈 | 为何 | 首期产出 |
|--------|---------|------|----------|
| **P0** | **OpenClaw** | 团队自用、文档已有、可立刻写「接 AI24X」 | 官方口径配置 + 仓库示例 |
| **P0** | **OpenAI SDK / 兼容 endpoint** | 覆盖面最大；大量工具只认这套 | `base_url` + key 一页 + 最小 Python/JS |

| **P1** | Open WebUI / LibreChat | 自托管聊天壳 | 环境变量表 |
| **P1** | LiteLLM / one-api 类网关 | 二次聚合用户 | provider 条目 |
| **P2** | Dify / n8n / Zapier | 工作流获客 | 节点/HTTP 示例 |
| **P2** | LangChain / LlamaIndex | 框架用户 | 短 notebook |
| **暂缓** | 闭源商业套件需商务授权的「官方插件」 | 成本高 | 有量再谈 |

列表在专栏页展示为卡片；**未写完的标 Coming soon**，勿空链。

## 4. 开源库策略（后期副脑共管）

| 项 | 口径 |
|----|------|
| 仓库 | 独立公开仓（如 `ai24x/examples` 或 `ai24x-integrations`），**勿把生产 `.env`/密钥放进仓** |
| 内容 | 按应用分子目录：`openclaw/`、`openai-sdk/`、`open-webui/`…；README 英文为主 |
| 许可 | MIT 或 Apache-2.0（便于二次分发） |
| 维护 | 主脑定目录与质量门禁；**副脑01** 跟国际文档/SEO；**副脑02** 可补中文镜像；代码小改由 01 提 PR，主脑合 |
| 节奏 | 先 1～2 个打穿（OpenClaw + OpenAI SDK），再按 issue/星标扩，**禁止首周堆 20 个空壳** |

站内专栏每篇链到对应开源目录的 raw/README，避免两处文案长期分叉（开源 README 为真源，站内可摘录）。
